## 1. 目标

1. 每类网络源在使用前做一次并行测速，尝试顺序按实测排列，官方源可以赢；
2. 主项目依赖与 Python 分发包经 Runtime 自己的回环中继下载：逐文件多源回退、大文件分片并行、先校验再交付；
3. `python.install` 与 `dependencies.sync` 发真实字节进度，事件里带当前文件名、来源与速度；测速过程以 `network.probe` stage 可见；
4. 受监督期间中继常驻，运行池拿到「回环首项 + 实测顺序」的源列表，不改后端代码即可受益。

## 2. 范围与边界

### 负责

- `internal/mirror`：`Prober`（并行探测）、`RankPlan`（实测排序）、目录增补 `astral`；
- `internal/relay`（新包）：回环 HTTP 服务、逐文件取回引擎（多源回退、分片、失速判定、哈希校验）、`/simple/` 改写、进度回调；
- `internal/uv`：锁规划器（本平台可安装制品集合与总字节）、依赖同步与 Python 安装改走中继、`UV_HTTP_TIMEOUT` 受控键、attempt 报告；
- `internal/cli` / `internal/backend`：测速预热、`network.probe` 事件、`dependencies.sync` / `python.install` 字节事件、`result.details.networkProbe` / `relay`、supervise 期间中继常驻与列表首项注入；
- `internal/protocol`：`ProgressEvent` 三个可选字段、`StageNetworkProbe`、human renderer、契约测试。

### 不负责

- **不**改动 Git 克隆的下载方式与进度形态（仍 go-git 直连 + 时间心跳；只按测速结果排序 cnb/github）；
- **不**接管 uv.exe 的下载器（仍是 `internal/mirror.Downloader`，只吃实测顺序）；
- **不**做跨操作的中继缓存（uv 自己的缓存负责复用）；
- **不**新增 CLI 参数、错误码、state；不升级协议版本；
- **不**改 AUTO-MAS Python 后端；Electron 侧只消费新字段（TODO-EL-14）；
- **不**解析 uv / Git 的自然语言输出（`uv python list --output-format json` 是机器 JSON，例外）。

## 3. 接口形态（并行实施的契约）

### 3.1 `internal/mirror`：测速

```go
// ProbeTarget 描述一个 Kind 的探针：路径拼在每个源的 base（package-index 用 packages 前缀）之后。
type ProbeTarget struct {
    Kind        Kind
    Path        string        // 例："0.12.3/uv-x86_64-pc-windows-msvc.zip"；git 为 "info/refs?service=git-upload-pack"
    WindowBytes int64         // Range 窗口，默认 256 KiB；git 为 0（只看 TTFB）
}

// ProbeResult 是单个源的探测结果；Err 非空时 OK 为 false，其余数值为零。
type ProbeResult struct {
    Source         Source
    OK             bool
    TTFB           time.Duration
    BytesPerSecond int64
    Bytes          int64
    AcceptRanges   bool          // 返回 206 或 Accept-Ranges: bytes
    Err            error
}

type ProbeOption func(*probeOptions) error
func WithProbeBudget(d time.Duration) ProbeOption          // 默认 3s
func WithProbeClient(client httpClient) ProbeOption         // 注入，测试用 httptest
func WithProbeClock(clock func() time.Time) ProbeOption

type Prober struct{ /* 不可变依赖 */ }
func NewProber(options ...ProbeOption) (*Prober, error)

// Probe 并行探测 plan 内全部源，预算到期即收口；永不返回网络错误（结果写进 ProbeResult.Err）。
// 只有 ctx 取消或参数非法才返回 error。report 可为 nil，每个源完成时同步回调一次。
func (p *Prober) Probe(ctx context.Context, plan Plan, target ProbeTarget, report func(ProbeResult)) ([]ProbeResult, error)

// RankPlan 按 C16 第 3 条重排：pinned（显式首选 key，可空）钉最前；其余按 BytesPerSecond 降序、TTFB 升序；
// OK=false 的源排最后但保留原相对顺序；results 缺失的源视为 OK=false。返回的 Plan 与输入同 Kind、同源集合。
func RankPlan(plan Plan, results []ProbeResult, pinned string) (Plan, error)

// ProbeCache 是进程内按 Kind 缓存的实测顺序，供长驻进程复用；30 分钟过期。并发安全。
type ProbeCache struct{ /* mutex 保护 map[Kind]cachedRanking */ }
func NewProbeCache(clock func() time.Time, ttl time.Duration) *ProbeCache
func (c *ProbeCache) Lookup(kind Kind, seal string) (Plan, []ProbeResult, bool)  // seal = 输入 plan 的 Seal()
func (c *ProbeCache) Store(kind Kind, seal string, plan Plan, results []ProbeResult)
```

补充：`Plan` 增加 `Seal() string`（十六进制 `planSeal`），供缓存键；`RankPlan` 通过包内 `newPlan(kind, sources)` 构造带正确 seal 的 Plan。
探针请求：`GET`，`Range: bytes=0-<WindowBytes-1>`，`Accept-Encoding: identity`，沿用 `downloader_client.go` 的重定向策略（≤ 10 跳、禁止降级 HTTP）。
TTFB 从请求发出到收到响应头；吞吐 = 首字节后读到的字节 / 首字节后经过的时间；预算到期时正在读的源按已读字节计算吞吐并记 OK。
目录增补：`KindPython` 在 `gh-proxy` 之前加入 `{key: "astral", baseURL: "https://releases.astral.sh/github/python-build-standalone/releases/download"}`。

### 3.2 `internal/relay`：回环中继

```go
// Item 描述锁内已知的制品；Path 是 PyPI 原路径（"ab/cd/<hash>/x.whl"），SHA256 为十六进制。
type Item struct {
    Path   string
    Size   int64
    SHA256 string
}

// Route 是中继的三个前缀之一。
type Route string
const (
    RoutePackages Route = "packages"
    RouteSimple   Route = "simple"
    RoutePython   Route = "python"
)

// Upstream 描述某条路由按实测顺序排列的上游前缀（每项以 / 结尾的绝对 HTTPS URL）与源 key。
type Upstream struct {
    Key         string
    Base        string   // packages 路由：packages 前缀；simple 路由：simple 前缀；python 路由：源 base + "/"
    AcceptRange bool     // 探针得知；未知为 false，HEAD 见到 Accept-Ranges 时中继自行更新
}

type Config struct {
    StagingDir       string                 // layout.RelayStagingDir()，中继独占，Close 时清空
    Upstreams        map[Route][]Upstream   // 至少 packages 与 python 两条
    Items            []Item                 // 可为空；Register 可追加
    ChunkThreshold   int64                  // 默认 8 MiB
    ChunkSize        int64                  // 默认 2 MiB
    MaxFiles         int                    // 同时下载的文件数上限，默认 6
    MaxChunksPerFile int                    // 默认 4
    StallTimeout     time.Duration          // 读空闲失速，默认 15s
    ConnectTimeout   time.Duration          // 默认 15s
}

// Progress 是中继的聚合进度：Item/Source 为当前（最近有字节到达的）文件与源；Total 为已登记 Item 的字节总和，
// 未登记文件在 HEAD 得知大小后并入；Received 为已校验交付的字节 + 进行中文件的已收字节。
type Progress struct {
    Route          Route
    Item           string
    Source         string
    Received       int64
    Total          int64
    BytesPerSecond int64
}

type Deps struct {
    Client   httpClient               // 上游客户端，测试注入
    Clock    func() time.Time
    Progress func(Progress) error      // 同步回调；返回错误时中继停止并让后续请求 502
    Logger   func(level, message string, fields map[string]any)
}

type Server struct{ /* ... */ }
func Start(ctx context.Context, cfg Config, deps Deps) (*Server, error)   // 绑定 127.0.0.1:0；ctx 取消即关闭
func (s *Server) BaseURL() string                                         // "http://127.0.0.1:<port>"
func (s *Server) Register(items []Item)                                    // 追加已知制品（幂等）
func (s *Server) Summary() Summary                                         // 供 result.details.relay
func (s *Server) Close() error                                             // 停服务、等 goroutine 退出、清暂存

type Summary struct {
    Files    int
    Bytes    int64
    BySource map[string]int64
    Failures []FileFailure                                                 // 上限 32
}
type FileFailure struct {
    Item     string
    Attempts []AttemptOutcome                                             // {Source, Outcome}：outcome ∈ connect_timeout/read_timeout/http_status/checksum_mismatch/network/cancelled
}
```

请求处理规则（C17 第 4 条的实现口径）：

1. 路径规范化后必须以三个前缀之一开头且不含 `..`、不含空段；否则 `404`。`/simple/` 只接受 `GET`，另两条接受 `GET` / `HEAD`。
2. `/packages/<path>`：查 `Items`；已知则按「多源取回 → 校验 sha256 → 交付」；未知则先 `HEAD` 首个可用上游取 `Content-Length` 与 `Accept-Ranges`，再多源取回，不校验哈希。`.metadata` 旁车文件与其它未登记文件走未知分支。
3. `/python/<path>`：同未知分支；路径中的百分号编码原样转发。
4. `/simple/<name>/`：按上游顺序取第一个 `200` 的响应，`Accept` 头透传（JSON / HTML 两种索引都可能），响应体内每个上游自己的 `packages` 前缀改写为 `<BaseURL>/packages/`；`Content-Type` 透传，`Content-Length` 重算。
5. 交付：文件完整落在暂存目录后用 `http.ServeContent` 响应（自动支持 `Range` / `206` / `HEAD`）；同一文件并发请求共享一次取回（singleflight 语义，自行实现，不引入依赖）。
6. 取回引擎：
   - 源顺序 = `Upstreams[route]`；对每个文件维护本文件已失败的源集合；
   - 单流：从首个未失败源 `GET`，连接超时 / 读空闲失速 / 非 2xx / 哈希不符 → 记 `AttemptOutcome`，换下一个源从头取；
   - 分片：`Size >= ChunkThreshold` 且支持 `Range` 的源 ≥ 2 时，按 `ChunkSize` 切片入队，最多 `MaxChunksPerFile` 个 worker 各绑定一个源逐片取；片失败回队并把该源标失败（该文件内），worker 退出；所有支持 `Range` 的源都失败后剩余片退化为单流由剩余源接管；
   - 慢源判定（T14.8）：`chunkPlan` 记录每个 worker 当前片的开始时刻、开始时的全局完成片数与已收字节；
     每完成一片就检查别的 worker（`demoteLaggards`），队列空了准备退出前再看一次（`demoteTailLaggard`）；
     判慢即取消该 worker 的片 context，它把剩余范围回队、已收字节计入贡献后退出，`engine.demoteUpstream` 把该源挪到路由末位；
     最小在飞时长 1.5 秒由注入时钟计量；
   - 哈希不符：该源对该文件失败；同一源在本中继生命周期内两次哈希不符 → 从该路由的上游列表中移除；
   - 全部源失败 → `502` + 中继内记 `FileFailure`；
   - 同时下载文件数 ≤ `MaxFiles`，超出者在 handler 内等待（ctx 取消可退出）。
7. 进度：每 200 ms 至多一次回调（有变化才回调），文件完成与失败时强制回调一次；`BytesPerSecond` 为最近 1 秒窗口。
8. 上游 URL 只能由 `Upstream.Base + path` 拼出；不接受请求方提供的主机；重定向沿用 `mirror` 下载器策略。
9. `Close`：停止接受连接、取消进行中取回、等待全部 goroutine 退出（有界，30 s）、删除暂存目录内容。

### 3.3 `internal/uv`：锁规划与接线

```go
// LockArtifact 是锁内为本平台选定的一个制品（PyPI 原路径 + size + 十六进制 sha256）；接线处转换为 relay.Item，
// 规划器本身不依赖 relay 包。
type LockArtifact struct {
    Package string
    Path    string
    Size    int64
    SHA256  string
}

// LockPlan 是从锁文件规划出的本平台可安装制品集合。
type LockPlan struct {
    Items      []LockArtifact
    TotalBytes int64
    Largest    LockArtifact   // 供 package-index 探针
    Skipped    int            // marker 求值失败按可达处理的次数（只会高估）
}

// PlanLock 解析锁文本，从根项目 dependencies 出发按 marker 求值可达包，每包取本平台 wheel（win_amd64 × cp312/abi3/py3，否则 none-any，否则 sdist）。
// env 固定：sys_platform=win32, platform_system=Windows, os_name=nt, platform_machine=AMD64, implementation_name=cpython,
// platform_python_implementation=CPython, python_version / python_full_version 取 pythonVersion。解析失败返回 error（调用方降级为无总量）。
func PlanLock(lock string, pythonVersion PythonVersion) (LockPlan, error)
```

实测（`dev@cca4ac486` 锁、Python 3.12.13）：规划出 95 个制品、143,023,892 字节，最大制品 opencv-python 38,842,521 字节，Skipped 0。
TOML 解析引入 `github.com/BurntSushi/toml` v1.5.0（理由：`uv.lock` 是多层 array-of-tables + inline table，手写解析器不可靠；该库无传递依赖、稳定十年；只用于读）。
marker 求值只支持 `==`、`!=`、`in`、`not in`、`and`、`or`、括号，以及 `python_version` / `python_full_version` 的 `<`、`<=`、`>`、`>=`（PEP 440 简单比较）；其它形态记入 `Skipped` 并按可达处理。

接线：

- `DependenciesService.Sync`：在线且非 `--offline` 时，`relaySession := s.relay.Start(...)`（工厂注入，测试替身），锁副本改写到 `relaySession.BaseURL()`，`Register(plan.Items)`，一次 `uv sync --frozen`，`RunOptions.Environment[uvHTTPTimeoutEnv]="900"`；中继启动失败 → 走既有 `syncWithMirrors`（不改）；uv 失败且中继 `Summary().Failures` 非空 → `MIRROR_EXHAUSTED`（`details.relay`），否则沿用既有依赖错误映射；`--mirror-only` 无直连回退；`DependenciesRequest` 增加 `Progress func(relay.Progress) error`，`DependenciesResult` 增加 `Relay *relay.Summary`、`Source` 记贡献最多字节的源。
- `PythonService.Prepare`：同样经中继，`UV_PYTHON_INSTALL_MIRROR=<BaseURL>/python`；启动失败退回 `networkExecutor.run`；`PythonRequest` 增加 `Progress`。
- `runner.go`：`uvHTTPTimeoutEnv = "UV_HTTP_TIMEOUT"` 加入 `canonicalUVOverrideKey` 允许集合（只允许 network.go / 中继路径注入，宿主的同名变量仍被剔除）。
- `network.go`：`networkExecutor` 增加 `probe`（`*mirror.Prober` + `*mirror.ProbeCache`），`plan()` 在线时先查缓存、未命中则探测并排序；`python` Kind 的探针路径由 `uv python list <version> --output-format json --only-downloads` 的 `url` 去掉官方 base 得到（新增 `pythonDownloadPath(ctx, runner, spec)`，失败则不测速）。
- `managed.go` / `backend/supervisor.go`：`SupervisionInfrastructure` 增加 `RelayBaseURL string`；非空时两份列表首项分别为 `<BaseURL>/simple/` 与 `<BaseURL>/python`。

### 3.5 `internal/cli` / `internal/backend`

- 会话建立时创建一个 `mirror.Ranker`（`internal/cli/probe.go`），登记 uv 与 git 的静态探针目标；生产工厂经 `rankerHolder` 拿到它的 `PlanFunc`，
  测试注入的工厂不受影响。**探测是惰性的**：各消费方第一次取该 Kind 的顺序时才探（uv 下载前、克隆前、Python 安装前、依赖同步前），
  每个源完成发 `network.probe running`（`item`=`source`=key，`bytesPerSecond`，`current/total`），一轮排好序发 `succeeded`（message 给出顺序）。
  不做统一预热（实施期修订）：不需要联网的阶段不会为测速而联网，单元测试里假服务也不会触发真实探测。
- python 的探针路径由 `PythonService` 在安装前用 `uv python list --output-format json` 取得并登记；package-index 的探针路径由
  `DependenciesService` 从锁规划的最大制品登记。
- `backend supervise`：任何 spawn 之前按目录顺序起中继并注入 `RelayBaseURL`（两份列表以回环首项开头），后端立即启动；
  有测速器时后台探测 package-index（探针目标取受管仓库锁内最大制品）并经 `relay.Server.SetUpstreams` 替换 packages / simple 上游顺序，
  监督结束前等待该 goroutine 退出再关中继；中继起不来退回今天的直连列表。
- `result.details`：`networkProbe` 与 `relay` 按增补 2 C18 第 7 条。
- 进度接线：`relay.Progress` → `dependencies.sync` / `python.install` 的 `running` 事件（`current/total/percent/item/source/bytesPerSecond`），沿用 `uvDownloadProgress` 的 200 ms 节流与单调约束；`total==0` 时不带数值。

## 4. 失败语义汇总

| 情形 | 结局 |
| --- | --- |
| 探针全部失败 / 超预算 | 退回目录顺序；操作日志 warning；`network.probe` 仍 `succeeded` |
| 中继绑定端口失败 | 记日志，本次操作按 T13.4 / 既有 python 轮换执行；`result.details.relay` 缺失 |
| 某文件所有源失败 | 中继 `502`；uv 失败；Runtime 报 `MIRROR_EXHAUSTED`，`details.relay.failures` 列出文件与逐源结局 |
| 哈希不符 | 换源；同源两次 → 本操作内剔除该源 |
| 用户取消 | 中继随 ctx 关闭，进行中请求以连接关闭结束；uv 收到 ctx 取消被终止；既有取消映射不变 |
| 进度回调失败 | 与 T13.12 一致：`OUTPUT_WRITE_FAILED` 立即结束 |

## 5. 安全边界

- 中继只监听 `127.0.0.1`；`Listener` 由 `net.Listen("tcp4", "127.0.0.1:0")` 创建，不监听 `0.0.0.0` 或 IPv6 任意地址；
- 路径必须以三个前缀之一开头、规范化后无 `..`；上游只能由目录内源 base 拼出；
- 暂存目录在受管根内 `runtime/cache/downloads/relay/`，`config.Layout` 新增 `RelayStagingDir()`；删除走既有受控删除（`filesystem`），`cleanup` 分类同 `downloads`；
- 不设置 `--allow-insecure-host` / `UV_INSECURE_HOST`；到上游的每一跳 HTTPS + 校验；重定向禁止降级 HTTP。
