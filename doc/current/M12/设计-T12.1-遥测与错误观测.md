# M12 遥测与错误观测设计

## 文档状态

- 状态：D11 调整中，T12.2、T12.4~T12.6 本地实现与验收收口中；T12.3 已取消
- 关联决策：D8/D9/D10（历史 provider 方案）、D11（当前 Sentry-only）
- 权威约束：`doc/架构设计.md`「遥测与错误观测策略」、`doc/任务拆分.md` T12.1~T12.6

本文定义遥测与错误观测的边界、配置和验证契约，并作为当前实现的审查依据；实现不得改变
协议 v1、CLI 命令树、错误码、stage、state、退出码或目录布局。

## 1. 目标与不负责

### 1.1 目标

- 用 Sentry 发现 Runtime 内部错误和未预期 panic，并保留可定位实现位置的最小栈信息；
- Sentry 只替换 DSN 即可切换项目；当前不发送命令完成运行质量事件；
- 在凭据缺失、显式关闭、离线、网络失败、队列满或 flush 超时时保持 Runtime 原有行为。

### 1.2 不负责

- 不代理业务 HTTP/WebSocket，不采集 Python 后端业务事件；
- 不收集或上传用户业务数据、仓库内容、命令参数、日志、错误原文、绝对路径、主机名、
  用户名、安装 ID、operation ID 或可直接定位用户的信息；
- 不做 tracing、profiling、session replay、日志转发、用户画像、GeoIP 丰富或跨命令缓存；
- 不让 Electron、Python 或业务包直接创建 SDK client；
- 不因遥测失败改变协议事件、stdout/stderr、状态、退出码、retryable 或 remediation。

## 2. 决策与范围

| 项目 | 定稿 |
| --- | --- |
| 首发数据源 | Sentry（DSN 决定项目） |
| 后续迁移 | 只替换 Sentry DSN；事件 schema 和业务接线不变 |
| provider 结构 | `internal/telemetry` 统一生命周期；仅保留 Sentry adapter |
| 默认开关 | 未显式关闭且对应凭据存在时启用；凭据缺失时该 provider no-op |
| 强制关闭 | 全局 `--offline` 或环境变量 `AUTO_MAS_TELEMETRY=disabled`；在 SDK 初始化前短路 |
| Sentry 范围 | 只捕获 `INTERNAL_ERROR` 与未预期 panic |
| 发送失败 | 静默丢弃，不阻塞业务，不跨命令重试，不落盘缓存 |
| 终态收口 | 业务终态确定后 best-effort flush，硬上限 500 ms |

## 3. 配置与凭据

### 3.1 配置来源与优先级

配置只在 `internal/telemetry` 的构造边界解析一次，不把 `context.Context` 存入结构体，
也不让 provider 自行读取环境变量。优先级由高到低：

1. `--offline` 或 `AUTO_MAS_TELEMETRY=disabled`：Sentry provider 关闭；
2. 环境变量覆盖构建期默认值；
3. 发布构建注入的默认值；
4. 值为空或缺失：对应 provider 为 no-op。

`AUTO_MAS_TELEMETRY` 只有值 `disabled`（大小写不敏感）表示关闭；未设置或其他值不绕过
凭据门禁，不会凭空启用 provider。未知/非法 DSN 按缺失处理并静默 no-op，
不映射为 Runtime 业务错误。

### 3.2 配置项

| 配置 | 首发默认 | 环境覆盖 | 说明 |
| --- | --- | --- | --- |
| Sentry DSN | 发布构建注入 | `AUTO_MAS_SENTRY_DSN` | 仅使用 DSN，不使用 auth token |
| Sentry environment | `production` | `AUTO_MAS_SENTRY_ENVIRONMENT` | 仅接受 `production`、`staging`、`development`、`testing` |
| Sentry release | 当前 Runtime 版本 | `AUTO_MAS_SENTRY_RELEASE` | 仅接受 `dev` 或带 `v` 前缀的受限版本形态；非法值回退固定安全值 |
| 遥测开关 | 默认启用（凭据存在时） | `AUTO_MAS_TELEMETRY=disabled` | Electron 关闭设置映射到该值 |

发布构建的默认值通过受控构建注入，不写入 Git 源码、日志、协议事件、README 或错误详情。
凭据缺失的本地构建仍必须能够编译、运行和通过全部测试。CI 的发布 smoke 必须显式禁用
遥测，避免把测试事件发送到生产项目。

### 3.3 零网络前置门

构造 provider 前先完成以下纯内存判断：

```text
offline || telemetryDisabled -> disabled providers
missing/invalid provider credential -> no-op provider
otherwise -> construct exactly one provider client
```

短路发生在 DNS、HTTP transport、SDK worker、timer、queue 或 flush 创建之前。关闭状态
贯通短命命令和长驻 `backend supervise`，不能只在首次 bootstrap 检查。

## 4. 统一观测模型

业务包只向 telemetry 层提交结构化、已分类的观察值，不传 `error.Error()`、details map、
日志文本或原始命令参数。推荐的消费方接口保持小而具体：

```text
CaptureInternal(ctx, InternalObservation)       // Sentry 白名单事件
Close(ctx)                                      // provider 自有队列在 deadline 内 best-effort flush/close
```

接口位于消费方边界且不向业务返回 provider 错误。adapter 接受可注入 transport，CLI 接线接受
可注入 clock/factory，单元测试不得触碰真实公网。

### 4.1 InternalObservation 与 Sentry payload

允许的触发原因只有：

- 协议层已分类的 `INTERNAL_ERROR`；
- Runtime 边界捕获的未预期 panic。

adapter 初始化固定：

```text
SendDefaultPII = false
EnableTracing   = false
DisableLogs     = true
```

`BeforeSend` 必须从白名单重建事件，保留固定错误类别、severity、release/environment 和
`command`、`stage`、`code`、Runtime/协议版本、`GOOS/GOARCH` 标签；清空 `user`、`request`、
`server_name`、breadcrumbs、extra、非白名单 contexts、原始 error/panic 文本、局部变量和
源码上下文。栈只保留函数、模块和行号，绝对路径与文件路径置空。`INTERNAL_ERROR` 使用
固定消息，panic 使用固定消息并丢弃 panic value；不符合触发条件时返回 `nil`。

Runtime panic 边界使用固定 32 槽缓冲采样栈，provider 防御性拒绝超过 64 帧的观察；每帧只
允许 `function`、`module` 与非负 `line`，函数/模块各最多 256 字节。发送前再次重建帧，路径形态、
控制字符、反斜杠/盘符，以及 `filename`、`abs_path`、vars、源码上下文全部清空；净化后为空的帧
丢弃。

Sentry SDK 仍会生成传输所需 envelope/header 以及 `event_id`、`timestamp`、`platform` 等技术
字段，这些不是应用字段白名单的扩展。应用可控内容仍只限固定 message/exception、level、
release/environment、允许标签和上述净化栈帧；DSN 认证信息不得复制到标签、extra、日志或协议。

## 5. 生命周期与接线

```text
CLI 参数解析
    -> telemetry config gate (offline/disabled/credential)
    -> create no-op or provider clients
    -> runOperationSession / backend supervise
    -> classify stable result
    -> emit final result (stdout remains last protocol event)
    -> observe allowed event
    -> provider-owned queue flush/close, caller waits <= 500 ms, discard failures
```

- 统一接线点是 `internal/cli` 的会话收口；业务服务只返回既有 typed result/error；
- Sentry 观察发生在 `INTERNAL_ERROR` 或未预期 panic 分类后；预期业务失败不发送；
- `result` 已写出后才允许 best-effort flush，flush 超时不能回写或追加协议事件；
- 发送、flush、close 的任何错误都不写 stdout/stderr，不改变退出码和持久状态；
- 由谁启动 goroutine 谁负责在 500 ms 等待预算、context 取消或 Close 后收口，禁止泄漏。

## 6. Sentry 配置

首发配置使用可选的 Sentry DSN。验收使用本地 HTTPS 测试服务，替换 DSN 后验证：

1. DSN 指向兼容的 Sentry ingestion endpoint；
2. provider 只接收本节定义的白名单事件，DSN 和传输技术字段不进入应用属性；
3. TLS 校验仍开启，不提供跳过校验的开关；
4. 业务包、CLI 协议、错误码、日志和事件 schema 不变；
5. DSN 不出现在日志或测试输出中。

切换不需要 Sentry auth token，也不修改用户数据目录。真实自建 Sentry 验收和任何远程配置
变更必须在明确授权的环境执行。Umami 不属于当前实现，相关 endpoint/website ID 配置不再读取。

## 7. 测试矩阵

| 层级 | 必测场景 | 证据 |
| --- | --- | --- |
| 单元 | config 优先级、缺 DSN、非法值、offline/disabled 前置门、环境/release 安全元数据 | 表驱动测试；无网络调用计数 |
| adapter | Sentry BeforeSend 净化、环境/release、panic 帧限制、拒绝非目标错误 | fake transport 收到的完整 payload |
| 生命周期 | success/failure/cancelled、`INTERNAL_ERROR`、panic、result 最后一事件、500 ms deadline、Close 幂等 | NDJSON 解析 + barrier/channel；无 stdout 污染 |
| 组件 | 所有顶层命令、managed/development supervise、凭据缺失、显式关闭、offline、provider 网络失败 | fake provider + 临时 app root |
| CI/smoke | 发布 smoke 禁止生产遥测；构建无 DSN 仍可运行；本地 HTTPS Sentry DSN 替换 | PowerShell 7 命令输出和退出码 |
| 并发 | 队列满、并发 Capture、取消与 Close 竞争、race detector | `go test -race ./... -count=1` |

标准门仍为 `gofmt`、`go vet ./...`、`go build -buildvcs=false ./...`、`go test ./... -count=1`
和 `git diff --check`；网络相关测试必须使用假 transport，禁止把真实自建服务结果作为单元
或 CI 通过证据。
