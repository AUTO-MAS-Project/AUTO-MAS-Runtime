# T12.11 锁、依赖与恢复失败诊断

## 范围

v0.1.29 的 Sentry 样本中，Mutex 故障没有操作或系统错误码；依赖同步有退出码 0 却标为非零退出；
更新恢复只有 `swap_shape/update_unknown`，无法重建目录形态。本任务补充诊断事实，不据此推断现场根因。

不修改错误码、退出码、retryable、remediation、协议 details、分组、重试、取消、清理或恢复判定；
不上传原始错误、输出、锁名称、目录路径，也不访问真实 Sentry。保持关闭/离线零网络。

## 所有权与数据流

锁包的结构化操作错误通过 `DiagnosticDetails()` 提供 `mutex`：`operation` 为现有操作 token，
`component` 为已知锁用途，`windowsError` 只从结构化 errno 提取。错误链和本地日志保持不变。

依赖包装错误通过诊断接口提供既有计数、耗时及底层 uv Error 的执行分类和安全 details。
底层有明确分类时优先保留；否则仅在退出码非零时使用现有 `*_nonzero`，其余归 `*_failed`。
公共协议 details 保持原值，Sentry 诊断覆盖其中失真的分类；不解析 stderr 或错误文本。
中继不可用而回退镜像轮换时，最终错误同样附加最后一次执行的诊断，包含官方源与仅镜像两种策略。
只读取 `lastResult/lastErr`，不从包含整轮历史的错误链提取执行事实，避免把最早一次失败混作最后一次。
保留两种策略既有错误码、重试与取消/报告失败优先级。

恢复服务在现有分类调用旁保存局部快照，失败返回时经可解包包装携带 `directories`。
固定三个角色为 `repo/update/previous`，初始状态 `not_observed`；已完成分类记录
`missing/incomplete/valid`，分类失败为 `unknown`。仅有效身份记录已知版本和提交。
同时提供事务目标版本和已知目标提交。快照表示检查时事实，不承诺是清理后的磁盘状态。
遇到分类失败立即停止，后续角色保持 `not_observed`；不额外访问磁盘。

CLI 在既有终态观察位置遍历错误链，合并专用诊断副本；较外层提供的事实优先，普通协议 details
作为回退。自身带协议分类的诊断只在 code/stage 与最终选中错误一致时合并，避免清理错误优先时
被次要执行错误的退出码覆盖。后端既有身份、终止请求与 primary/cleanup 规则保持。新增 `mutex/directories`
容器走已有深度、字段数、大小与凭据净化约束；CLI 和 BeforeSend 各净化一次。

## 验证

复用 Windows 锁 API 夹具产生真实结构化故障；复用依赖中继夹具注入成功退出但输出读取失败，
证明退出码、同步错误四元组与清理行为不变。扩展恢复歧义与读取失败用例，证明目录状态有用且
仍无副作用、未观察目录不补查。通过 CLI recorder 与 Sentry fake transport 验证最终保留字段、
未知/凭据字段丢弃和协议隔离。先红后绿，再运行 gofmt、vet、build、完整测试与 diff check。
