更新恢复只有 `swap_shape/update_unknown`，无法重建目录形态。本任务补充诊断事实，不据此推断现场根因。

不修改错误码、退出码、retryable、remediation、协议 details、分组、重试、取消、清理或恢复判定；

## 所有权与数据流

锁包的结构化操作错误通过 `DiagnosticDetails()` 提供 `mutex`：`operation` 为现有操作 token，
`component` 为已知锁用途，`windowsError` 只从结构化 errno 提取。错误链和本地日志保持不变。

依赖包装错误通过诊断接口提供既有计数、耗时及底层 uv Error 的执行分类和安全 details。
底层有明确分类时优先保留；否则仅在退出码非零时使用现有 `*_nonzero`，其余归 `*_failed`。
公共协议 details 保持原值，Sentry 诊断覆盖其中失真的分类；不解析 stderr 或错误文本。
中继不可用而回退镜像轮换时，最终错误同样附加最后一次执行的诊断，包含官方源与仅镜像两种策略。
只读取 `lastResult/lastErr`，不从包含整轮历史的错误链提取执行事实，避免把最早一次失败混作最后一次。
保留两种策略既有错误码、重试与取消/报告失败优先级。

恢复服务在现有分类调用旁保存局部快照，失败返回时经可解包包装携带 `directories`。
固定三个角色为 `repo/update/previous`，初始状态 `not_observed`；已完成分类记录
`missing/incomplete/valid`，分类失败为 `unknown`。仅有效身份记录已知版本和提交。
同时提供事务目标版本和已知目标提交。快照表示检查时事实，不承诺是清理后的磁盘状态。
遇到分类失败立即停止，后续角色保持 `not_observed`；不额外访问磁盘。

CLI 在既有终态观察位置遍历错误链，合并专用诊断副本；较外层提供的事实优先，普通协议 details
作为回退。自身带协议分类的诊断只在 code/stage 与最终选中错误一致时合并，避免清理错误优先时
被次要执行错误的退出码覆盖。后端既有身份、终止请求与 primary/cleanup 规则保持。新增 `mutex/directories`
容器走已有深度、字段数、大小与凭据净化约束；CLI 和 BeforeSend 各净化一次。

## 2026-11-12 状态失败诊断增补

用户提供的 exFAT 日志记录了 `mutation` 写入的 `finalize` 失败，但只保留外层摘要。
五次失败只有首次留下 Runtime error 记录，后续命令可能在恢复检查、日志器建立之前返回。
本次沿用 T12.11 补齐诊断，不据此判断 exFAT 故障根因，不改变状态写入与恢复流程。

`state.WriteError` 经 `DiagnosticDetails()` 提供 `persistence`，包含已知逻辑文件角色、
写入阶段、`mutationApplied` 和 `recoveryRequired`。主因与独立清理错误分别放在
`primary` 和 `cleanup` 中，只提取文件操作 token、结构化系统错误号与已知错误类别。
存在错误但没有可提取分类时记录 `failureKind=unknown`，不把未知清理错误当作没有错误。
`state.ReadError` 同样提供逻辑文件角色和读取错误事实。未知文件名不回显，原错误链保持不变。
CLI 合并诊断时校验仅带 Code 的嵌套错误也与最终错误码一致，避免次要状态错误污染主错误。
新增容器和布尔字段经过既有双重净化；路径、原始错误和文件内容不进入 Sentry。

本地 State 失败记录额外保存有界错误链与结构化诊断，保留主因和清理错误。
最多遍历 32 个错误，每项文本最多 4096 字节，截断记录单独标识。
即使命令尚未打开日志器，会话也为已经分类的 `STATE_WRITE_FAILED` 尝试建立受管终态日志。
工厂沿用路径安全校验和现有清理预算；打开或写入失败时将有界错误链写 stderr。
其他早期失败仍不创建日志目录。已有日志、取消与错误优先级保持原语义。

新增回归覆盖提交后 finalize、恢复读取失败、独立清理错误、完整错误链、早期 bootstrap
失败的真实文件日志、日志不可写降级、协议 details 隔离与 Sentry fake transport。

## 目录与 Python 执行诊断增补

在 PR #35 继续补齐目录占用、仓库清理、uv Job 隔离和 Python 安装失败。所有事实来自已经
执行的操作与结果，不增加扫描、重试、删除、终止或恢复动作，不改变协议 details。

Git 错误经 `repository` 提供重命名阶段、固定源/目标角色、清理角色、`committed`、
`mutationApplied`、`removed`、`partial`、`auditCompleted` 及底层操作/系统错误号。
目录角色从既有 RenameKind/DeleteKind 推导，不从路径猜测；轮换只提升最后一次同分类失败的
诊断。CLI 本地失败记录同样保存结构事实，workspace 已打开的日志绑定到终态出口。

uv 的 Job 工厂通过消费方私有接口注入，生产缺省仍调用 `process.NewJob`。创建与 Assign
保留现有 `process_isolation_failed`，另用 operation 区分，附带 errno 与已有执行上下文。
Python 中继和逐源失败保存最后一次执行的分类、耗时、捕获字节数及源尝试信息，未知失败与
真实非零退出分开。共享执行诊断从依赖专用命名迁移到 uv 包内通用实现，原调用方同步迁移。
源尝试只保留最后四条安全摘要，总尝试数不变，超出时标记 truncated，给最后一次执行事实留出字段预算。
取消、网络策略错误和进程清理保持原样，Sentry 仍只接收白名单结构字段。

新增回归 `TestSwapper_OperationDiagnostics`、`TestFetcher_CleanupDiagnostics`、
`TestRunner_IsolationFailureDiagnostics`、`TestPython_InstallFailureDiagnostics`、
`TestSentry_RepositoryFailureDiagnostics` 及 CLI 本地诊断回归，先确认缺项再实现。
