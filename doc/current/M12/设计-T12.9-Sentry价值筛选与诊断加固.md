# T12.9 Sentry 价值筛选与诊断加固设计

## 状态与目标

- 日期：2026-09-14
- 状态：进行中
- 输入：T12.8 本地未推送提交 review

本任务修复 T12.8 的四个边界缺口：任意错误文本可能泄露凭据、所有稳定失败会自动放大噪声、
真实 typed container 被静默丢弃，以及 uv/依赖失败缺少可定位的安全结构信息。不改变协议 v1、
错误码四元组、退出码、stdout 顺序、离线/禁用零网络和 500 ms 收口。

## 价值筛选

`internal/telemetry` 持有唯一的失败上报策略表。策略按错误码正向登记，并由 CLI、Observer 与
Sentry `BeforeSend` 共用：

- 输入错误、无效版本、正常 mutation/backend 并发冲突和用户取消不上传；
- Git 仓库/替换、受管目录安全、持久状态、uv/Python/依赖环境、镜像耗尽、后端生命周期、
  协议兼容、输出故障与 Runtime 内部错误保留；
- 新错误码未登记时运行期默认拒绝，完整性测试要求维护者明确选择上报或忽略。

## 诊断 schema 与隐私边界

CLI 绝不向观测层传 `operationErr.Error()`、cause、stdout、stderr、完整命令行或日志文本。
普通失败只携带稳定 code/stage/reason 和以下类别的正向结构化字段，不提供自由文本诊断通道：

- 阶段事实：`operation`、`component`、`failureKind`、`outcome`、`field`；
- 版本身份：`pythonVersion`、`version`、`expectedVersion`、`actualVersion`、`branch`、`commit`、
  严格 64 位十六进制 `expectedSHA256`；
- 有界数值：`exitCode`、`durationMs`、`windowsError`、`attemptCount`、`sourceTry`、`globalTry`、
  `capturedStdoutBytes`、`capturedStderrBytes` 与汇总计数；二者仅表示 Runtime 保留的有界诊断
  快照长度，不表示 uv 进程实际写出的总字节数；
- 源与尝试：`sourceKind`、`source`、`attempts`、`failures`、`relay`、`bySource`；
- 运行事实：已知协议 `code`、`mode`、`state`、`sink`、PID、端口和连续探针错误数；
- 路径字段：只保留 basename。

容器只接受 JSON 基础标量、字符串键 map 和 slice，并显式规范化 `[]map[string]any`、`[]string`、
`json.Number` 及具名基础标量；未知字段、凭据字段（连同字段名）、struct、pointer、非字符串键 map
与自定义 marshaler 默认丢弃。`INTERNAL_ERROR` 与 panic 不携带普通失败
diagnostics。

包含 `details` 外壳的完整 diagnostics JSON 总计不超过 8 KiB；单字符串最多 512 字节，超限或
不符合字段语义的值直接丢弃。`BeforeSend` 从同一 schema 重新构造 context，防止调用方绕过 CLI。

## uv 可排查信息

uv runner 与依赖封装在已存在的 details 中增加稳定 `failureKind`，并记录 stdout/stderr 有界捕获
快照的字节数，不记录内容。至少区分请求/路径无效、进程启动、管道关闭、进程隔离、输出读取、非零退出、
锁检查非零和依赖同步非零。结合 code、stage、exitCode、版本、镜像尝试与 relay 汇总即可判断
修复入口；完整 stderr 继续只存在于本地轮转日志或受控本机诊断中。

## 不负责

- 不上传 pre-session 或最终 result 写失败后无法形成的观测；
- 不解析 uv/Git 自然语言输出驱动错误分类；
- 不访问真实 Sentry，不配置或推送远端凭据；
- 不修改业务包的错误码、retryable、remediation 或用户可见协议 details 语义。
