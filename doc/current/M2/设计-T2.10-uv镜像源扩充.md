## 目标与边界

T2.10 只扩充 `mirror.DefaultCatalog` 的 uv 二进制镜像源，不改变：

- uv 固定版本、Windows x64 资产名或 SHA-256；
- `Policy` / `Plan` / `Rotator` 的导出 API、每源重试次数或官方兜底语义；
- HTTPS/TLS、重定向和下载器的失败关闭规则；
- CLI 参数、NDJSON、错误码、stage、状态或目录布局。

网络源可用性会漂移。内置目录只代表本次发布经过完整性验证的确定性候选顺序，
不承诺任一第三方源永久在线。

## 准入验证

固定目标为：

- uv 版本：`0.12.3`；
- 资产：`uv-x86_64-pc-windows-msvc.zip`；
- 字节数：`19,013,455`；
- SHA-256：`b23350c79e8ad0192b8124af13a0f17e8d4e4549524785e1aef389ae5a06990e`。

2026-08-10 对候选源做两轮实际 HTTPS 下载：一轮使用 PowerShell 7
`Invoke-WebRequest`，一轮使用与 Runtime 请求一致的 `Go-http-client/1.1` User-Agent 和
`Accept-Encoding: identity`。结果如下：

| key | Base URL | 结果 | 决策 |
| --- | --- | --- | --- |
| `agentsmirror` | `https://uv.agentsmirror.com/github/astral-sh/uv/releases/download` | 两轮均完整下载，字节数与 SHA-256 匹配 | 加入，默认首选 |
| `gh-proxy` | `https://gh-proxy.com/https://github.com/astral-sh/uv/releases/download` | 两轮均完整下载，字节数与 SHA-256 匹配 | 保留既有 key，默认第二 |
| `cdn-gh-proxy` | `https://cdn.gh-proxy.com/https://github.com/astral-sh/uv/releases/download` | 一轮完整匹配；一轮 90 秒内下载部分内容后超时 | 加入后置候选 |
| `edgeone-gh-proxy` | `https://edgeone.gh-proxy.com/https://github.com/astral-sh/uv/releases/download` | 一轮完整匹配；一轮响应中断 | 加入后置候选 |
| `ghfast` | `https://ghfast.top/https://github.com/astral-sh/uv/releases/download` | 两轮均返回 HTTP 403，未产出资产 | 不加入 |

`cdn-gh-proxy` 和 `edgeone-gh-proxy` 的波动由既有有界轮换处理：失败后换源，不放宽完整性校验。

## 默认顺序

uv 类别的默认顺序冻结为：

1. `agentsmirror`；
2. `gh-proxy`；
3. `cdn-gh-proxy`；
4. `edgeone-gh-proxy`；
5. `github`（官方兜底）。

显式 `--mirror uv=<key>` 仍把选定源移到计划首位；`--mirror-only` 仍排除
`github`；`--offline` 仍不发起任何网络请求。

## 验收

1. `TestDefaultCatalog_ExactSourcesAndOrder` 精确断言上述 key、Base URL、顺序和官方标记。
2. 先修改测试并确认因缺少三个新 Source 出现预期红灯，再修改 `defaults.go`。
3. `go test ./internal/mirror -count=100` 和仓库标准验证门全绿。
4. 生产代码仍无 HTTP、TLS 跳过开关、在线安装脚本或 uv 版本/SHA 改动。
