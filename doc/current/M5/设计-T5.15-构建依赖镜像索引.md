# T5.15 源码包构建依赖镜像索引

Issue #25 中锁内制品已正常使用镜像，源码包构建所需的 setuptools / wheel
仍请求官方 PyPI。锁副本的 registry 改写不能替代构建环境的默认索引设置。

在 `runStagedSyncWithEnvironment` 向共用的 `mirrorSyncArguments` 传入
`rewrite.SimpleBase()`，追加 `--default-index` 参数。中继启动时该值是回环
`/simple`，逐源镜像路径每次使用当前源的 simple 地址。

只修改 `--frozen` 锁副本安装。原锁的 `uv lock --check`、直接 `--locked`
同步和离线路径不加覆盖参数；不修改仓库项目声明和锁文件、不关闭构建隔离，
不新增环境放行键、错误码或外层重试。同步失败、取消、镜像耗尽、临时目录和
Relay 关闭沿用既有路径。先修订架构与增补 2 C17，再实现本任务。

默认单元测试通过 uv 替身锁定 Relay 与逐源轮换的显式索引参数，以及原锁检查、
离线和官方回退的参数边界。显式启用的真实构建测试使用固定 uv 0.12.3 与预先准备的
受管 CPython 3.12.13：本地 TLS 镜像提供合成 sdist、构建后端 wheel 与后端需要导入的
第二个构建依赖 wheel，真实执行隔离构建并确认包已安装。每例缓存与 venv 独立，
第一个镜像的构建索引不可用；两条路径都须从第二个镜像取齐构建依赖。

测试代理拒绝全部非回环请求，断言外部请求数为零；同时注入无效的宿主默认索引，
验证 C20 隔离仍生效。TLS 使用临时 CA 签发的回环服务端证书，未放松验证。
这证明通用 PEP 517 构建依赖接线，不代替现场 pyscreeze / pytweening 的网络复验。

```powershell
# 调用者预先准备固定 uv 与受管 Python，测试不会下载工具或解释器。
$env:AUTO_MAS_TEST_UV_EXE = '<固定 uv 0.12.3 的 uv.exe 路径>'
$env:AUTO_MAS_TEST_PYTHON_DIR = '<含 CPython 3.12.13 的受管安装目录>'
$env:GOCACHE = Join-Path $env:TEMP 'auto-mas-runtime-verify'
& go test ./internal/uv -run '^TestDependencies_BuildDependenciesIntegration$' -count=1 -v
if ($LASTEXITCODE -ne 0) { throw 'real build integration failed' }
```

未设置上述两个测试变量时真实构建测试显式跳过，默认测试不依赖机器上的 uv / Python。
