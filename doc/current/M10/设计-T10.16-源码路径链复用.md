# T10.16 源码路径链复用

## 目标与边界

源码恢复扫描为每个文件重新固定完整路径链。复用一次扫描中仍持有的公共祖先句柄，降低日常启动的本地校验耗时。依赖 T4.12 的源码恢复；不改变 Git 遍历、内容哈希、排除策略、CLI、状态或遥测契约。

## 所有权与安全语义

`ManagedSourceReader` 在一次顺序扫描内持有一条目录链，不跨协程、操作或进程共享。构造时沿原有 `openPinnedChainWith` 固定应用根上级至 repo 的目录；读取时规范化目标并限制在该 repo 内，关闭非公共后缀，再打开新的后缀。

目录句柄持续不共享删除，阻止替换和重命名。复用前从句柄重新查询 volume/file-ID、目录/Reparse 属性和大小写模式。新目录与叶子继续走 `openRelativeCheckedWith` 的最终路径、父目录身份、Reparse 和大小写验证；文件保持只共享读取、有界读取和取消处理。缓存的是持续持有的能力，不是路径字符串或旧属性快照。

检查结束后先关闭读取器，再执行原有 `beforeWrite` 与恢复写入。关闭失败不继续扫描，未关闭句柄可以通过 `Close` 重试；错误链保留。非 Windows 入口继续失败关闭，不增加跨平台支持。

## 验证计划

1. 临时受管目录测试公共祖先禁止替换，换目录后释放非公共后缀，关闭后解除固定。
2. 通过 Windows API 边界注入目录身份、Reparse、大小写模式变化和关闭故障，要求失败关闭及可重试清理。
3. 验证读取期间禁止写句柄，并复用源码缺失、被修改、Git 对象缺失、目录冲突、取消和恢复失败状态测试。
4. 恢复前允许重新固定或创建原扫描目录，防止缓存句柄妨碍修复。
5. 对同一安装版源码按轮交替运行两侧只读诊断构建，确认校验范围一致；通过基于临时目录的基准入口复现路径读取成本。

## 本地证据

Windows、Go 1.26.10，目标 commit `a640598bf521c59cb255202e95ae2595dd690b45`。两侧各 5 轮，交替先后顺序，每轮独立进程；均遍历 3511 个 Git 文件条目、哈希 1268 个文件、读取 60.48 MiB，发现需要修复时中止，未修改安装版。

| 测量 | 优化前中位数 | 优化后中位数 |
|---|---:|---:|
| 关闭分段计时的完整源码扫描 | 2880.2 ms | 1605.0 ms |
| 带分段计时的完整源码扫描 | 2880.7 ms | 1663.5 ms |
| 路径规范化与范围检查 | 274.5 ms | 117.6 ms |
| 路径链固定与身份检查 | 1459.7 ms | 454.3 ms |
| 关闭句柄 | 46.5 ms | 5.9 ms |

完整扫描缩短 44.3%。数据来自本地诊断插桩；正式实现移除了计时调用，功能路径一致。顺序读取未清空 Windows 缓存，不能据此承诺冷启动或完整桌面启动收益。

可移植基准只测临时目录文件读取，不包括 Git 对象访问：

```powershell
go test ./internal/filesystem -run '^$' -bench '^BenchmarkManagedSourceReader$' -benchtime=1x -count=3
```

原诊断分支的安全与恢复定向测试、读取器安全测试重复 20 次、Windows vet/build 均通过。全量测试遇到现有临时目录清理和 SUBST 盘映射失败；清理失败用例原样复跑通过，SUBST 在未优化基线同样复现。Race 验证缺少 PATH 中的 GCC，未完成。后续 PR 验证以正式分支及 CI 的实际结果补充，不将这些边界称为通过。
