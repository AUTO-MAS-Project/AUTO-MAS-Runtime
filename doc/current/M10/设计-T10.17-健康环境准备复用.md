# T10.17 健康环境准备复用

完整 bootstrap 新增 `--reuse-ready-environment`，仅改变环境复用权限，不改变工作区目标选择。原参数默认行为保持；`--if-needed` 的日常启动语义保持。

持原 mutation 锁完成事务恢复、工作区同步和源码真实性检查后，仅当工作区未变化、初始和仓库状态均 ready、版本及 Commit 匹配、venv 结构完整，才允许复用。新选项还用现有 CheckPython 复验受管 Python，随后执行既有离线解释器与锁定依赖检查。明确未就绪回原准备流程；取消、输出、进程或状态基础设施错误直接失败。源码恢复和环境重建不短路。

`version` 的 result.details 追加 `bootstrapEnvironmentReuse: true`。桌面端从已有 exe 版本查询提取该能力，在成功对齐的本次结果中传递；旧 exe 或未知能力不传新参数，不猜测首发版本，不增加进程。独立 repair、重建和普通失败重试不启用此选项。进度沿用现有完成收口，遥测复用原命令结果观察者。

新选项若执行完整准备，必须在写入 ready 前严格离线复验实际解释器和锁定依赖。同步退出 0 不能替代此实证；仍未就绪或复验故障经既有持久化入口写 broken，保留原错误码与 cause，不再递归准备、不自动删除 venv。健康快速返回不增加检查。旧默认、if-needed 与独立 sync 的既有行为保持，本次不修复它们的配置恢复缺口。

不合并准备与监督，不改锁、进程、源测速算法或 uv 安装/同步的全局语义，不改安装版。

## 实施与验收

1. 先扩展 bootstrap 的 alpha 更新、健康/损坏及错误分类矩阵，确认新选项在基线因不支持而失败；补 version 能力断言。
2. 实现独立复用策略及受管 Python 检查，保留原依赖检查和修复；定向回归、vet、build、全仓检查。
3. 主程序接入能力透传及正常初始化选项，覆盖旧/未知 exe、升级后能力、离线、进度和重建语义；运行相关测试、Electron 编译与格式检查。
4. 在隔离 app root 用真实 uv 和相同仓库/环境，交替测量旧/新二进制。保留网络探测与实际动作证据，验证健康/缺包/解释器失效的原行为。
5. pstack 审查规范和规格，修复可复现问题后复验。记录验证限制，不以模拟计时替代真实性能。

实现、真实计时与损坏试验、规范及规格双轴复审已完成，结果见[本地验收](验收-T10.17-健康环境准备复用.md)。复验开始事件的输出故障也会写 broken；测量身份漂移会中止。进入正式 PR 交付，全仓检查保留有记录的环境失败说明，未替换安装版或发布。
