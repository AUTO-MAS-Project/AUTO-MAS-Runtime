# T10.11 旧后端兼容

新 Runtime 先更新时，允许没有健康 proof 的旧后端启动；仍校验完整协议、版本/commit（managed）与 Job，连续就绪后由调用方写一次日志。不增加协议 warning。非空错误证明或本轮已见有效证明后的缺失证明仍失败关闭，不尝试无签名关闭重试。旧关闭接口忽略新增签名请求头，保持原行为。

health 不依赖 logging：Expectation 注入 LegacyReady(context.Context) error 回调；nil 保持严格校验，生产监督显式接入操作日志与统一 Emitter。回调失败按既有内部错误路径收口，不泄漏密钥。每次自动重启重新检查并单独提示。

计划：文件 health/checker.go、health/health_test.go、backend/supervisor.go、backend/control.go、backend/port_test.go。红灯 TestHealth_LegacyBackendCompatibility 覆盖允许旧响应并提示一次、错误身份和 Job 拒绝、错误 proof 拒绝、已认证后拒绝无证明；TestBackend_LegacyHealthNotice 写操作日志和 protocol log。绿灯最小实现；定向 go test -v -run、全仓标准门、protocol -count=100 与全仓 race；每条命令检查退出码。验收后计划由 Git 历史追溯。
