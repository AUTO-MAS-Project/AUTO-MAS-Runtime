# T11.5 macOS 跨进程锁设计

在已通过 macOS 15/26 双 APFS 矩阵的 T11.4 分支基线上，先实现跨进程锁。PID 身份与 StateFiles 事务分别验收，生产 CLI 保持能力门关闭。

Darwin 用 `runtime-state` 下由 config 集中定义的 `backend.lock`、`mutation.lock` 和 `lock-coordinator.lock`。三个名称只用于 Runtime 自身协调，永不在释放、崩溃恢复或清理时删除重建。诊断使用固定叶名，不包含安装根。Windows 仍用既有命名 Mutex。

Set 先固定应用根 FD；变更需要时才以该 FD 相对创建/打开状态目录。只读 Probe 不创建目录或文件。只在可证明不存在时报告空闲；已有锁文件必须是同卷普通文件、单链接、零长度，打开后和操作前后均复核名称与对象身份。已观察的锁或目录被替换时该 Set 失败关闭。物理目录别名使用同一锁文件。沿用同 UID 信任边界，不保证强制抵御非协作同 UID 进程主动替换后另起全新 Set。

获取、对端探测和协调门的释放在短时独占 `flock` 内串行化。门用非阻塞探测和可取消的短时重试，超预算返回现有 `MUTEX_OPERATION_FAILED`。业务锁只探测一次；本锁占用和对端占用保留现有错误码。staging 使用 mutation 锁，允许另一个 Set 已持有 backend；同一个 Set 仍只签发一个 Lease。只读 Probe 进入同一门，已存在业务叶但门缺失视为不明现场。

Lease 独占 FD，关闭即释放；正常关闭和持有进程被杀均不改文件身份。POSIX 不提供 abandoned 事实，因此 `Recovered` 始终为 false；事务是否陈旧由后续状态和 PID 身份证明。取消、身份变化或收口失败均不交付新 Lease。
