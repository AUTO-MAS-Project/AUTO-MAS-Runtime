# T11.1 跨平台适配设计

日期：2026-11-14。平台基线按本轮任务冻结：Ubuntu 24.04 LTS、macOS 15 及以上，均覆盖 amd64/arm64。Windows 10/11 x64 继续作为 Tier 1。

## 范围与边界

目标是让相同的 CLI、NDJSON、错误码、stage/state 和相对目录布局在 Windows、Linux、macOS 上成立。首批 POSIX 功能包括 bootstrap、workspace 更新、uv/Python/依赖、backend supervise、doctor、repair、cleanup。Runtime 不接管用户数据、插件依赖或业务 HTTP/WebSocket。

## 平台实现方案

| 领域 | POSIX 实现与安全边界 |
| --- | --- |
| `filesystem` | 逐段 `openat`/`O_NOFOLLOW` 检查受管路径；记录目录/文件设备号与 inode；删除和 rename 前复核身份；原子替换只允许同文件系统；身份不明时失败关闭。Linux/macOS 分文件实现并共享上层契约。 |
| `state` | 同目录独占临时文件，写入后 `fsync` 文件、rename、`fsync` 父目录；沿用 Windows 状态枚举和恢复状态机。 |
| `lock` | 安装根 inode 上的短期 `flock` 门闩与封闭 xattr 租约记录；按 PID/内核创建身份恢复死亡所有者，同一 Set 只持有一份租约；不支持文件系统失败关闭。 |
| `process` | 后端独立 session/process group；保留 pid、启动时间及可用的进程身份信息；HTTP 优雅关闭预算耗尽后 KILL；用 `wait`、进程组探测及宿主存活管道回收后代。若无法证明回收完整则返回失败，不启动无监督后端。 |
| `backend` | 复用现有 supervisor 与 health/control 状态机；POSIX 只替换平台工厂和进程实现，NDJSON 不分叉。禁止按名称查杀。 |
| `doctor` | 使用 `statfs`/`statvfs` 查询可用空间，文件系统能力以运行时探针表达；Windows 专属 FAT/NTFS 诊断仅在 Windows 编译。 |
| `cleanup` | 复用受控删除；lock 占用探针使用对应 POSIX 锁语义。任何目录身份或符号链接状态不明均停止清理；仅受管 uv 缓存中已用 no-follow 方式核验的叶子链接可删除链接条目本身，链接目标永不遍历。 |
| `uv` | 按 GOOS/GOARCH 选择官方固定版本资产及 SHA-256；Python 下载目标过滤 `linux`/`macos` 与 `x86_64`/`aarch64`。所有 uv 调用仍经唯一执行器。 |

CI 在原生平台执行 gofmt、vet、build、适用测试、version/doctor NDJSON smoke。Release 对四资产统一生成 SHA-256 并验证下载/运行；CNB 发布与回填沿用同一资产集合及哈希校验。Windows 现有 x64 构建、签名与校验链保持原样。macOS 首批不签名、不公证，Release notes 明确 Gatekeeper 提示及手动允许运行说明。

## 验收矩阵与限制

| 能力 | Linux amd64/arm64 | macOS amd64/arm64 | 证据 |
| --- | --- | --- | --- |
| 格式、vet、build、单元/组件 | 原生 runner 全跑 | 原生 runner 全跑 | CI 日志 |
| 路径链接攻击、身份替换、原子替换、并发锁 | 原生测试 | 原生测试 | T11.2 |
| bootstrap、Git 更新、uv 环境同步、repair、cleanup | 原生组件测试 | 原生组件测试 | T11.4 |
| backend 健康、关闭、宿主/异常退出、进程后代 | 原生 E2E | 原生 E2E | T11.3 |
| 发布产物和 NDJSON smoke | 原生 | 原生 | T11.5 |

标准库抽象和交叉编译只能证明编译，不代替原生安全/进程验收。`flock` 对不支持或语义不明的文件系统失败关闭；不承诺网络文件系统。普通 worker/Agent 继承受管 session 与进程组；游戏、模拟器允许显式 `setsid` 建立新 session，生命周期归创建方。仅重设进程组不是受支持的脱离方式。内部守护模式使用同一可执行文件与专用存活管道，在握手完成后才启动后端；宿主异常退出时回收受管进程组，守护进程不持有协议 stdout。真实 AUTO-MAS 游戏启动接线单独联调。macOS Gatekeeper 可能阻止未签名资产首次运行。

## 实施顺序

依次执行任务拆分中的 T11.2（文件系统/状态）、T11.3（锁/进程）、T11.4（部署与平台工具链）、T11.5（CI/发行）。每个任务先新增失败测试，再实现；每个任务独立审查与提交。全阶段保留 Windows 全量验证。跨平台实现不满足安全不变量时先补设计/任务文档，不以“尽力而为”实现放宽语义。

## 独立审查修订（2026-11-15）

- POSIX 没有 Windows deny-delete 的等价目录租约。递归变更在每一层和每个叶子操作前复核完整祖先链；任何移动、身份变化或跨设备目录都停止，不能只在完成后校验。
- 单独的锁文件 flock 无法防止同用户重命名活动锁文件后创建第二把锁。锁协调改用安装根目录 inode 上的短期 flock 门闩与该 inode 的封闭扩展属性保存租约所有者（PID、内核创建身份、随机 token）。每次获取在同一个门闩内校验所有者存活，死亡所有者可恢复；不支持目录 flock 或扩展属性时失败关闭。此方案不创建 runtime-state，且保留 staging 与 backend 并存。直接篡改根 inode 的租约扩展属性不属于受支持操作。
- 守护进程的内部 FD 在 exec 后端前设置 close-on-exec；宿主同时监测守护进程退出，异常退出必须兜底回收并传播错误，Close 不得仅以守护进程已退出作为回收证明。

macOS 根级固定系统别名 `/var`、`/tmp`、`/etc` 按系统布局展开到 `/private` 后，再逐段拒绝链接。其他目录链接仍拒绝；安装根与锁身份始终按内核 inode 确认。

所有 uv 调用（包括一次性探针、安装、依赖同步）在 POSIX 上经同一守护机制执行；原始流仍由 uv 的有界解析器处理。正常 EOF 先排空，超时才取消回调并关闭管道。doctor 的 Python 探针强制 `--no-cache`，消费 uv 返回的真实版本化安装路径，不假定安装目录被展平。
