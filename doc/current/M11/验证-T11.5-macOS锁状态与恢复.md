## 2026-11-21：Darwin 状态事务与 PID 身份落地

- 红灯：macOS 15 ARM64 上 `go test ./internal/filesystem -run 'TestPOSIXState_' -count=1` 两个用例均以 `filesystem capability is unsupported on this platform` 失败——Darwin 只有 `//go:build linux` 的 `state_files_posix.go` 与占位桩。
- 实现：
  - `internal/filesystem/state_files_darwin.go`：每次事务重新打开 state 目录、复核构造时固定的物理身份，锁**目录 inode** 而非可替换的守卫文件；读取有界快照并在读取后复核名称仍指向同一对象；原子写入为「同目录独占临时文件 → 文件同步 → 身份复核 → `renameat` → 目录同步」；条件删除只移除与本能力读取身份和摘要一致的快照。
  - `internal/filesystem/transaction_darwin.go`：`replaceDarwin` 负责上面的提交点，失败只清理本次创建的临时文件。
  - 并发初始化：state 目录允许多实例同时首建，`Mkdirat` 的 `EEXIST` 收敛后重新按 no-follow 打开并复核身份。该收敛只作用于 state 目录打开路径，`PrepareManagedDirectory` 的「已存在即拒绝」语义保持不变（`TestDarwinDirectory_PrepareAndInspect` 仍通过）。
  - `internal/filesystem/capability_darwin.go` 与 `state_types_darwin.go`：删除状态能力占位桩，保留其余未开放能力（删除、下载、日志）的占位。
- PID 身份：新增 `internal/state/pid_posix_test.go`（`linux || darwin`）覆盖当前进程存活、`CreatedAt`/`Identity` 的可重复稳定、退出后判死与创建时间失效、非法 PID 与已取消上下文。helper 进程用 pipe 闸门而不是 `time.Sleep`，退出后先 `Wait` 再断言 `Alive=false`。
- 本机证据（macOS 15.7.7 ARM64、Go 1.26.11、`-race`）：
  - `go test -race ./internal/filesystem -count=10` 退出 0（全包，不再有状态能力失败）。
  - `go test -race -v ./internal/filesystem -run '^TestPOSIXState_' -count=100` 退出 0，共 200 条 `--- PASS`。
  - `go test -race ./internal/state -count=20` 退出 0。
  - 大小写敏感 APFS 卷（`TMPDIR=/tmp/m11-apfs/mnt/tmp`）：`TestPOSIXState_` 20 轮、`internal/state` 5 轮均退出 0。
  - `GOOS=windows GOARCH=amd64` 与 `GOOS=linux GOARCH=amd64` 的 `go build -buildvcs=false ./...` 均退出 0。
- 门禁：`scripts/verify-posix.sh` 的 darwin 分支新增 `TestPOSIXState_` 与 `internal/state` 的 race 运行；`macos-prototype.yml` 把 `TestPOSIXState_` 纳入两档 APFS 的 100 轮矩阵，并新增 `internal/state` 全包一次 + `TestSystemPIDProbe_POSIX` 100 轮；`TestMacOSWorkflow_PrototypeBoundary` 断言这两类用例不会被移出原型工作流。

## 2026-11-21：cleanup 副作用与状态恢复复核

- `cleanup.Service.Run` 在分类遗留 `repo.update-*` 前获取 mutation 锁。Darwin 的锁设计将持久锁叶放在 `runtime-state/`，因此首次获取锁会创建该目录与协调锁文件；该创建发生在 `classifyRepoUpdate` 之前，不是状态读取本身创建的。
- 这与 `doc/任务拆分.md` 的 T3.6 F2「无事务 `repo.update-*` 场景不得创建 `runtime-state/` 与 `.update.guard`」存在冲突。待明确并落实兼容的目录与锁方案前，不能把仅允许 Darwin 创建锁文件的测试改动当作解决该验收项的证据，也不能删除已通过的无目录创建约束。
- 当前 Darwin `replaceDarwin` 使用临时文件同步后直接 `renameat`，没有实施 T11.5 计划 Task 3 所列的 sealed intent、旧对象备份与逐阶段恢复协议。上述状态测试只证明现有路径的定向行为，不能证明崩溃恢复矩阵通过；CLI 能力门必须继续关闭。
- 在尚未提交的 cleanup 测试和工作流改动上，本机 macOS 15 ARM64、Go 1.26.11 执行 `go test -race ./internal/cleanup ./internal/release -count=1`，退出码 0。该结果仅说明当前测试断言通过，不解决前述验收冲突。
