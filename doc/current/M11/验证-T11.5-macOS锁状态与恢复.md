## 2026-11-10：跨进程锁本地验证

- 红灯：Windows 上以显式源文件列表执行 `go test -v ./internal/lock/set_other.go ./internal/lock/kind.go ./internal/lock/errors.go ./internal/lock/set_darwin_test.go -run '^TestDarwinLock_StagingMatrix$' -count=1`。测试在旧桩返回 `lock set is unsupported on this platform` 处失败；这证明缺少实现，不算原生红灯。
- 实现：`5b56746`。同一根下的业务锁和协调门固定在持久文件；已观察的身份丢失或变化时拒绝交付租约，正常关闭或持有进程退出不删除锁文件。保留原冲突码、staging 例外和只读探测。
- Windows：`gofmt -l .`、`go vet ./...`、`go build -buildvcs=false ./...`、`go test ./... -count=1`、差异检查、protocol 100 轮及 `go test -race ./... -count=1` 全部退出 0。
- Darwin：`GOOS=darwin GOARCH=arm64 CGO_ENABLED=0` 下完整交叉构建、lock/filesystem vet、lock 测试编译通过；Linux 失败关闭桩仍可交叉构建。
- 原生矩阵已接入两档系统与两种 APFS 的定向 race 100 轮，尚未推送运行。持锁进程被杀、锁替换和真实互斥只在原生测试通过后记为已验收。PID 与状态事务留给 T11.5 后续小任务，生产 CLI 能力门仍关闭。

- 基线为 `6b02c51`，测试代码提交为 `89c21f9`；macOS 15.7.7（24G716）、ARM64，Go 1.27.1。临时目录所用卷的 APFS 大小写模式未确认。

- 本机执行 `GOCACHE=/tmp/auto-mas-runtime-go-cache go test -race -v ./internal/lock -run '^TestDarwinLock_' -count=100 -timeout=5m`，退出码 0，新增测试出现 100 条 PASS，无 `[no tests to run]`。
