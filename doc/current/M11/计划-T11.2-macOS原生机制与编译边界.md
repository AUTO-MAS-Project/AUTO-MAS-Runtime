# T11.2 / T11.3 实施计划

## 边界

先形成可以在 macOS 14/15 ARM64 运行的本地原型和完整程序编译；尚未证明的生产能力失败关闭。
不创建正式 launchd 服务、不修改其他仓库、不发行或推送。原型中的 launchd job 和 IPC 只存在于测试生命周期。

## Task 1：编译边界（T11.3）

- 文件：`internal/filesystem/*_other.go`、`internal/lock/set_other.go`、`internal/state/pid_other.go`、`internal/doctor/probes*.go`、`internal/backend/production_other.go`、`internal/config/layout*.go`、`internal/cli/platform*.go`。
- 红灯：`GOOS=darwin GOARCH=arm64 CGO_ENABLED=0 go build ./...` 暴露公共文件的 Win32 导入与缺失类型；`TestExecute_PlatformBoundary`、`TestLayout_POSIXIdentity` 验证版本协议、命令拒绝、零副作用和根路径拒绝。
- 绿灯：只隔离平台 API，不提供未经证明的路径写入/进程监督降级。
- 验证：Windows 全量标准门；Darwin 全仓 build 与本期选定测试包编译；原生用例由 Task 2 的 Actions 运行。既有 filesystem/gitrepo 测试仍直接依赖 Win32 内部能力，留在 Windows 全量门执行，替换矩阵属于 T11.4/T11.8，不声称 Darwin 全仓 test 已通过。代码提交 `feat: 建立 macOS 编译与能力边界 (T11.3)`。

## Task 2：原生原型（T11.2）

- 文件：`internal/macosprobe/*`、`.github/workflows/macos-prototype.yml`、`internal/release/macos_workflow_test.go`。
- 固定用例：`TestLaunchd_OwnerDisconnect`、`TestLaunchd_GuardKilled`、`TestRoot_PathReplacement`、`TestRoot_AncestorSymlink`。
- 红灯：先让原型依赖缺失的操作函数，使用 `go test -c` 确认失败位置；实际机制若不满足断言则原生 job 必须失败。
- 绿灯：启动确认后才断连/强杀，使用 Unix socket、kqueue 退出事件与超时；目录交换使用确定步骤。显式记录原型未覆盖的事实，不能宣称生产就绪。
- 验证：工作流与协议边界的本机检查；两档 macOS 原生原型与 race、资源收口和系统信息。代码提交 `test: 增加 macOS 原生机制验证 (T11.2)`。

## 验证命令（PowerShell 7）

```powershell
$env:GOOS = 'darwin'
$env:GOARCH = 'arm64'
$env:CGO_ENABLED = '0'
go build -buildvcs=false ./...
if ($LASTEXITCODE -ne 0) { throw 'Darwin build failed' }
```

定向运行统一使用 `go test -v`，同时校验退出码为 0、输出不含 `[no tests to run]`、包含 `--- PASS:`。
