## T11.5 锁、进程身份与状态恢复

继续使用固定 flock 叶及短时协调门。持锁进程被强杀后，由内核释放租约，下一个持有者应拿到同一锁对象。探测不得初始化目录或锁。对象替换后拒绝继续操作。

使用内核报告的 PID 和创建时间确认身份。消失和 zombie 视为不存活，权限不足、不完整身份和无法解释的内核错误保留现场。PID 相同但创建身份不同，表示原持有者已经离开，恢复不得向新进程发信号。

状态事务沿用共享意图和恢复流程。在固定守卫下，从已打开的目录 FD 校验目录、事务文件和目标文件的身份及旧新摘要，再相对该 FD 发布或按快照条件删除。仅当磁盘状态符合意图记录可解释的阶段时才继续恢复。目录或文件被替换、摘要不符、身份未知时保留原现场。单独记录进程强杀恢复和整机断电耐久性，前者不能作为后者的证据。

## T11.6 launchd guard 与监督

每次启动创建唯一临时用户级 job，使用当前登录用户可达的 launchd 域，在无桌面环境中使用用户域。使用同一 Runtime 二进制的私有 guard 入口，guard 保留在 launchd job 进程组内，uv 和普通后代同组。显式脱离进程按既有后端契约处理。

每代使用用户私有且路径长度受限的临时目录，权限 `0700`。目录包含 job 注册文件和权限 `0600` 的 Unix socket。连接在限定时间内完成对端 UID、代次和启动确认校验，校验通过后才允许启动受管子进程。IPC 传输有界控制帧、退出状态和日志，Runtime 独占公开 NDJSON 输出。连接断开、注册失败、握手超时或 guard 异常退出时收口该代，清理 job 与临时目录。确认旧代资源收口后才能重启。launchd 验证覆盖同组清理及显式脱离。

## T11.7 工具链

固定官方 Darwin ARM64 uv 制品和摘要。tar 解包仅提取预期安全成员，验证结构化 Python 安装身份和解释器链接。用项目锁验证 ARM64 wheel 和 marker 选择。真实下载与离线复跑走独立集成验证，镜像、中继、取消和故障恢复使用可控夹具。

## T11.8 命令能力与证据

按架构和命令分批开放，每批依次覆盖只读检查、部署维护、后端监督。每批纳入正式提交前，先在 macOS 15 和 26 ARM64 运行候选工作树的原生 CLI 黑盒测试。对尚未开放的命令检查 `UNSUPPORTED_MODE` 和目录、网络、进程零副作用。每条 NDJSON transcript 验证 `hello` 首发、序号严格递增及唯一 `result` 收尾。

最终使用同一候选 SHA 在两档 macOS 完成 vet、build、全仓 test/race 和 CLI 黑盒验证，保留双 APFS 定向矩阵和关键并发用例 100 轮。另跑 Windows 标准门与 race、Linux POSIX 回归。验收记录保存 SHA、系统版本、架构、APFS 类型、执行命令、Actions run 或本地原生运行证据、逐命令结果及资源收口检查。发行资产、签名公证、真实 Electron 和 Intel 另立验收。
