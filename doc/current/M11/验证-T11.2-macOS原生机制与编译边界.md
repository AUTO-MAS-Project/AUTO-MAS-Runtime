## 原型可以回答什么

- 在无 GUI 的 Actions `user/<uid>` 域 bootstrap/bootout 临时 launchd job 是否成立。
- 确认 guard、普通 worker、孙进程和显式 setsid worker 的 PID、PPID 与 PGID 后，owner 断连或 guard SIGKILL 是否触发普通组回收。
- Unix socket 代次 token、内核对端 UID/PID 校验、短路径、权限和退出事件能否按预期工作。
- 根重命名后 `os.Root` 会继续写入原 inode，这个反例说明 FD 并不固定词法位置。
- 越界链接被 Root 拒绝，但根内链接被允许；因此 Root 不能直接代替 Runtime 的链接拒绝规则。
- 两种 APFS 大小写模式是否满足同一组确定步骤下的观察。

退出使用预先注册的 kqueue NOTE_EXIT 事件证明，不靠 sleep 或解析 ps 文本。
工作流固定两档 ARM64 系统、记录实际架构和系统版本，检查 Mach-O，并运行 race 及 100 次重复。
测试只使用自己的临时根；清理临时 job、socket、已知文件和空目录，不注册生产服务。
