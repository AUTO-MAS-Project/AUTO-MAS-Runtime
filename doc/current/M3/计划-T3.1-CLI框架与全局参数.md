## 3. RED 测试与预期失败原因

先按新 API 落测试（`cli.Execute(ctx, args, IO, options...)`、`cli.IO`、
命令树与 session 断言），并同步把 `cmd/auto-mas-runtime/main.go` 改成新形态：

1. 首次运行 `go test ./internal/cli` 预期为**编译失败**，原因：`Run()` 旧
   API 被删除，`Execute`/`IO`/`Option` 不存在；
2. `go build ./...` 预期失败，原因：`main.go` 引用的 `cli.Execute` 缺失。

编译通过后逐组运行定向测试，预期红灯原因：

- help 相关：命令树尚未注册，帮助缺子命令、NDJSON 帮助未路由到 stderr；
- flag 校验：尚未实现 output/protocol/mirror/offline 校验，错误值被当作
  合法参数，退出码不是 2/10；
- session 相关：尚无 hello/result 框架，transcript 为空或顺序错误；
- 骨架命令：尚未注册或返回非稳定错误。

## 4. 最小 GREEN 实现

1. `go get github.com/spf13/cobra@v1.10.2`（固定版本，写入 go.mod）；
2. `cli.Execute`：每次调用独立构建根命令，`SetArgs` 后 `ExecuteContext`；
3. 根命令：`SilenceErrors/SilenceUsage=true`、`CompletionOptions.
   DisableDefaultCmd=true`、隐藏默认 help 命令；`SetOut/SetErr` 按输出模式
   路由（ndjson 的 Out 指向 Err writer）；
4. 全局 persistent flags 与 `flags.go` 校验：output/app-root/protocol/
   mirror/offline/mirror-only；校验失败返回解析错误（退出码 2），
   protocol 不兼容返回专用错误（退出码 10）；
5. 完整命令树注册：version/doctor/cleanup 先挂占位 RunE（返回
   UNSUPPORTED_MODE 骨架错误，后续 Task 替换为真实服务），其余命令同骨架；
6. `session.go`：解析成功后创建 ProcessOutput（human/ndjson renderer）、
   NewEmitter（version.Version、命令路径、空 capabilities）、调用命令 RunE、
   按 operationError/context 规则发射 error+result，返回退出码；
7. `main.go`：`os.Exit(cli.Execute(ctx, os.Args[1:], IO{...}))`。

## 9. 审查项目

对照任务验收原文、`doc/代码审查清单.md` 与本设计逐项检查：

1. Cobra 只存在于 internal/cli，版本固定 v1.10.2；
2. 帮助清单与架构命令树一致，无 completion/help 泄漏；
3. 解析失败（含 protocol 不兼容）无 hello/result，退出码 2/10；
4. 解析成功 hello 首发、result 唯一且最后；
5. NDJSON stdout 无 Cobra 文本；stdout 单一所有权扫描通过；
6. cli 不含业务逻辑；未实现命令错误稳定且来自冻结错误码；
7. 退出码来自 `LookupErrorDefinition`；context 贯通；
8. 未引入 Viper 或其他新生产依赖；
9. mirror 复用 M2 模型，无第二套解析；
10. internal 包无 os.Stdout 引用。
