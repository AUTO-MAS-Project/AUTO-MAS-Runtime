## 3. RED 测试与预期失败原因

先落测试：

1. `internal/version` 测试：`Load`/`Info` 不存在 → 编译失败；
2. `internal/cli` version 测试：`version` 命令未注册（help 无此命令）、
   `Execute("version")` 返回骨架 UNSUPPORTED_MODE 或未知命令 → 断言失败；
3. 契约测试：`contracttest.Register(t, "version", versionRunner)` 尚未接入
   → 无该测试或 runner 缺失 → 编译/断言失败。

红灯原因均为「目标行为不存在」，符合 TDD 要求。

## 4. 最小 GREEN 实现

1. `internal/version`：包级变量（默认 `dev`/空串）与 `Load(ctx)`
   （返回 `Info{Version, Protocol: protocol.Version, Commit, BuildDate,
   GoVersion: runtime.Version()}`；ctx 只做取消检查，生产不失败）；
2. `cli.Option`：`WithVersionSource(func(ctx) (version.Info, error))`，
   默认 `version.Load`；版本命令 RunE 调用该源；
3. 源错误处理：实现 operationError 的错误原样返回；其他错误包装为
   `commandError{code: OUTPUT_WRITE_FAILED, stage: runtime.handshake,
   message: "无法获取版本信息"}`；
4. 成功路径：发射一条 progress 事件（stage=`runtime.handshake`、
   status=succeeded、message 为人类可读版本摘要），返回 nil；
5. cli session 框架自动补 result：成功 result details 含
   `runtimeVersion`、`protocolVersion`、`commit`、`buildDate`、`goVersion`；
6. `hello.runtimeVersion` 使用 `version.Version`（经 version.Info 读取）。
