## 3. RED 测试与预期失败原因

先落测试：

1. `internal/doctor` 包与类型不存在 → 编译失败；
2. 健康夹具：Run 未实现或结果缺失 → 断言失败（`checks` 为空）；
3. 缺失夹具：尚未实现逐项检查 → 只得到部分检查或提前终止；
4. 无副作用：尚未建立「运行前后目录树/文件内容比较」→ 无该断言或失败；
5. 探针：`Probes` 注入点不存在 → 编译失败；
6. 契约测试：runner 未接入 → 编译/断言失败。

红灯原因均为「目标行为不存在」，符合 TDD 要求。

## 4. 最小 GREEN 实现

1. `doctor.Service`：持有 `*config.Layout` 与 `Probes`；`Run(ctx, emitter)`
   按设计第 11 节逐项检查，每项先发射 running progress、完成后发射
   succeeded/failed progress，最后返回 `Report`；
2. 检查实现全部只读：`os.Stat`/`os.ReadDir`/有界 `os.ReadFile`；
   `runtime-state` 检查做大小上限（对齐 state 包上限）与严格 JSON 解析，
   不使用 `state.Store`；
3. `mutex` 检查：`lock.NewSet(ctx, layout)` + `Probe(backend)` +
   `Probe(mutation)`，完成后 `Close`；探测错误 → 该项 error 但继续；
4. `uv` 检查：枚举 `runtime/tools/uv/<ver>/uv.exe`；找到后调用
   `Probes.UVVersion(ctx, exe)`，输出原文仅作展示；
5. `disk` 检查：调用 `Probes.DiskFree(ctx, layout.AppRoot())`；
6. 生产 `Probes`：UVVersion 用 `exec.CommandContext(exe, "--version")`
   捕获输出（T5.2 后改经 uv 包）；DiskFree 用 Windows API；
7. `cli.doctor`：构造 Service，`Run` 返回 Report 后由 session 发射成功
   result，details 含 `checks` 与 `summary`；
8. `WithDoctorFactory`：供契约测试注入可失败/可取消的替身服务。

## 9. 审查项目

1. doctor 不取 mutation/backend 锁，只零等待探测；
2. 测试前后目录树、文件内容、状态文件字节完全一致（无副作用证明）；
3. 不调用真实公网、真实 Python、用户机器 Git；uv/disk 探针全部可注入；
4. 单项异常不提前丢失其他检查；error 检查项不改变命令成功语义；
5. 输出结构化检查列表 + 总结 result；human 模式可读；
6. `runtime-state` 检查不使用 StateFiles（避免创建 guard `G`）；
7. 错误码/退出码来自冻结定义；context 贯通；
8. 未引入新生产依赖（仅新增内部包与 Windows API 调用）。
