# T13.23 桌面启动恢复

## 范围与职责

Electron 统一拥有最多两轮的启动预算。Runtime 不增加准备命令的重试循环；上游 T5.18 已修复 uv 短命进程纳管竞态。Runtime 提供可验证的业务暂缓能力、幂等放行控制和启动绝对截止时间。

后端仓库 `res/runtime-capabilities.json` 声明 `deferredBusinessStart: 1`；Runtime 在启动进程前固定路径链读取并验证。`backend supervise --defer-business-start` 是严格模式：缺少声明时不创建子进程。桌面通过 `AUTO_MAS_RUNTIME_DEFER_BUSINESS_START=1` 表达偏好，旧 Runtime 可忽略它，新 Runtime 在旧后端没有声明时直接按旧模式启动，不声称该次后端可安全自动重试。仅验证支持后才注入后端专用的 `AUTO_MAS_DEFER_BUSINESS_START=1`；宿主继承的同名变量会被剔除。

## 协议

- 新能力 `stdin.activate`，新控制命令 `activate`，沿用 protocol / command / commandId 与有界去重账本。
- 放行只在 backend.run / running 时适用，读取线程只入队，HTTP 由监督循环执行。
- 健康响应新增可选 `startupActivation`：pending / active / closed；延迟启动必须取得 pending 才能报告就绪。
- 内部 `POST /api/core/startup/activate` 返回同一健康形状；不进入 OpenAPI/MCP，无密钥、签名或鉴权头，遵循 C21。
- 放行成功发 backend.run / running，details 带 startupActivation=active 和 controlCommandId；失败保留 pending/unknown 语义，不另起后端。status 返回当前状态。
- 首次放行前的后端退出结束监督，交 Electron 预算处理；已放行后维持原有一次运行期重启，并对继任进程重新完成健康与放行。

## 预算

从 supervise 开始计算 175 秒工作截止时间，覆盖桌面受控路径的预检和健康检查；清理继续独立有界。健康采用首次有效响应 60 秒、后台总预算 150 秒、失联 60 秒，任何阶段不得越过工作截止时间。健康超时后清理期间接受关闭请求，仍保留先发生的超时错误。复用 [PR #12](https://github.com/AUTO-MAS-Project/AUTO-MAS-Runtime/pull/12)（qiyinxi，`de7649506a5e7df4a0b186bda9ce3cf84b4d2c32`）的健康等待与用例，保留当前诊断字段。

## 验收

能力缺失不拉起进程；宿主同名环境变量不泄漏；pending 时不自动重启；激活幂等且可查状态；取消先到时不放行；运行期重启仍一次；35 秒预检加 150 秒健康不得越过桌面 180 秒等待。测试先红后绿，标准门和并发验证完成后更新任务记录。
