# T13.20 alpha 滚动后端

## 契约与范围

规范的 `vX.Y.Z-alpha.N` 固定解析为 `dev`；正式版、beta 和其他历史安全版本仍使用
`release/<完整版本>`。GitHub Release 的 `dev` 名称不作为 CLI 版本。
不新增任意 ref 参数，不修改 AUTO-MAS 发布工作流，不修改受管源码中的版本或锁文件。

alpha 的构建目标版本与 dev 的源码版本独立：源码版本必须仍是安全的产品版本，
不要求等于 alpha 目标或拥有同一数字基线（滚动 dev 可以进入下一开发周期）。
仓库的 remote、符号 HEAD、Depth 1、NoTags 和版本文件校验继续执行。

完整校验后，在受管仓库已有的 `.git/config` 中写入唯一的
`[auto-mas-runtime]` 节，包含 `version`、`commit`、`sourceversion`。
它只用于 dev，将 alpha 目标绑定到已验证的 HEAD 和该 Commit 的源码版本；
缺失、重复、额外字段、非 alpha 目标或不一致的绑定一律拒绝。
绑定随整个仓库原子替换，无新目录或状态 schema。绑定未完整写入时不得进入 swap。
release 仓库继续由版本文件确定身份，不读取 alpha 绑定。

检查、远端查询、stage、sync 和 recovery 统一读取绑定的 alpha 身份。
后端注入与健康校验继续要求该 alpha 版本和实际 Commit 完全相等。
同 Commit 的不同 alpha 构建仍更新目标绑定及稳定状态，避免沿用旧目标身份。
旧的 alpha release 仓库保留只读识别与恢复能力，新 sync 迁移到 dev。
旧 release alpha 的暂存不属于新的 dev 目标，迁移时按既有受控流程丢弃，再获取 dev。

## 启动与更新

普通在线 bootstrap 对 alpha 检查远端 Commit；`bootstrap --if-needed` 用于正常启动，
仍复用已准备的本地目标，避免启动隐式滚动更新。显式 workspace sync 始终按 Commit 检查。
已校验的 stage 优先应用，即使 dev 随后前进；offline 不访问网络。
运行中后端保护、基础 Commit 和目标 Commit 绑定、模糊现场失败关闭全部保留。

## 验收

- alpha 与 beta/正式版的目标矩阵、镜像目标和状态分支校验。
- 本地 HTTPS dev 克隆，源码版本不等于目标，不改版本文件和锁文件。
- dev 同目标新 Commit、无变化、不同 alpha 目标、跨数字周期。
- 运行期间 stage、重复 stage、离线应用固定 Commit、中断后恢复。
- dev 绑定缺失、重复、字段篡改与 Commit 不匹配失败关闭。
- managed 后端仍严格验证 alpha 版本和 Commit。
- 完整标准门、protocol 重复门与 race。AUTO-MAS 钉扎改动和远端发布另行交付。
