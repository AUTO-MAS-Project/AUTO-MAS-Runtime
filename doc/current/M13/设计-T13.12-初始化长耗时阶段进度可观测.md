## 目标

让 Electron 在首次初始化的长耗时阶段持续得到诚实、可消费的进度：固定 uv 制品下载使用真实字节数；
Git、Python 安装与依赖同步在总量未知时使用不带百分比的活动状态，并为已开始的阶段发出明确终态。

## 边界与事件语义

- 不新增或修改协议字段、stage、state、错误码和能力标识；沿用 v1 `ProgressEvent`。
- `uv.download` 只有在下载器取得可信总量后才携带 `current`、`total`、`percent`。三个值逐字来自
  `mirror.DownloadProgress`，CLI 不二次估算；镜像切换时允许新一次尝试从 0 重新开始。
- 缓存命中没有网络传输，不伪造字节进度；保留已有 running 与 verify succeeded 事件。
- Python 安装、依赖同步和 Git 操作没有稳定任务总量，running 事件不携带数值。Electron 应显示不定进度，
  Runtime 不解析 uv/Git 的自然语言输出，不用输出行数、耗时或阶段权重拼百分比。
- `bootstrap` 已开始的 `python.install` 与 `dependencies.sync` 在成功时各发一条 succeeded；失败与取消
  继续由既有统一失败路径收口，不改变错误四元组。
- 回调同步执行；协议写失败沿错误链保留 `OUTPUT_WRITE_FAILED`，不得降级成 `UV_DOWNLOAD_FAILED`。

## 数据流

```text
mirror.Downloader
  -> mirror.DownloadProgress（真实字节）
  -> uv.Bootstrapper Ensure/Repair progress callback
  -> uv.EnvironmentService / ProductionEnvironment
  -> cli ensureM5UV / repairM5UV
  -> protocol.Emitter.EmitProgress
  -> Electron
```

`internal/uv` 只接收 `mirror.ProgressFunc`，不感知 Electron，也不自行持有协议输出；`internal/cli` 负责把
领域进度翻译为 `protocol.ProgressEvent`，保持现有包边界。

## 不负责

- 不为无法量化的过程制造平滑百分比；
- 不把 uv 原始输出发到 stdout 或新增 `log.stream` 能力；
- 不改变 AUTO-MAS 的视觉样式与阶段权重；Electron 仅消费 Runtime 的事实并选择确定/不定进度形态。
