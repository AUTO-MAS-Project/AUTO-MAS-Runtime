## 背景与缺陷

`internal/gitrepo/clone.go` 的 `cloneProgressWriter` 把 go-git `CloneOptions.Progress` 的每次 `Write`
转成一条 `workspace.clone` / `running` 事件，累计 `maxCloneProgressPulses = 64` 条后彻底静默。这个
Writer 的唯一写入源是 go-git 的 sideband 文本，而 sideband 集中在握手阶段一次性涌入：真机初始化夹具
（AUTO-MAS 仓 `bootstrap-success.ndjson`）里 `21.298`、`21.393` 各一条，`23.260` 一瞬间 64 条，此后直到
`31.169` 的 `succeeded` 之间 7.9 秒零事件；66 条脉冲文案完全相同。真正传输 packfile 的阶段没有 sideband
文本，`Write` 不再被调用——克隆最长、最需要显示「还活着」的那一段，界面什么都收不到。

## 目标

在 go-git 传输期间，无论 sideband 是否有输出，`workspace.clone` 都以固定间隔持续发出不带数值的
`running` 事件，直到 Fetcher 发出该 attempt 的终态；终态之后不再出现 running。

## 边界

- **不带数值。** 心跳事件不设置 `current` / `total` / `percent`。这不是省事：架构设计 2026-09-05 定稿
  「Git、Python 安装和依赖同步等无法取得稳定总量的外部过程仍只发不带数值的 `running` 事件，由
  Electron 展示不定进度」。本任务只改事件的**触发时机**（从写入次数改为时间），不改事件形态，
  不新增或修改字段、stage、state、错误码与能力标识，也不改 `cloneProgress*Message` 文案常量，
  因此不触碰冻结契约，不触发红线第 2 条。
- **不解析、不外发 sideband 原文。** go-git 的 `Progress` 仍传入一个 `io.Writer`，以保持传输协商
  不变；写入内容一律丢弃，不保存、不解析、不写进任何事件（原文是外部自然语言，可能含 URL 与凭据）。
  sideband 的 `Write` 本身**不再产生脉冲**，脉冲只来自 ticker，因此「同一瞬间 N 次 `Write`」最多贡献
  0 条，满足验收的「至多 1 条」。
- **时钟注入。** ticker 经 `fetcherDependencies` 注入（生产默认 `time.NewTicker`），测试用假 ticker
  按 `advance(d)` 同步推进，不用 `time.Sleep`。
- **goroutine 生命周期由 Fetcher 负责。** 心跳在 `f.git.Clone` 调用前启动，Clone 返回后先 `stop()`
  并等待 goroutine 退出，再检查输出故障、取消与 clone 错误，再发终态事件。因此终态与心跳之间存在
  happens-before，不会有迟到的 running。
- **输出失败语义不变。** 旧实现里 `Write` 遇到 emit 失败返回错误让 go-git 中止；新实现中心跳 emit 失败
  会取消传给 Clone 的派生 context 让传输尽早结束，并在 Clone 返回后**优先**映射
  `OUTPUT_WRITE_FAILED`（`failureOutput`），先于取消与 clone 错误判定，与现有顺序一致。

## 数据流

```text
Fetcher.attempt
  -> heartbeat := newCloneHeartbeat(f.emitProgress, f.newTicker, cancelClone)
  -> heartbeat.start()                          // goroutine：每 tick 发一条 running（无数值）
  -> f.git.Clone(cloneCtx, ..., Progress: heartbeat)   // heartbeat.Write 丢弃 sideband
  -> heartbeat.stop()                           // 关闭 stop 通道并 <-done，ticker 已 Stop
  -> heartbeat.Err() != nil ? OUTPUT_WRITE_FAILED : 原有取消 / clone 错误判定
  -> succeeded / failed / cancelled 终态（f.emit）
```

`protocol.Emitter` 自带互斥锁（`internal/protocol/emitter.go`），goroutine 内直接调用 `emitProgress`
是安全的；`gitrepo` 不感知 Electron，也不持有协议输出。

## 心跳间隔

固定 `cloneHeartbeatInterval = 1 * time.Second`。依据：Electron 侧只需要「还活着」的信号驱动不定进度
动画，1 秒足以让停顿可感知（夹具里的 7.9 秒静默会变成约 8 条心跳）；更密只会增加 NDJSON 噪声而不
增加信息量；更疏（如 2~3 秒）在慢网下会让用户误以为卡死。间隔是包内常量，不暴露为 CLI 参数。
