# T13.13 同分支后端热更新检查设计

## 目标

在 managed 模式下支持同一 `release/<版本>` 分支的新 Commit 检查和后台准备。运行中的后端继续提供服务；发现远端分支有新 Commit 时，Runtime 在独立暂存目录下载并校验，成功后由 Electron 提示“下次启动生效”。下次 `bootstrap --version` 复用已校验目录完成整体替换并同步环境。

## 方案

Runtime 新增 `workspace check --remote`。命令先读取当前受管仓库身份，再按当前版本推导唯一 release 分支，使用既有镜像轮换和 HTTPS Git reference discovery 查询远端分支指向的 Commit。命令只读，不取得 mutation/backend 锁，不创建事务，不写状态，不下载工作区。

结果新增 `remoteCommit` 与 `updateAvailable` 字段。远端不可用按既有 Git/网络错误码失败，调用方将其视为“本次未检查成功”，不影响当前后端。

Runtime 新增 `workspace stage --version`。该命令允许后端继续运行，使用 `repo.update-<operationId>` 获取并校验目标仓库，并保留 `update.json` 作为待启用事务；它不替换 `repo/`、不修改环境、不停止后端。下次 `workspace sync` 或 `bootstrap` 识别同版本的待启用事务后直接复用暂存目录，再按原子 swap 流程启用。

`workspace sync --version` 的 no-op 条件收紧为版本、分支和 Commit 均相同。同版本但 Commit 变化时继续完整 clone、verify、swap 和环境失效流程。Runtime 不接受任意分支或 Commit 参数。

Electron managed 模式在后端启动后周期调用 `workspace check --remote`。检查成功且 `updateAvailable=true` 时立即调用 `workspace stage`；暂存成功后设置共享更新提示，不主动停止或替换后端。用户点击提示或下次正常退出后，应用重启初始化再次调用同版本 `bootstrap`，从而启用同分支更新。

## 边界

- development/off 模式不执行 Runtime 远端检查。
- 后台允许保留一份经过校验的暂存工作区，但不在后台替换正在运行的仓库。
- 远端检查失败只记录日志并等待下次检查。
- 远端 Commit 只作为提示和同步 no-op 判定依据，不改变版本到分支的信任模型。

## 并发与恢复约定（2026-09-05 收口）

- stage 独占现有 mutation Mutex，但允许 backend Mutex 被持有；不写 mutation.json 或 environment.json。其他 stage、sync、bootstrap、cleanup 与它互斥。
- update.json 新增可选 targetCommit/baseCommit，记录已校验目标和准备时的本地 Commit。只有完整 verify 事务是 pending；clone 中断可在持锁后安全清理并重试。
- 完整 pending 重复 stage 返回同一 revision，不重复下载。下次启动优先离线使用 pending；目标版本或 baseCommit 已变化时安全废弃它，不阻止大版本升级。
- 普通 bootstrap 在同版本且没有 pending 时使用当前仓库，远端检查交给后台轮询；显式 workspace sync 仍检查远端。managed 后端的启动入口也调用 bootstrap，覆盖跳过初始化页的冷启动。
- swap 前把 targetCommit 写入 update transaction；恢复按 Commit 区分同版本的旧、新仓库。目录身份不明时失败关闭，不猜测删除。
- 后台失败保留当前仓库及运行环境。依赖仅在下次启动同步；依赖失败沿用 environment_broken 与修复入口，不承诺对已经修改的共享虚拟环境进行自动回滚。
- 界面仅以成功结果 staged=true 提示就绪，冲突或网络失败不是就绪；后续检查失败保留先前已确认的就绪提示。
- managed 启动先只读查询当前受管版本，再调用 `bootstrap --version <当前版本> --if-needed`；首次无仓库时使用桌面版本。ready 且 revision 未变时跳过 Python/依赖同步，避免每次启动访问包索引；跨版本初始化仍由既有完整 bootstrap 负责。
- bootstrap 持有 mutation 锁时可回收失活的 workspace sync mutation，把 update 现场保留给紧随其后的 workspace 恢复器；下载和切换期间退出均不遗失暂存目录所有权。

## 验收

- 同版本同 Commit 返回 `updateAvailable=false`，不 clone、不 swap。
- 同版本不同 Commit 返回 `updateAvailable=true`；stage 成功后暂存目录和待启用事务跨进程保留，重启后的 bootstrap 复用并执行实际替换。
- 远端不可用返回稳定错误且不改动本地目录、状态和后端进程。
- Electron managed 定时检查能在标题栏显示重启提示，点击重启后走既有初始化链路。
