# T4.8 受管仓库根目录稀疏检出设计

## 1. 目标与边界

`workspace sync` 继续获取目标发布分支的完整 Depth 1 Git 对象，但只把后端运行需要的
仓库根条目检出到受管 `repo/`。首版不落盘 `frontend/` 和根文件或目录 `.debug`，同时保留
M4 已冻结的临时目录、静态校验、目录身份、整体原子替换和中断恢复语义。

本任务不实现 partial clone，不承诺降低网络传输或 `.git/objects` 体积，不改发布分支映射、
mirror 轮换、错误码、协议字段、用户数据目录或开发模式源码目录。

## 2. 集中排除策略

排除清单集中在 `internal/gitrepo/checkout_policy.go` 的 `repositoryCheckoutExclusions` 中。
每项必须是 Git 仓库根目录下的一个精确文件或目录名。首版固定：

```text
frontend
.debug
```

策略采用排除清单而不是后端白名单：目标 Commit 根 tree 中未排除的新条目自动进入检出集合，
避免后端新增根文件后因 Runtime 未同步更新而静默缺失。匹配区分大小写并以完整根条目为单位，
`frontend` 不得误排除 `frontend-tools`。

以下配置无效并在创建真实 Fetcher 时失败：空值、重复项、包含 `/` 或 `\` 的嵌套路径、
绝对路径、`.`、`..`、`.git`，以及 `.python-version`、`pyproject.toml`、`uv.lock`、`main.py`、
`app`、`res` 等后端必需根条目。排除项在目标 tree 中不存在不是错误。

## 3. 获取与检出顺序

单个 mirror attempt 的成功路径固定为：

1. 在已租赁的 `repo.update-<operationId>` 中以 `NoCheckout=true`、`SingleBranch=true`、
   `Depth=1`、`NoTags` 获取目标分支；
2. 读取符号 HEAD 指向的 Commit 和根 tree；
3. 从根 tree 全部条目中删除排除项，为目录生成带 `/` 的前缀，为根文件保留精确名称；
4. 使用 go-git `Worktree.ResetSparsely` 检出剩余条目；
5. 静态校验 remote、HEAD、shallow、Tag、Commit 和 `res/version.json`；
6. 关闭租约后按既有事务整体替换 `repo/`。

go-git v5.19.2 的稀疏接口内部使用前缀匹配。策略构造必须检测“被保留根文件名是排除项前缀”
的歧义并失败关闭，不能让 `front` 意外重新包含被排除的 `frontend`。目录模式追加 `/`，避免
普通同名前缀目录碰撞。

## 4. 失败与取消

策略无效属于构建内配置错误，必须在 reference discovery、临时目录创建和网络访问前拒绝
Fetcher。获取或稀疏检出失败沿用 `GIT_CLONE_FAILED` 和既有 mirror/清理规则；取消、输出故障、
租约关闭失败及清理错误优先级不变。任何失败都不得激活不完整 worktree。

## 5. 测试与验收

- 单元测试固定默认排除清单及全部非法策略；
- Fetcher 测试证明 `NoCheckout=true`，其他 CloneOptions 不回退；
- go-git 真实组件测试同时创建 `frontend/ignored.txt`、根 `.debug`、`app/kept.txt` 和普通根文件，
  证明仅前两项不落盘；
- 组件测试继续证明 Git status clean、符号 HEAD、Depth 1、NoTags、remote、版本和父 Commit
  不可读边界；
- 重复运行 `internal/gitrepo`，执行标准验证门和完整 race detector。
