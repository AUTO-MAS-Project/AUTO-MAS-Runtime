# T4.15 启动后核对源码

仅优化日常托管启动。进入本地复用之前照常验证目录、revision、稳定状态及启动所需输入；不改变 Python、依赖或调度。现有 `StateFiles` 保护一个未完成核对的提交号，无路径清单、计时缓存或第二套修复器。

日常准备先留下标记。后台检查受 backend 锁保护，只读活动源码；干净时按文件身份移除标记。损坏、启动失败或关机早于核对完成时标记保留，下次日常准备在 mutation 锁内走 T4.12 的完整离线恢复，复核或修复成功后才移除旧标记。不同版本绝不使用标记中的提交当作修复源。独立完整 bootstrap 和 `workspace sync` 始终保留同步核对。

监督器拥有后台任务：健康通知和业务放行不等待它，关闭时取消、等待读取退出后才交还 backend 锁。开发模式不核对外部源码。无需 Electron 发送首屏事件，因此 Runtime 以托管后端实际就绪为界，不声称能观察首页。
