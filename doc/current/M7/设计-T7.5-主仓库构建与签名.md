# T7.5 主仓库构建与签名

2026-10-03 用户启动 T7.5，取代 D1/D3 对后续发布不签名的限制。历史 Release 不修改。

## 发布边界

Runtime 的 tag 工作流校验 tag 和源 Commit，触发 AUTO-MAS 的 `build-sign-runtime.yml`
（`workflow_dispatch`，固定 `main`），等待准确请求的签名 artifact，再发布裸
`auto-mas-runtime-<tag>.exe` 与签名后计算的 `SHA256SUMS.txt`。CNB 继续复制 GitHub
已发布且冒烟通过的最终资产。签名失败、超时、身份或校验和不符均阻止发布，无未签名回退。

AUTO-MAS 工作流在 GitHub-hosted Windows runner 上从固定 Runtime 仓库、完整 Commit
构建。要求 tag peeled Commit 等于输入 Commit，且 Commit 已在 Runtime `main` 上；
不接收任意仓库、下载地址或外部 EXE。主仓库按用户要求先推 `dev`，由用户合入 `main`。
`workflow_call` 不改变调用方仓库上下文，因此不能代替主仓库的独立运行。

## 构建、签名与产物

固定 Go 工具链来自 Runtime `go.mod`。保留 Version/Commit/BuildDate/Sentry DSN 注入，
发布测试和 EXE 验证均禁用遥测。仅发布构建使用固定版本 `goversioninfo v1.7.0`
生成 Windows amd64 版本资源（工具通过 Go module checksum 验证，不加入运行时依赖）；
ProductName 为 `AUTO-MAS Runtime`，FileVersion/ProductVersion 字符串为完整 tag，
OriginalFilename 为 `auto-mas-runtime.exe`。数字版本前三段须能放入 Windows 16-bit 字段。

主仓库上传只含稳定文件名 `auto-mas-runtime.exe` 的 artifact，使用现有组织、
`AUTO_MAA` 项目、`release-signing` 策略和专用 artifact configuration；签名等待预算
3600 秒。签名后要求 Authenticode `Valid`、匹配配置的证书 thumbprint，并校验 PE 资源
以及严格 NDJSON version 的 tag/Commit/BuildDate。签名产物 artifact 使用
`runtime-signed-<Runtime run id>-<attempt>` 命名，包含版本化 EXE 和 `signing-manifest.json`。
manifest 绑定请求、Runtime tag/Commit/构建日期、主仓库 run id/attempt 与最终 EXE SHA-256。
manifest 是产物关联信息，信任同时依赖准确主仓库 run、GitHub artifact 和 Authenticode。

Runtime 请求脚本固定主仓库和 workflow，派发前记录主仓库 `main` SHA，按唯一请求名
定位 run；确认 event、branch、workflow path、head SHA、成功结论与 artifact 均匹配。
重复匹配失败关闭。下载只使用准确 run id/artifact id，返回 Runtime 后再次验证上述身份，
签名和哈希。发布 job 再次验签后计算校验和；发布后下载 EXE/校验和再验证，之后才执行 CNB。

## 配置与上线

- Runtime secret `AUTO_MAS_SIGNING_TOKEN`：仅授权 AUTO-MAS，Actions write / Contents read。
- AUTO-MAS secret `SIGNPATH_API_TOKEN`：沿用；新增 `RUNTIME_SENTRY_DSN`，复制 Runtime 的
  `AUTO_MAS_SENTRY_DSN`，仅在 Runtime 构建步骤注入，不修改主仓库自己的 Sentry 配置。
- SignPath 专用配置 slug：用户已配置并确认 `AUTO-MAS_Runtime`。
- 两仓库 variable `RUNTIME_SIGNING_CERTIFICATE_THUMBPRINT`：批准的签名证书 SHA-1 thumbprint。
- SignPath 需要允许主仓库 `main` 构建 Runtime 子项目，配置模板随主仓库提交。
- 无配置时失败关闭；先合入主仓库 main 并配置，再推新 Runtime tag。不自动发测试版本。

## 验收

本地：请求脚本以 httptest 模拟 GitHub API，覆盖成功、异步 run 可见、并发无关请求、
错误来源、签名 run 失败、重复匹配、过期 artifact、超时与凭据净化；真实 Windows EXE
验证资源/NDJSON 和拒绝未签名文件；工作流静态契约、PowerShell AST 与 Runtime 标准门。
远端：用户配置后，以新的不可变版本验证主仓库签名、Runtime 双资产和 CNB 哈希一致；
远端验收未完成前不勾选 T7.5。
