# M7 实施计划

## T7.1 版本注入

- 文件：`internal/version/*`、必要的版本测试/构建说明。
- 红灯：使用测试专用 linker 参数构建时，`Version`、`Commit`、`BuildDate` 仍不是预期值，或
  hello 与 `version` result 不一致。
- 绿灯：保留未注入的 `dev` 占位，测试专用 `-ldflags` 构建验证三个变量，默认版本契约测试继续全绿。
- 验证：`go test -tags integration ./internal/version -run '^TestVersion_LdflagsBinary$' -count=1 -v`，
  并确认输出含 `--- PASS: TestVersion_LdflagsBinary` 且不含 `[no tests to run]`；
  `go test ./internal/version ./internal/cli -run 'TestVersion|TestVersionCommand' -count=100`；
  `go test -race ./internal/version ./internal/cli -count=1`；再跑标准门。

## T7.2/T7.3 发布与冒烟

- 文件：`.github/workflows/release.yml`、发布资产所需 `LICENSE`，以及静态验证说明。
- 红灯：无效/强制 tag 未拒绝、构建未注入 metadata、zip 缺少固定文件、校验和或冒烟校验缺失。
- 绿灯：build → release → smoke 三 job 依赖清晰；权限最小；不签名；smoke 从 Release 下载并解析
  两个命令的 NDJSON。
- 验证：PowerShell 本地复演构建/压缩/解压/命令检查；
  `go test ./internal/release -run '^TestReleaseWorkflow_' -count=100 -v` 并确认无 no-tests；
  `go test -race ./internal/release -count=1`；最后标准门。
