# M6 实施计划：后端进程监督

## 1. 执行规则

每个 Task 独立执行：先写并运行固定测试取得预期红灯，再做最小实现；完成时检查 `git diff`、
`git diff --cached` 和 `git diff --check`，运行本 Task 定向测试、并发相关 `-count=100` 与
race detector，再由两个未参与本 Task 实现的审查者分别给出“规格合规性”和“代码质量”
结论。全部 Critical/Important 修复并复审清零后才提交并进入下一 Task。

每条 `-run` 命令必须退出码 0、输出至少一个 `--- PASS:` 且不得出现
`[no tests to run]`。测试缓存放在临时目录；race 前把已验证的 MinGW-w64 GCC 16.1.0
置于 PATH 首位。固定端口 36163 的夹具/E2E 禁止 `t.Parallel()`，并跨测试进程取得同一个
Windows 命名 Mutex；fixture 自测使用临时端口，不能只用“端口当前空闲”检查规避竞态。

## 2. 执行顺序

```text
设计/计划
  -> T6.6 假后端夹具
  -> T6.1 Job/管道
  -> T6.2 health
  -> T6.3 managed supervise
  -> T6.4 shutdown/restart/control
  -> T6.5 development
  -> T6.7 Windows E2E/CI
  -> M6 文档归档与最终对抗性 CR
```

T6.6 无生产依赖，先交付以供 T6.1/T6.2 使用；T6.3 只在 T6.1、T6.2 分别审查清零后开始。

## 3. T6.6 假后端测试夹具

所有权：`testdata/fakebackend` 及测试构建 helper。用 Go 实现配置驱动的健康/close 服务、
stdout/stderr、进程退出与孙进程，不修改生产包。

固定测试：

- `TestFakeBackend_HealthAndCloseScenarios`
- `TestFakeBackend_StreamsAndGrandchild`

定向门：`go test ./testdata/fakebackend -count=1 -v`。验收必须覆盖延迟监听、
starting/running/ready、failed/backgroundError、协议/版本/Commit 回放、close 拒绝、崩溃、
孙进程和两路日志。

- `TestJob_ConfiguresKillOnCloseAndNoWindow`
- `TestJob_AssignFailureCleansHandles`
- `TestJob_ResumeFailureCleansJob`
- `TestJob_PipeInterleavesStreamsAndFlushesTail`
- `TestJob_PipeReplacesInvalidUTF8AndBoundsEventLine`
- `TestJob_ContextCancellationDrainsAndClosesResources`
- `TestJob_ChildStdinCannotConsumeRuntimeControl`
- `TestJob_QueryConfirmsTreeEmpty`
- `TestJob_UnsupportedPlatformFailsClosed`
- `TestJobE2E_FastChildSpawnIsAlreadyInJob`
- `TestJobE2E_RuntimeTerminationReapsGrandchildren`

定向门：

```text
go test ./internal/process ./internal/uv -run 'Test(Job_|Managed)' -count=100 -v

```

Assign/Resume 失败均无逃逸进程和句柄，真实 AssignProcessToJobObject 成功可查询；Wait 必须
join 两路 EOF/尾行，process/thread/Toolhelp snapshot/pipe/Job handle 全部分支成对关闭，
Terminate/WaitEmpty/Close 顺序可观察。

- `TestHealth_BackgroundFailureIsImmediate`
- `TestHealth_IdentityMismatch`
- `TestHealth_ResetsConsecutiveSuccess`
- `TestHealth_ProcessExitBeforeReady`
- `TestHealth_RequestAndTotalTimeout`
- `TestHealth_DevelopmentOnlyChecksProtocol`
- `TestHealth_BoundsAndClosesResponseBody`
- `TestHealth_LocalCancelTakesPriorityOverBackendCancelled`

定向门：

```text
go test ./internal/health -run 'TestHealth_' -count=100 -v
```

## 9. T6.7 Windows E2E 汇总

所有权：Windows E2E、测试 helper 和 CI glue；仅修复 E2E 暴露的生产缺陷，不新增未设计
能力。Windows 测试默认在 `windows-latest` 的普通 `go test ./...` 中执行；若使用
`integration` build tag，必须同步 CI 显式运行该 tag，禁止静默跳过。

固定测试：

- `TestBackendE2E_LifecycleSpawnReadyShutdown`
- `TestBackendE2E_PreReadyExit`
- `TestBackendE2E_FirstCrashRestartSuccess`
- `TestBackendE2E_SecondCrashTerminates`
- `TestBackendE2E_ForcedShutdownReapsTree`
- `TestBackendE2E_RuntimeTerminationLeavesNoDescendants`
- `TestBackendE2E_DescendantHoldingPipeCannotBlockCleanup`

另运行 T6.1 的两个 `TestJobE2E_*`。每例通过跨进程命名 Mutex 独占 36163，启动前确认端口
未占用，退出后确认
uv/Python/孙进程、backend Mutex、backend.json 和临时文件全部清空。

验收证据同时包含 `windows-latest` CI 和当前项目控制的 Windows x64 环境完整 E2E；若以后
把项目环境注册为 GitHub self-hosted runner，M7 只接线相同命令，不改变 M6 测试语义，也不
在 runner 未配置时增加会永久排队的 workflow job。

## 10. 每 Task 通用验证门

```powershell
$unformatted = & gofmt -l .
if ($LASTEXITCODE -ne 0 -or $unformatted) { $unformatted; throw 'gofmt failed' }
& go vet ./...
if ($LASTEXITCODE -ne 0) { throw 'go vet failed' }
& go build -buildvcs=false ./...
if ($LASTEXITCODE -ne 0) { throw 'go build failed' }
& go test ./... -count=1
if ($LASTEXITCODE -ne 0) { throw 'go test failed' }
& git diff --check
if ($LASTEXITCODE -ne 0) { throw 'git diff --check failed' }
```

并发相关 Task 再运行 `go test -race ./... -count=1` 并检查 `$LASTEXITCODE`。golangci-lint 使用只检查本 Task 新增
问题的增量模式；仓库基线 148 条既存问题单独记录，不在 M6 中做无关批量重构。

静态审计：所有 stdout/Print/json encoder 所有权、直接 Python/pip/taskkill/Shell/runas、
`localhost`/`--port`、未授权 `exec.Command`、开发目录写入和不受控 `time.Sleep`。

## 11. 提交与最终收口

建议提交边界：M6 设计计划、T6.6、T6.1、T6.2、T6.3、T6.4、T6.5、T6.7、文档归档/
最终修复。提交前只暂存当前 Task 范围并复核 staged diff。全部代码完成后启用第四名独立
LunaMAX 审查者执行详细对抗性 CR；修复全部 Critical/Important 后由原审查者复审，最终
回写 `doc/任务拆分.md` 的 M6/T6.1～T6.7 证据并把设计归档、删除已执行计划。
