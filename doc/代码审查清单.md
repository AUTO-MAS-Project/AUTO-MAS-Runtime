# AUTO-MAS Runtime 代码审查清单

本清单补充自动化门禁无法完整表达的架构边界。每个任务仍需满足
[任务拆分](./任务拆分.md) 中自己的验收项。

## NDJSON 与 stdout 所有权

- [ ] 只有 `cmd/auto-mas-runtime` 进程入口可以持有 `os.Stdout`；`internal`
      业务包不得导入或保存它。
- [ ] 参数解析成功且 `--output ndjson` 时，进程入口只用 stdout 创建一个
      `protocol.ProcessOutput`，再从中创建唯一的 `protocol.Emitter`；
      `ProcessOutput` 拒绝第二个 emitter。业务包只接收类型化事件出口，
      不接收 stdout writer。
- [ ] `hello/progress/state/log/warning/error/result` 全部经同一个
      `protocol.Emitter` 发射，不直接调用 `fmt.Print*`、`log.Print*` 或
      `json.Encoder` 写 stdout。
- [ ] Runtime 自身诊断写 stderr；受管进程 stdout/stderr 转换为 `log`
      事件并写轮转日志。
- [ ] 新增输出路径时执行以下 PowerShell 7 检查，并逐项审查命中结果：

```powershell
rg -n 'os\.Stdout|fmt\.F?[Pp]rint|log\.[Pp]rint|json\.NewEncoder' --glob '*.go' .
if ($LASTEXITCODE -gt 1) { throw "stdout ownership scan failed" }
```

- [ ] `ProcessOutput` 仍保证首事件为 `hello`、进程内唯一序列从 1 递增、
      每行一个 JSON、每行刷新，并在并发调用时保持完整事件边界。

## 冻结全集与容器字段

- [ ] `code`、`stage`、`remediation`、`progress.status`、`state.status` 和
      `hello.capabilities` 的取值全部来自 `internal/protocol` 的冻结全集，
      没有就地编造字符串。需要新值时先追加到架构文档与 `errors.go` /
      `values.go`，再使用。（`result.status` 按 T1.3 设计不是枚举，不受此限。）
- [ ] 构造 error/warning 优先用 `protocol.NewErrorEvent` / `NewWarningEvent`，
      构造 result 优先用 `NewSuccessResult` / `NewFailureResult`，
      让四元组直接取自冻结表而不是手写。
- [ ] `details`、`remediation`、`capabilities` 恒为 `{}` / `[]`，
      **wire 上不得出现 `null`**；新增事件字段若是容器类型，
      必须一并加入 `normalize()`。
- [ ] 新命令的契约测试以一行 `contracttest.Register` 接入，
      未因命令特殊性绕过或削弱契约断言。

## 遥测与错误观测

- [ ] 只有 `internal/telemetry` 的 Sentry adapter 直接导入 `sentry-go`；已取消的 Umami/PostHog
      provider 不得出现在当前实现；业务包、`internal/protocol` 和 `internal/logging` 不依赖实现。
      执行以下 PowerShell 7 扫描并逐项审查：

```powershell
rg -n 'sentry-go|umami|posthog' --glob '*.go' .
if ($LASTEXITCODE -gt 1) { throw "telemetry dependency scan failed" }
```

- [ ] `--offline` 或 `AUTO_MAS_TELEMETRY=disabled` 在创建 Sentry client、transport、
      goroutine 或 timer 前短路；DSN 缺失时 provider 为 no-op。测试以计数 transport 证明
      没有 DNS、代理探测或 HTTP 请求。
- [ ] Sentry 只接收 `INTERNAL_ERROR` 与未预期 panic；固定
      `SendDefaultPII=false`、`EnableTracing=false`、`DisableLogs=true`，其他协议/
      业务错误被 `BeforeSend` 拒绝。
- [ ] Sentry `BeforeSend` 从白名单重建事件并清空 user、request、server name、
      breadcrumbs、extra、非白名单 contexts、原始 error/panic 文本、栈帧路径、局部变量
      和源码上下文；只保留固定错误类别、severity、release/environment、允许标签与
      函数/模块/行号。
- [ ] provider 初始化、capture、flush、close、队列满、超时或网络失败均不产生协议事件、
      不写 stdout/stderr、不改状态、退出码、retryable 或 remediation；`result` 仍是 stdout
      最后一事件。
- [ ] flush 只在业务终态确定后执行，总等待上限 500 ms；不落盘缓存、不跨命令重试、
      不遗留 goroutine。并发和超时测试使用 barrier/channel，不用 `time.Sleep`。
- [ ] Sentry DSN 只来自集中配置/构建注入，源码、日志、协议和发布说明不含凭据；Runtime
      不读取 Sentry auth token。切换到本地测试 endpoint 只改 DSN/transport 配置，不改业务代码
      或事件 schema；Umami 配置不再属于当前契约。
- [ ] 单元/组件测试只使用 fake transport 或本地测试服务；默认测试、发布 smoke 和
      `--offline` 验证不访问真实 Sentry，也不污染生产项目。
