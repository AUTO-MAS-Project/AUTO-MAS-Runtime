# T1.8 中文注释与可维护性审查设计

## 1. 目标

T1.8 在不改变 Runtime 行为和协议契约的前提下完成两件事：

1. 将仓库现有 Go 注释迁移为中文，并为缺少说明的关键声明、不变量和测试夹具补充必要注释；
2. 对 M1 全部 Go 实现做一次对抗性审查，重点判断代码是否易于维护、职责是否清晰、逻辑是否容易验证。

本任务响应用户在 2026-07-29 提出的专项要求。它独立于 T1.7 的契约收口，不用注释迁移掩盖逻辑改动。

## 2. 范围

### 2.1 包含

- `cmd/auto-mas-runtime` 与全部 `internal/*` Go 源码；
- `internal/protocol` 及 `contracttest` 的测试代码；
- 当前工作树中尚未提交但属于 T1.7 的 Go 文件；
- 导出声明、包注释、并发约束、协议不变量、非显然分支和复杂测试夹具；
- 一份带严重程度、文件行号、影响与建议修法的审查报告。

### 2.2 不包含

- 修改标识符、JSON 字段、错误字符串、测试名或协议文案；
- 为简单赋值、直接转发、表驱动用例逐行写复述性注释；
- 仅为减少文件长度而拆包或重构；
- 在本任务中修复审查发现的业务逻辑问题；
- 改写权威协议、错误码、stage、state 或生命周期迁移。

审查发现若需要代码修复，必须进入对应任务执行 TDD；不能混入注释提交。

## 3. 注释原则

### 3.1 语言与格式

- 注释使用中文，英文标识符、协议字面量和行业缩写按原样保留；
- 导出声明的 doc comment 以被注释的英文标识符开头；
- 同一声明内不混排中英文自然语言；
- 注释说明“为什么、有什么约束、错误会造成什么”，不逐句翻译实现。

### 3.2 必须保留或补充的内容

- 包职责及与相邻包的边界；
- stdout 单一所有权、首尾事件、序列化临界区和 warning 账本等协议不变量；
- 锁保护范围、一次性调用、回调重入限制和停止语义等并发约束；
- 防御性副本、规范化时机、失败关闭和输入上限；
- 测试中用于证明并发、文档驱动契约或恶意输入边界的非显然夹具。

### 3.3 应删除或避免的内容

- 仅复述函数名或下一行代码的注释；
- 与实现不一致、已经过期或只描述历史过程的注释；
- 把测试断言改写成自然语言的长篇说明；
- 使用“显然”“简单地”等不能提供约束信息的措辞。

## 4. 文件组织

注释迁移按职责分组：

1. 入口与占位包：`cmd/auto-mas-runtime`、`internal/cli`、各包 `doc.go`；
2. 协议生产代码：事件、错误、值集、renderer、emitter、生命周期与 stdin 控制；
3. 契约库与测试：只在复杂夹具和非显然证明点增加说明。

不为本任务拆分生产文件。若审查认为文件职责过重，记录为发现并给出后续任务建议。

## 5. 对抗性审查方法

审查从三个互相独立的视角进行：

1. **生产代码视角**：职责边界、状态与并发不变量、错误传播、可扩展点和命名；
2. **测试视角**：测试是否验证真实行为、重复夹具是否掩盖意图、是否存在脆弱的文档解析或时间依赖；
3. **文档一致性视角**：实现是否偏离 T1.x 设计、计划和代码审查清单。

每条有效发现必须包含：

- `Critical`、`Important` 或 `Minor` 严重程度；
- 精确文件与行号；
- 可复现证据或明确的控制流说明；
- 对维护性、逻辑清晰度或正确性的影响；
- 可执行的修复建议。

没有证据的风格偏好不列为问题。

## 6. 基线与失败归属

任务开始时必须先运行标准验证门。若当前工作树已有失败：

- 记录失败命令、测试名和原因；
- 注释迁移后重跑同一验证门；
- 只有新增失败才归因于 T1.8；
- 既有失败仍会阻止 T1.8 按仓库 DoD 标记完成。

失败：T1.7 新增的 capability 全集校验先于 renderer 清洗测试生效。该问题属于审查基线，
不在注释迁移中修复。

## 7. 验收

1. 全部 Go 文件经过人工检查，现有英文自然语言注释已迁移为中文；
2. 导出声明均有符合项目格式的必要中文 doc comment；
3. 复杂并发、协议不变量和测试夹具有足够说明，简单代码无复述性注释；
4. `gofmt -l .` 无输出，`go vet ./...`、`go build -buildvcs=false ./...` 通过；
5. `go test ./... -count=1` 相比记录的基线无新增失败；
6. 对抗性审查报告落盘，所有发现有严重程度、定位、影响和修复建议；
7. `git diff --check` 通过，注释迁移未夹带业务逻辑改动。
