# T2.11 非 NTFS 状态删除降级

## 问题与边界

Issue #9：exFAT/FAT32 不支持 `FILE_DISPOSITION_POSIX_SEMANTICS` 时，
`WriteAtomic` 在状态写入前失败，初始化无法继续。T2.5 原方案只允许 POSIX
删除。本任务修订该约束，保持原有 guard、固定身份、sealed intent、no-replace
rename 与恢复矩阵；不改变状态文件布局或协议事件字段。

## 删除策略

每个 `StateFiles` 实例首次写入仍在独占 guard 内建立随机 probe。先尝试 POSIX
删除；仅当 disposition 自身明确返回 `ERROR_INVALID_PARAMETER`、
`ERROR_NOT_SUPPORTED` 或 `ERROR_INVALID_FUNCTION`，才在同一 probe 上尝试传统
删除。传统删除的 `U` 相对固定 parent 打开并复验与锚点 `A` 的 file ID；设置
disposition 后依次关闭 `A`、`U`，再从固定 parent 证明名称不存在。若扩展传统
flags 不支持，允许 legacy `FileDispositionInfo`。任一步不明确即失败关闭，
不按路径重试删除。

传统 Windows 删除在其他读者持有句柄时可能延迟，故这类占用返回恢复错误。
进程崩溃时系统关闭 `A/U`；下次仍由 sealed intent 和现有恢复矩阵决策。
保留对象身份或名称不明时不猜测、不清理。doctor 只读检测 FAT/exFAT 卷并
给出降级风险及迁移 NTFS 的建议；文件系统名称是提示，不代替实际能力 probe。
状态写入失败时本地操作日志记录底层 cause；日志器尚未建立时写 stderr。
NDJSON error 仍只携带稳定字段。

## 验证

注入 POSIX 不支持并用真实 Windows 句柄完成首次写、替换和按快照删除；
保留其他 probe 故障、旧 POSIX 精确 flags、状态恢复和 crash 测试。
当前机器未提供 exFAT/FAT32 测试卷，真卷端到端验收仍需补充。
