## 问题与范围

最新 `main` 的远端 CI 依次通过 formatting、vet 和 build，只在 `go test ./...` 失败。
失败集中为三类同源边界：

1. hosted runner 的 `TEMP` 使用 8.3 短路径；`DirectoryLease.Path()` 已返回规范长路径，
   测试却与原始路径比较，失败后还让租约句柄存活到 `TempDir` 清理；取消测试也因相同比较
   没有触发注入。
2. rename pin 失败中的 `FileError.Path` 来自规范路径，重试分类却与请求原始路径做词法比较；
   短路径、扩展路径等价表达因此绕过有限重试和 `DIRECTORY_OCCUPIED` 映射。
3. `InspectManagedDirectory` 先规范化和判断目录类型，随后才验证路径链；Windows 可以在处理
   祖先 Reparse Point 时先跟随到目标，悬空链接也可能先按非目录误报，违反 T2.5 的失败关闭顺序。

本任务只修改 `internal/filesystem` 及其测试，并验证被连带影响的 `internal/gitrepo` 组件用例。
不修改协议字段、错误码、目录布局、Git 更新流程、CI workflow 或 M6 后端行为。

## 冻结修复

### 规范路径测试边界

`DirectoryLease.Path()` 的既有语义明确为租约固定对象的规范 display 路径。测试必须先用
`Canonicalize` 计算期望值；租约创建成功后立即注册 cleanup，使后续任何断言失败都不会把
句柄泄漏伪装成 `TempDir` 清理错误。注入钩子同样只比较两侧规范路径。

### rename pin 占用分类

只有 `pinRenameAttempt` 已经完成 source 授权和规范化后，才有资格判断 source 叶子的
`open-relative` 共享/锁/access-denied 是否为可重试占用。该判断结果以私有错误标记向
`AtomicRename` 传播；外层不再重新拿原始请求路径匹配。标记必须保留原错误链，close、授权、
父目录或身份错误不得被误标记。每次重试仍重新固定并复验全部身份。

### raw Reparse 链优先级

`InspectManagedDirectory` 在调用 `Canonicalize`、读取最终类型或执行 managed-root 授权前，
先对清理后的原始绝对路径逐级向卷根执行只读检查：

- 属性明确带 `FILE_ATTRIBUTE_REPARSE_POINT` 时立即返回 `UNSAFE_REPARSE_POINT`；
- 属性报 not-found 时，用 `OPEN_REPARSE_POINT` 分别按目录/非目录探测原始对象，以识别悬空链接；
- 普通既有组件继续检查父级，不因叶子普通就提前结束；
- 非 not-found I/O、identity 或 close 错误保留原错误链并失败关闭；
- 全过程不创建、删除、重命名或跟随链接执行后续授权。

这样 raw 路径中的 Junction/符号链接不会因最终路径规范化而消失，8.3 与扩展路径等价表达仍由
后续 `CanonicalPath` 负责身份统一。

## 验证结果

- 新增 raw Reparse 与等价路径 rename 测试在修复前得到预期失败，修复后转绿。
- 相关 filesystem 测试 `-count=100`、gitrepo 目录占用组件短路径 `TEMP` `-count=10` 通过。
- 真实 8.3 `TEMP/TMP` 下 `go test ./... -count=1` 与默认环境标准验证门通过。
- MSYS2 GCC 16.1.0 沙箱外 `go test -race ./... -count=1` 通过。

  用例固定相同检查顺序。未获 push 授权，因此远端 Actions 尚未在修复提交上复跑。
