# T2.15 日志容量分卷

## 目标与边界

日志达到单文件 128 MiB 不应阻断后端运行或同日重启。保留现有容量检查，logging 只对零字节写入的 ErrRuntimeLogCapacity 自动分卷；真正 I/O、路径安全、关闭故障保持原错误链。不修改后端日志级别、NDJSON 或消费方版本钉扎。

## 设计

- config 统一生成首卷及 `.001.log` 起的数字分卷路径；旧文件名兼容。
- filesystem 提供显式序号的追加与 create-new 能力，复用固定祖先句柄、单硬链接和 Reparse 检查，禁止覆盖和按路径重命名。
- logging 生产适配器列举安全令牌，启动/跨日打开同命令同日最大序号；创建下一卷遭遇名称竞争时重新列举，最多重试 16 次。
- Logger 的 mutex 覆盖追加、分卷、关闭和保留。容量拒写且本次尚未写入时创建新卷并重试完整编码行；超过单文件上限的单条记录直接拒绝，防止无限空卷。
- 初始化、保留清理记录和普通记录共用容量追加入口。成功切换后 LogPath 指向最新卷，WriteResult.Rotated 反映容量轮转。先打开新卷再关闭旧卷，已生效的切换和写入在错误结果中保留。
- 所有卷按日期、数字序号排序，最多保留 30 日且每命令 30 文件。维护记录自身触发分卷时再执行一次维护，避免构造器留下正常可删除的超额旧卷。正在写入的文件由现有 token 删除和 Windows share 约束保护。
- 创建竞争有界；日期/容量轮转不递归触发维护，避免写入失败循环。取消前无副作用，已提交追加继续沿现有 WithoutCancel 语义收口。

## 验收

以真实 Windows 日志文件在临时目录触发边界，配合注入式错误/竞争证明。现场机器升级后的复验单独记录，不以本机测试代替。
