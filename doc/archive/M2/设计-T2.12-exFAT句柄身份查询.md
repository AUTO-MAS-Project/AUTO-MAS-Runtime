# T2.12 exFAT 句柄身份查询兼容

现场：用户 F 盘确认为 exFAT，Runtime 在固定 `F:\auto_mas` 祖先时，
`FileIdInfo` 返回参数不正确；尚未进入 T2.11 的状态删除探测。

以同句柄卷查询限定兼容范围，只有明确 unsupported + exFAT 才读旧版身份。
保留 basic/standard 元数据，核对旧版属性、link count、size，拒绝零索引。
低 64 位使用 little endian 编码，高 64 位清零；内部及持久 intent 结构不变。
权限、无效句柄、其他卷或矛盾元数据均保留原始错误链并停止操作。
不引入全局能力缓存，不按路径猜测卷，不截断 NTFS/ReFS 的 128 位身份。

exFAT 大小写查询若明确 unsupported，只在卷能力不支持大小写敏感时返回 false；
支持或不确定时停止操作。现有普通目录、祖先 pin、Reparse 和 hardlink 检查保留。
FAT/FAT32 文件索引可能因长名称 rename 改变，此次不扩展其身份兼容。

测试以依赖注入模拟 exFAT API 结果，并在真实 Windows 句柄上验证状态能力。
额外提供可选真实 exFAT 临时根验收，覆盖重新打开、长名称 rename 后身份和状态生命周期。
本机当前 C/D 仅 NTFS 且未提升权限，不格式化现有卷；真实 exFAT 测试缺口明确保留。

参考：[旧版身份及 FAT/ReFS 限制](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/ns-fileapi-by_handle_file_information)、
[同句柄卷能力](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-getvolumeinformationbyhandlew)。

## 实施与验证记录

实现提交：`e84f9c5`。新增三个主测试先在基线得到正确红灯：

修复后成功。非 exFAT、权限/句柄错误、零索引和元数据冲突均保留错误链并拒绝身份。
真实 Windows 句柄注入兼容分支，覆盖重开、长名称 rename 和不同对象，
四类状态覆盖首次写、替换、关闭重开和事务快照条件删除；旧快照拒绝删除新内容。
提交后复核了同句柄卷查询、ReFS 不截断、恢复 proof 表示和既有路径/链接校验入口。

本次最终验证全部退出码 0：gofmt、`go vet ./...`、
`go build -buildvcs=false ./...`、`go test -p 1 ./... -count=1`、
`go test -race -p 1 ./... -count=1`、`git diff --check`。
四个兼容/真实句柄/状态生命周期测试定向 100 次，protocol 100 次通过。
并行全仓首轮的 lock Junction 子进程超时，经原样定向重跑和完整串行重跑通过；

```powershell
& go test -v ./internal/filesystem -run '^TestIdentityWindows_ExFATVolumeLifecycle$' -count=1
if ($LASTEXITCODE -ne 0) { throw 'exFAT volume validation failed' }
```
