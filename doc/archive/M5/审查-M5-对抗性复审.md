## 复审重点与修复

1. 生命周期状态由 `protocol.LifecycleMachine` 校验；bootstrap、environment、dependencies 和 repair
   均覆盖准备、失败、回滚和 ready 的合法迁移。
2. `mutation.json` 在取得 mutation 租约后按 PID/Mutex 事实恢复；活动或无法分类的事务失败关闭，只有陈旧事务条件删除。
3. UV、Python 和依赖失败保留 active revision 时原子写 `environment_broken`；无 active revision 时回滚到原稳定态；状态写失败优先返回 `STATE_WRITE_FAILED`。
4. 非 Windows 在 UV 下载、删除或启动前直接返回 `UNSUPPORTED_MODE`，不会降级为无进程树监督执行；Windows Job Object 的
   `CREATE_SUSPENDED -> Assign -> Resume` 启动竞态，以及文件身份锚定，明确留给 M6/filesystem 专项。
5. stdin 控制读取在取消后执行有界 join；UV 行回调同步执行并可取消；过长未终止输出和不合规 HTTP transport 均有界收口测试。
6. `requires-python` 覆盖 TOML 表/键形式、字符串、注释、多行字符串和重复键拒绝，不依赖第三方网络或系统 Python。
