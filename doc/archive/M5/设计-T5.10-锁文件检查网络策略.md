# T5.10 锁文件检查网络策略回归修复设计

> 2026-08-17 修订：真实 uv 0.12.3 证明 `--default-index` 会改变 lock check 与 locked sync
> 的锁定输入。本设计中“在线检查选择 package-index 源”的结论已由 T5.11 取代；最终边界见
> [`设计-T5.11-锁文件-sources-语义.md`](./设计-T5.11-锁文件-sources-语义.md)。

## 1. 背景与根因

`bootstrap --version` 在未传 `--offline` 时会把在线 `MirrorPolicy` 传给依赖同步，
但 `DependenciesService.Sync` 的前置 `checkLockfile` 无条件通过 `withOfflineUV` 注入
`UV_OFFLINE=1`。当本地 uv 缓存不足时，正常在线 bootstrap 会在 `uv lock --check`
阶段提前失败，无法进入后续支持镜像轮换的 `uv sync --locked`。

权威架构规定只有显式 `--offline` 才禁止网络。原实现把“只读检查”错误地收窄成了
“离线检查”，二者不是同一约束。

## 2. 范围与边界

本任务只修改 `internal/uv` 的锁文件检查策略及对应测试：

- 默认在线策略从 package-index 计划选择首个源，以 `--default-index` 传给
  `uv lock --check`，不注入 `UV_OFFLINE`；
- 显式首选 package-index 时使用该首选源；
- 显式离线时不构造网络源，只注入 `UV_OFFLINE=1`；
- `uv lock --check` 仍为只读检查，不允许修改 `uv.lock`；
- 锁文件缺失、过期、取消和底层执行失败继续使用现有错误映射；
- 后续 `uv sync --locked` 的有界重试与完整镜像轮换保持不变。

本任务未修改 CLI 参数、NDJSON 字段、错误码、stage、退出码、retryable、remediation，
未改 uv 固定版本，也未触碰 M6 以后业务逻辑。

## 3. 失败语义

锁文件检查没有直接复用把普通 uv 执行失败统一视为网络失败的轮换执行路径，否则
锁文件过期可能被误报为 `MIRROR_EXHAUSTED`。检查阶段只冻结本次策略的首个包索引源；
检查成功后，真正下载依赖的 `uv sync --locked` 继续执行完整源轮换。

离线检查失败仍按既有锁文件检查语义处理；本任务只纠正网络许可和参数选择，不扩大
错误契约。

## 4. TDD 与验收结果

`TestDependencies_LockfileCheckFollowsMirrorPolicy` 的红灯准确证明默认在线和显式首选
均缺少 `--default-index`，同时离线子用例已通过。最小实现后：

1. 默认在线检查使用 Aliyun package-index，且无 `UV_OFFLINE`；
2. 显式首选检查使用 Tsinghua package-index，且无 `UV_OFFLINE`；
3. 显式离线检查携带 `UV_OFFLINE=1`，且无 `--default-index`；
4. 既有锁文件缺失、目录和过期用例继续通过，过期仍映射 `LOCKFILE_OUTDATED`。

最终验收：依赖测试 20 轮、协议包 100 轮、全仓 gofmt/vet/build/test/diff-check
全部退出码 0；受管沙箱内 race 命中已知 cgo 环境错误后，按仓库规定在沙箱外提升
GCC 路径并重跑 `go test -race ./... -count=1`，全部包退出码 0。stdout 所有权扫描未发现
新增生产输出路径。
