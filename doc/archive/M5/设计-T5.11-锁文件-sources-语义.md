# T5.11 锁文件 sources 语义回归修复设计

## 1. 真实黑盒证据

基于当前源码 `f6ffdcb` 新构建的 beta.6 EXE 在 `D:\runtime-blackbox-test` 对
`release/v9.9.9-alpha.1` 执行 bootstrap，稳定返回 `LOCKFILE_OUTDATED`、exit 20。

测试分支远端锁本身存在一处真实过期：`pyproject.toml` 为 `9.9.9-alpha.1`，但
`uv.lock` 根项目版本仍为 `5.4.0b7`。临时 `uv lock` 只把该值更新为规范化的
`9.9.9a1`。

在使用这份修正锁后，真实 uv 0.12.3 的结果为：

- `uv lock --check --default-index <mirror>`：exit 1；
- `uv lock --check`：exit 0；
- `UV_OFFLINE=1 uv lock --check`：exit 0。

三次检查前后锁文件 SHA-256 一致。证据证明 T5.10 注入索引 URL 会改变锁定输入，
使有效锁被错误判定为过期。

T5.11 第一轮实现移除 lock check 的覆盖后，新 EXE 已越过 `dependencies.check`，但后续
`uv sync --locked --default-index <mirror>` 对所有内置源都返回同一“锁文件需要更新”错误，
最终被误报为 `MIRROR_EXHAUSTED`。这证明覆盖 package-index 与 locked sync 本身也不兼容，
不是某个镜像临时不可用。

## 2. 冻结边界

- `uv lock --check` 是发布锁一致性检查，必须使用锁文件及项目声明的 sources；
- 在线模式不注入 `UV_OFFLINE`，也不传 `--default-index`；
- 显式离线只注入 `UV_OFFLINE=1`，不构造 package-index 源；
- `uv sync --locked` 同样不传 `--default-index`，只消费锁文件记录的精确 artifact URL；
- 显式 package-index 首选返回 `INVALID_ARGUMENT`，不得静默忽略；
- 主项目依赖不参与 Runtime package-index 轮换；离线缓存不足仍为 `NETWORK_UNAVAILABLE`，
  其他同步失败为 `DEPENDENCY_SYNC_FAILED`，不得把锁语义冲突误报为 `MIRROR_EXHAUSTED`；
- 不解析 uv 自然语言输出，不修改锁文件，不改变 `LOCKFILE_OUTDATED`、stage、退出码、
  retryable 或 remediation；
- 远端测试分支缺失的锁文件版本更新属于 AUTO-MAS 发布输入问题，不在 Runtime 中绕过。

## 3. 验收

新增/调整表驱动回归测试，固定默认在线、显式首选和显式离线三种 check/sync 参数、环境
与错误映射。完成定向红绿灯、依赖测试重复、协议 100 轮、全仓标准门、完整 race 和新 EXE
黑盒。黑盒使用本地修正锁验证依赖同步，不伪装为远端测试分支已修复。

## 4. 最终结果

- 红灯 1：默认在线与显式首选的 lock check 因多出的 `--default-index` 失败，离线控制组通过；
- 绿灯 1：lock check 在线沿用 sources，离线只注入 `UV_OFFLINE=1`；
- 红灯 2：默认在线 locked sync 仍携带 `--default-index`，显式覆盖未拒绝，普通失败被镜像
  轮换掩盖；
- 绿灯 2：在线 `uv sync --locked` 沿用锁定 sources，显式 package-index 覆盖返回
  `INVALID_ARGUMENT`，普通/离线失败分别稳定映射 `DEPENDENCY_SYNC_FAILED` /
  `NETWORK_UNAVAILABLE`；
- 依赖测试 20 轮、协议 100 轮、全仓 gofmt/vet/build/test/diff-check 与沙箱外完整 race
  均退出码 0；
- 最终 EXE：版本 `v0.1.0-beta.6-t5.11-final`，源码提交 `ae46046`，SHA-256
  `3E8CBD86FDF3D26D342C629FCA1C66981583F82560BEF522B9073F69A2DE30F5`；
- 黑盒：修正锁 SHA-256
  `44C5528E8AB8FB8AB40EFB24E43505621B630D6339CBCF1E6C9AC9571FC9A6B1`，首次真实同步下载并
  构建 98 个锁定包后 `ready_to_start`/exit 0，二次同步幂等 exit 0，前后锁哈希不变；
- 远端 `release/v9.9.9-alpha.1` 仍为提交 `130f1840`，其锁根项目版本仍是旧值；本次未 push，
  因此不能把本地依赖同步成功表述成远端 bootstrap 已修复。

uv 官方语义依据：`--locked` 要求锁文件保持不变且最新，`--frozen` 会跳过最新性检查；本任务
继续使用 `--locked`，不以 `--frozen` 绕过 sources 冲突：
<https://docs.astral.sh/uv/reference/cli/#uv-sync>。
