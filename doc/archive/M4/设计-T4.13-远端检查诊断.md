# T4.13 远端检查阶段与失败诊断

日期：2026-10-22。来源：Issue #27，Runtime v0.1.27 的远端更新检查失败记录。

状态：已完成，代码提交 `f8efc95`；本地验收通过，未推送、未发版。

## 原因与范围

`resolveRemoteWithClient` 在 attempt 内构造 `workspace.check` 错误，最终却调用默认用于克隆的
`mapFetchFailure`，丢失命令阶段。所有引用查询错误都归为 `resolve_failed`，已有 Rotator
耗时也没有写入 `attempts`。本任务修复诊断链，不推断当事机器的真实故障。

## 实现边界

- 保留镜像轮换与错误优先级；远端调用在汇总边界恢复 `workspace.check`，含取消与离线。
- 使用 `errors.Is/As` 及 go-git 已知包装类型读取底层错误。DNS、TCP、超时、TLS、可识别的
  `net.OpError.Op=proxyconnect`、HTTP 固定错误与状态分别映射到架构登记的固定 token。
  不解析错误字符串；go-git 没有 `Unwrap` 的包装显式读取 `Err`，有界递归以防异常错误链。
- 每次回调收集可确认的 HTTP 状态，按实际尝试顺序合入 Rotator 报告。耗时直接复用
  `AttemptReport.Duration`，不另起时钟。测试通过 Rotator 时钟注入证明精确耗时。
- `httpStatus` 只接受 100~599 的整数并通过 Sentry 二次净化。原始错误仅保留在本机错误链，
  协议 message/details 与遥测不携带 URL、地址、正文、凭据或自由文本。
- 不改 clone 的阶段、错误优先级、总网络预算、来源顺序、锁、状态或目录；无新依赖。

## 验证

表驱动故障测试先红后绿；失败结果保留每源诊断、混合失败仍保留原主错误；成功回退仍成功。
本地 TLS 服务通过真实 go-git 验证 401/403/404/407/503 与不受信任证书的实际错误形态。
CLI 契约验证 error/result 阶段和详情一致，Sentry 净化后仍保留有效字段；未知诊断和敏感
内容被剔除。补充取消、离线与分支缺失，运行标准门与定向重复测试。

## 本地验收记录

- 原有失败测试先红后绿：远端失败阶段、失败类别、耗时与 HTTP 状态在旧实现中缺失；
  精确计时测试先确认缺少 Rotator 时钟注入接缝，再以内部可选依赖完成实现。
- `TestRemoteResolve_FailureDiagnostics` 覆盖 DNS、连接、读超时、证书、TLS、可识别代理、
  HTTP、空仓库、未知错误与自然语言不参与分类；本地真实 go-git/TLS 服务验证
  401/403/404/407/503 和证书不受信任。不访问真实公网或生产 Sentry。
- `TestRemoteResolve_AttemptDurations` 以注入时钟精确证明逐源 125/250 ms；
  `TestRemoteResolve_MixedFailures` 交换失败顺序，证明主错误优先级及逐源状态仍正确。
- `TestWorkspaceRemote_FailureDiagnostics` 核对 NDJSON error/result 的阶段、错误码、
  retryable、remediation 与详情一致，并核对 CLI 交给观测层的完整诊断；
  `TestSentry_RemoteFailureDiagnostics` 证明 SDK transport 最终收到安全事实，敏感字段被丢弃。
- Go 1.26.10、`gofmt -l .`、`go vet ./...`、`go build -buildvcs=false ./...`、
  `go test -p 1 ./... -count=1` 和 `git diff --check` 全部退出 0。
  完整测试串行运行包，减少既有 Windows Job/子进程夹具的时序干扰。
- 以下定向测试命令退出 0，各用例重复 100 次，输出包含 PASS，且无 `[no tests to run]`：

```powershell
$env:GOCACHE = Join-Path $env:TEMP 'auto-mas-runtime-verify'
$output = & go test ./internal/gitrepo ./internal/telemetry ./internal/cli -run 'TestRemoteResolve_|TestSanitizeDiagnostics_HTTPStatus|TestAttemptDetails_|TestWorkspaceRemote|TestSentry_RemoteFailureDiagnostics' -v -count=100 2>&1
$testCode = $LASTEXITCODE
$output
if ($testCode -ne 0 -or "$output" -match '\[no tests to run\]' -or "$output" -notmatch '--- PASS:') { throw 'targeted tests failed' }
```

提交后按代码审查清单复核：没有新增 stdout 路径、生产业务包没有依赖遥测实现；Rotator
回调顺序与报告顺序一致，HTTP 状态按实际 attempt 对齐；错误码优先级、45 秒总预算、换源、
只读边界和克隆阶段保持既有语义。没有修改并发策略，本任务未追加 race 验收。

现场网络根因仍未确认。`proxy_failed` 仅用于可读取的结构化 `proxyconnect`；不可识别的
代理/协议错误仍为 `resolve_failed`，不会解析错误文本补猜状态。本地 HTTP 407 组件用例是
远端响应状态验证，不代表所有 CONNECT 代理握手错误都能取回状态码。
