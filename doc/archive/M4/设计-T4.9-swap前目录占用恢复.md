# T4.9 swap 前目录占用后的确定性恢复设计

## 1. 问题与目标

`Swapper.Swap` 在第一次 rename 前持久化 `workspace.swap` transaction。若旧 `repo/` 的 Git
身份无效，但目录叶子身份可由 Recovery 重新固定，第一次 rename 又因目录占用明确返回
`MutationApplied=false`，同步会保留完整 update 和 transaction。下一次 Recovery 当前只允许
在 clone/verify 阶段把损坏 repo 分类为 incomplete，因此先返回 `repository_unknown`，无法进入
本来可以确定回滚的 swap 前目录形状。

本任务让该现场恢复到干净的 swap 前状态：保留旧 repo，删除已验证 update，条件删除 update
transaction，使调用方下一次重试能够重新同步。

## 2. 安全边界

Recovery 只在 transaction stage 为 `workspace.swap` 时允许普通 Git 读取或身份校验失败的 repo
成为 incomplete。目录仍必须通过受管路径检查、固定句柄 pin 和 volume/file-ID token 复验；权限
错误、Reparse、取消或 token 变化不降级为 incomplete。

只有以下目录形状可执行回滚清理：

- repo 为 valid 或 incomplete；
- update 为 transaction 记录的目标 version/Commit；
- previous 缺失。

动作只删除带已固定 token 的 update 并条件删除 transaction，不移动或删除 repo。其他包含
incomplete 的形状继续返回 `UPDATE_STATE_AMBIGUOUS`，不执行目录副作用。

## 3. 非目标

本任务不识别最初占用进程，不改变 Windows rename 重试次数，不放宽受信 remote，不改变两步
rename、错误码、协议、环境状态或用户数据边界，也不处理提交点之后损坏 previous 的 H-4 问题。

## 4. 验收

- 损坏 repo、有效目标 update、previous 缺失、stage=swap 时恢复成功；
- repo 内容保持不变，update 与 transaction 被安全清理；
- update 缺失、非目标或 previous 存在等形状仍失败关闭；
- 既有正常 swap、两次 rename 之间回滚、目录身份竞态和 Reparse 测试不回退；
- 定向重复测试、组件矩阵、标准验证门与 race detector 全绿。
