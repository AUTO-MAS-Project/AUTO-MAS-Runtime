# 运行时失败诊断补齐

登记：2026-10-22；完成：2026-10-23。来源：用户授权修复诊断审查的前四项；第五项测速摘要不在本轮范围。

## 范围与契约

本轮分别登记 T5.16、T6.10、T14.11、T4.14。仅增加安全诊断事实，不改变错误码四元组、
退出码、来源顺序、重试次数、预算、取消优先级、目录授权或成功/失败判定，无新依赖。
原始错误、响应正文、URL、主机/IP、代理地址和凭据不进入协议或遥测。

- T5.16：`mirror` 提供共用的结构化网络分类，只读 `errors.Is/As`，不解析自然语言；
  DNS、连接、网络超时、可识别代理和 TLS 细分，未知错误保持各调用方原有兜底。
  uv 下载失败的 `attempts` 保留 source/sourceTry/globalTry/outcome，增加 failureKind、
  非负 durationMs，能确认时增加 httpStatus（100~599）。只改变诊断，不改变换源和发布事实。
- T6.10：健康检查 timeout 增加 attemptCount、durationMs、port 及最近一次结构化观测。
  failureKind 区分连接/请求超时/网络错误、后端未就绪、Job 验证尚未完成；state 只来自已验证
  的 starting/running/ready，缺少观测时不猜。取消、退出、HTTP 非 200、身份失败与原轮询规则不变。
- T14.11：Relay 的逐源 AttemptOutcome 追加 failureKind、httpStatus、durationMs、operation、
  windowsError（仅真实系统错误码）；沿单流、分片与索引取回传递。原 outcome 字面量保留，
  network 中的本地 open/write/close/sync/publish/truncate 失败以 filesystem_* 细分类明确区分，
  长度异常与超限以 size_mismatch/size_limit 分类。每个请求或 worker 持有独立诊断值，
  汇总在既有锁下复制，无全局最近错误、无新增 goroutine/timer。
  索引失败仅增加诊断，不触发此前仅制品失败触发的 MIRROR_EXHAUSTED；制品摘要优先保留，
  避免新增索引记录占满上限后改变既有错误判断。内部 DiagnosticOnly 不作为协议字段输出。
- T4.14：完整 Git 获取的引用查询和 clone 复用安全网络分类，并保留 operation 和可确认的
  httpStatus；原 clone/resolve/branch 及 cleanup/output/cancel 主错误优先级不变。
  内部传输预算耗尽显式记 network_timeout，不将其改成用户取消；未知仍为 resolve_failed/clone_failed。

Sentry 继续使用已登记的 source、attempts、failureKind、durationMs、operation、windowsError、
httpStatus、attemptCount、port、state 字段，BeforeSend 再次净化；不加入自由文本通道。
业务包不依赖 telemetry，生产分类集中在 mirror，Git 特有 go-git 包装仍由 gitrepo 处理。

## 验收

每项先红后绿、独立代码提交及提交后复核，再进入下一项。覆盖混合来源/状态、回退成功、
取消与清理覆盖、负耗时钳制、真实本地 HTTP/TLS、协议/Sentry 生产形态脱敏。
定向 100 次，标准 gofmt/vet/build/全仓 test/diff-check；Relay 与并发路径追加 protocol 100 次
及全仓 race。完整包测试使用 -p 1，减少 Windows Job/子进程夹具的既有时序干扰。
完成后独立回写任务状态、归档设计、删除计划，ff-only 合入本地 main；保留已有 M11 草案，
不推送、不发版，不把本地注入故障称为现场网络根因已解决。

### 最终验证（PowerShell 7，本机 Windows）

标准门 `gofmt -l .`、`go vet ./...`、`go build -buildvcs=false ./...`、
`go test -p 1 ./... -count=1`、`git diff --check` 全部退出 0。
五个包的 11 个新增诊断顶层测试以 `-run ... -v -count=100` 各运行 100 次，
逐项核对 PASS 次数且无 `[no tests to run]`；`go test ./internal/protocol -count=100` 退出 0。
组件 race：`go test -race -p 1 ./internal/relay ./internal/uv ./internal/health ./internal/mirror -count=1`
退出 0。提升 PATH 中实际 GCC 目录的优先级后，完整
`go test -race -p 1 ./... -count=1` 全部包通过、退出 0，未改动测试期间的生产源码。

诊断重复验证的完整选择条件如下（五个包各有匹配项，检查每项 PASS 100 次）：

```powershell
$names = @(
  'NetworkFailureKind_Structured', 'Bootstrap_DownloadDiagnostics', 'Health_TimeoutDiagnostics',
  'Relay_FailureDiagnostics', 'Relay_LocalFailureDiagnostics', 'Relay_DiagnosticCapacityPreservesTransferFailures',
  'RelaySummary_DiagnosticTelemetry', 'Dependencies_IndexDiagnosticsPreserveErrorCode',
  'Fetcher_NetworkDiagnostics', 'Fetcher_MixedDiagnosticAttempts', 'Fetcher_CleanupOverridesNetworkDiagnostics'
)
$pattern = '^Test(' + ($names -join '|') + ')$'
go test -p 1 ./internal/mirror ./internal/uv ./internal/health ./internal/relay ./internal/gitrepo -run $pattern -v -count=100
if ($LASTEXITCODE -ne 0) { throw 'diagnostic repeat failed' }
```

全部验证在 `codex/diagnostic-details` 的独立工作树执行；合并时核对 main 与分支提交一致，
并以反向补丁检查及未跟踪文件 SHA-256 对照保留原有工作。无推送、发版或现场复跑。

上述网络矩阵使用注入错误或本地 HTTP/TLS 服务，无外部上传；Sentry 测试经生产 schema
净化后检查，未把 URL、主机、凭据、正文或原始错误引入协议。现场故障仍需新版本日志确认。
