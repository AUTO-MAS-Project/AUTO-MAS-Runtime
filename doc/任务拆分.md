# AUTO-MAS-Runtime 任务拆分与实施清单

> 本文档从 [架构设计](./架构设计.md)（2026-07-27 冻结版）派生，是逐任务的可执行清单。
> 目标：用 Go 实现 `auto-mas-runtime.exe`，替代 AUTO-MAS 当前由 Electron 承担的初始化 / 更新 / 后端进程管理流程，并建立本仓库的 GitHub CI/CD 发布流水线。
> AUTO-MAS 侧需要配合修改的内容集中在第 5 章「AUTO-MAS 侧配合改造 TODO」，均以 `TODO-*` 编号标注。

## 0. 使用与维护规则（执行 agent 必读）

### 0.1 状态标记

- 未开始：`- [ ]`
- 完成：改为 `- [x]`，并在任务标题行尾追加 `✅ YYYY-MM-DD <commit 短哈希>`
- 进行中（可选）：任务标题行尾追加 `🚧`
- 受阻：任务标题行尾追加 `⛔ <一句话原因>`，并在第 7 章「变更记录」登记
- 里程碑标题上的复选框：其下**全部任务**勾选后才允许勾选

### 0.2 完成定义（DoD，对每个任务生效）

1. 代码已提交到 main 分支（或经 PR 合入）；
2. `gofmt` 无 diff、`go vet ./...` 无告警、`go test ./...` 全绿；
3. 任务条目中的「验收」逐条满足；
4. 不回退已通过的协议契约测试（M1 建成后）；
5. 涉及对外契约（NDJSON 字段、错误码、stage、状态、环境变量、目录布局）的实现必须与 `doc/架构设计.md` 一致；发现文档矛盾时**先改文档并登记变更记录，再写代码**。

### 0.3 执行顺序

- 按各任务标注的「依赖」执行；无依赖关系的任务可并行；
- 里程碑整体顺序建议 M0 → M1 → M2 → M3 →（M4 ∥ M5）→ M6 → M7 → M9（M8 编号已随决策 D6 移除，保留空缺）；M10 为跨阶段维护；M11/M12 为 2026-08-04 新增的规划中扩展，均为设计任务先行，实施在设计定稿后拆分登记；
- AUTO-MAS 侧 TODO 由那边的仓库执行，本仓库任务不阻塞在其上，除非「依赖」中显式标注。

### 0.4 规模标记

`S`＝半天内，`M`＝1~2 天，`L`＝3 天以上（供排期参考，非硬约束）。
