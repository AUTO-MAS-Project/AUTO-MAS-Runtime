# T1.6 协议契约测试套件实现计划

> 严格测试驱动：每个任务先新增失败测试并确认失败原因，再写最小实现；
> 每个提交独立审查，修复 Critical/Important 后才能进入下一任务。

**目标：** 在生产 `ProcessOutput` 中保证 result 至多一次且最后，自动生成
有界、权威 warning 汇总，并交付后续命令可一行注册的原始 NDJSON 契约库。

**架构：** terminal、sequence、warning ledger 和 renderer 继续共享
`ProcessOutput.mu` 单一线性化域；`contracttest` 独立消费 stdout transcript，
不反向依赖具体命令。

**技术栈：** Go 标准库（`bytes`、`encoding/json`、`errors`、`fmt`、
`strconv`、`strings`、`sync`、`testing`、`time`）和现有 protocol API。

**红灯：**

1. warning snapshot 精确包含六个业务字段且不含 Common；
2. canonical warning 与 ledger 从一次 JSON 编码分别解码，非确定性
   `json.Marshaler` 也只调用一次且原 warning/汇总相同；
3. 调用方修改原 remediation、顶层/嵌套 details，或 renderer 修改收到的
   canonical event 后，result 均不变；
4. 非 JSON warning details 在两种 renderer 下都非 sticky 拒绝；

   terminal 不变；

7. 调用方伪造保留键被删除或覆盖，其他 result details 与原 map 不变；
8. result encode 失败后重试保留同一 ledger；
9. 两个受控并发子测试分别让 warning renderer 和 result renderer 持锁，
   使用 barrier/超时确定性证明两种线性化结果。

- `TestEmitter_WarningSummary`
- `TestEmitter_WarningSummaryLimit`
- `TestEmitter_WarningResultRace`
- `TestEmitter_WarningSnapshotFailure`
- `TestEmitter_WarningLedgerFailureBoundaries`

**绿灯：**

1. 增加 `WarningSummary` 和 `MaxResultWarningSummaries=256`；
2. warning renderer 前只编码一次，并分别解码 canonical event 与 ledger
   snapshot；
3. renderer 成功后更新 count，并仅保存前 256 条独立 snapshot；
4. result renderer 前复制 details、清除保留键并注入权威汇总；
