# T2.1 config 与目录布局设计

## 文档状态

- 日期：2026-07-29
- 状态：已批准，采用方案 A
- 任务：[T2.1 config 与目录布局](./任务拆分.md)
- 架构基线：[架构设计](./架构设计.md)
- 代码基线：AUTO-MAS Runtime `ad536a8`

本文冻结 `internal/config` 对应用根目录的解析、路径身份和受管目录布局。
后续包不得自行重复拼接本文已经定义的应用根级路径；若目录契约需要变化，
必须先修改权威架构和本文，再修改实现与测试。

## 1. 目标与范围

T2.1 交付以下能力：

1. 消费 CLI 已经解析出的 `--app-root` 字符串，不在 `config` 中注册参数；
2. 相对路径只相对调用方显式传入的 `base` 解析，不读取隐式当前目录；
3. 分离用于展示和文件 I/O 的规范绝对路径与大小写不敏感的身份键；
4. 以不可变 `Layout` 提供应用根级固定路径和少量受校验的动态路径；
5. 冻结仓库、更新事务、状态、uv、Python、venv、缓存和日志目录；
6. 冻结根级保护目录并通过防御性副本返回；
7. 为 T2.4 物理锁身份、T2.5 文件安全和后续业务包提供同一布局入口。

本任务不创建、删除、移动或探测任何文件，也不解析 Runtime 业务配置文件。
`NewLayout` 成功只表示路径在词法层面满足本设计，不表示路径存在、可写或
没有 Reparse Point。

## 2. 方案 A：不可变 Layout + 显式 base

采用一个构造完成后只读的 `Layout`。调用方先完成命令行解析，再取得一次
明确的基准目录并传入：

```go
func NewLayout(appRoot, base string) (*Layout, error)
```

`base` 无论 `appRoot` 是绝对还是相对路径都必须非空且为绝对路径。这样每次
构造都具有相同前置条件，不会因输入形态不同而暗中读取进程当前目录。CLI
后续可在参数解析成功后调用 `os.Getwd`，并把结果显式交给 `NewLayout`；
测试则直接传入临时目录。

`Layout` 的字段不导出，构造后不再修改。所有方法只返回字符串值或新建的
切片，因此同一个 `*Layout` 可以被多个 goroutine 并发读取，不需要锁。

不采用以下方案：

- 不让 `config` 自行读取 `os.Getwd`、环境变量或用户主目录；
- 不把全部路径作为可变公开字段暴露给调用方；
- 不建立通用的字符串键到路径映射；
- 不让各业务包各自持有根目录后再调用 `filepath.Join` 重建固定布局。

## 3. app-root 解析

### 3.1 输入所有权

`appRoot` 是 CLI 层已经完成语法解析的参数值。`config` 只负责路径语义：

- 不注册 `--app-root`；
- 不决定缺省应用根目录；
- 不读取 Electron 配置或注册表；
- 不对字符串执行 shell 解析；
- 不展开 `~`、`%NAME%`、`$NAME` 或其他环境变量语法。

例如 `~\AUTO-MAS` 和 `%LOCALAPPDATA%\AUTO-MAS` 都按普通相对路径文本
处理，并相对显式 `base` 解析。调用方需要展开时必须在进入 `config` 前
明确完成，首版 CLI 不提供这种隐式展开。

### 3.2 解析步骤

`NewLayout` 按固定顺序处理：

1. 拒绝空 `base` 或 `appRoot`；
2. 拒绝任一输入中的 NUL；
3. 要求 `base` 已是绝对路径，并对其执行 `filepath.Clean`；
4. 拒绝带卷名但不是绝对路径的含糊形式，例如 `C:relative`；
5. 若 `appRoot` 为相对路径，则使用 `filepath.Join(base, appRoot)`；
6. 对结果执行 `filepath.Clean`，得到用于展示和文件 I/O 的绝对路径；
7. 拒绝盘符根和 UNC 共享根等卷根路径；
8. 从规范绝对路径派生大小写不敏感的身份键；
9. 预计算全部固定目录，不访问文件系统。

尾部斜杠、`.` 和 `..` 仅按 `filepath.Clean` 的词法规则归一化。本文不调用
`filepath.EvalSymlinks`，也不展开 8.3 短路径；这两项需要访问 Windows
文件系统，属于 T2.5 的物理身份与删除安全边界。

### 3.3 显示路径与身份键

`Layout.AppRoot()` 返回保留调用方实际大小写的规范绝对路径。它用于：

- 打开和创建文件；
- 记录本地诊断；
- 返回绝对 `logPath`；
- 作为其他 `Layout` 路径的前缀。

`Layout.IdentityKey()` 返回同一路径的词法身份键：

```text
filepath.Clean(appRoot) -> 统一 Windows 分隔符 -> Unicode 小写
```

身份键仅用于无需访问文件系统的大小写不敏感比较、缓存和诊断关联，不用于
文件 I/O，也不向用户展示。输入仅大小写不同或尾部斜杠不同，身份键必须
相同；`AppRoot()` 仍保留各自的显示大小写。

身份键不宣称识别短路径、Junction、符号链接、卷挂载点或硬链接指向的同一
物理对象。T2.4 必须通过 app-root 目录句柄取得物理同步身份后再派生命名
Mutex，T2.5 必须在危险文件操作前执行更强的 Windows 物理路径校验；两者
都不能把 `IdentityKey()` 当作最终授权。

```go
func (l *Layout) EnvironmentStateFile() string

func (l *Layout) RuntimeDir() string
func (l *Layout) UVToolsDir() string

func (l *Layout) UVExecutable(version string) (string, error)

func (l *Layout) RuntimeCacheDir() string
func (l *Layout) UVCacheDir() string

    version string,
    operationID string,
) (string, error)

func (l *Layout) LogsDir() string
func (l *Layout) RuntimeLogDir() string
func (l *Layout) RuntimeLogFile(
    command string,
    localDate time.Time,
) (string, error)

func (l *Layout) ConfigDir() string
func (l *Layout) DataDir() string

func (l *Layout) DebugDir() string

```

`NewLayout` 返回具体类型，调用方无需为纯路径数据定义接口。固定路径方法
不返回 error，因为构造成功后结果已经确定；包含动态单段名称的方法在每次
调用时校验输入并返回 error。

`RuntimeLogFile` 由 T2.2 使用。它从 `localDate` 生成 `YYYYMMDD`，返回
`<command>-YYYYMMDD.log`；扩展名保持架构文档冻结的 `.log`，文件内容由
T2.2 定义为 JSONL。时间的 Location 由调用方提供，`config` 不读取或修改
全局时区。

## 5. 目录布局

给定 `AppRoot() == D:\AUTO-MAS`，方法与路径的精确映射如下：

| --- | --- |

| `RepoUpdateDir("01J...")` | `D:\AUTO-MAS\repo.update-01J...` |
| `RepoPreviousDir("01J...")` | `D:\AUTO-MAS\repo.previous-01J...` |
| `StateDir()` | `D:\AUTO-MAS\runtime-state` |
| `BackendStateFile()` | `D:\AUTO-MAS\runtime-state\backend.json` |
| `MutationStateFile()` | `D:\AUTO-MAS\runtime-state\mutation.json` |
| `UpdateStateFile()` | `D:\AUTO-MAS\runtime-state\update.json` |
| `EnvironmentStateFile()` | `D:\AUTO-MAS\runtime-state\environment.json` |
| `RuntimeDir()` | `D:\AUTO-MAS\runtime` |
| `UVToolsDir()` | `D:\AUTO-MAS\runtime\tools\uv` |
| `UVVersionDir("0.8.0")` | `D:\AUTO-MAS\runtime\tools\uv\0.8.0` |
| `UVExecutable("0.8.0")` | `D:\AUTO-MAS\runtime\tools\uv\0.8.0\uv.exe` |
| `PythonDir()` | `D:\AUTO-MAS\runtime\environment\python` |
| `VenvDir()` | `D:\AUTO-MAS\runtime\environment\venv` |
| `RuntimeCacheDir()` | `D:\AUTO-MAS\runtime\cache` |
| `UVCacheDir()` | `D:\AUTO-MAS\runtime\cache\uv` |
| `DownloadCacheDir()` | `D:\AUTO-MAS\runtime\cache\downloads` |
| `BuildCacheDir()` | `D:\AUTO-MAS\runtime\cache\build` |
| `UVStagingDir("0.8.0", "01J...")` | `D:\AUTO-MAS\runtime\cache\build\uv-0.8.0-01J...` |
| `LogsDir()` | `D:\AUTO-MAS\logs` |
| `RuntimeLogDir()` | `D:\AUTO-MAS\logs\runtime` |
| `RuntimeLogFile("workspace-sync", date)` | `D:\AUTO-MAS\logs\runtime\workspace-sync-YYYYMMDD.log` |
| `ConfigDir()` | `D:\AUTO-MAS\config` |
| `DataDir()` | `D:\AUTO-MAS\data` |
| `HistoryDir()` | `D:\AUTO-MAS\history` |
| `ScriptDir()` | `D:\AUTO-MAS\script` |
| `DebugDir()` | `D:\AUTO-MAS\debug` |
| `PluginsDir()` | `D:\AUTO-MAS\plugins` |

`repo.previous-<operationId>` 是一次替换事务中的旧仓库目录，不是长期 Slot。
T4.4 只能通过 `RepoPreviousDir` 取得它；事务结束后是否删除由 state、
filesystem 和 gitrepo 共同决定，`config` 不实施清理。

`DownloadCacheDir()` 和 `BuildCacheDir()` 分别是 T2.5
`DeleteDownloadTemporary`、`DeleteBuildCache` 的唯一目标来源，T3
`cleanup` 也只能从这些 getter 取得缓存路径。`UVCacheDir()` 由 uv 包拥有；
三者都不得在业务包中从 `RuntimeCacheDir()` 再次硬编码子目录名。

`UVStagingDir()` 是 T5.1 解压 uv 发行包后、发布到 `UVVersionDir()` 前的
版本化事务目录。它只接受分别通过动态 segment 校验的 version 和 operation ID，
路径固定为 `BuildCacheDir()\uv-<version>-<operationId>`；filesystem 的删除和
重命名授权必须重新调用同一 getter 核对身份，T5.1 不自行拼接 staging 名称。

`Layout` 只集中应用根级布局。仓库内部的 `.python-version`、
`pyproject.toml`、`uv.lock`、`res/version.json` 和 `main.py` 仍由对应业务
包定义，但必须从 `RepoDir()` 起步，不能重新拼接应用根或假定仓库在根目录。

## 6. 动态 segment 校验

`operationID`、uv `version` 和日志 `command` 都只能形成一个 Windows
文件名 segment。校验只保证路径安全，不替代业务语义校验；例如
`RepoUpdateDir` 不负责验证 operation ID 是否为规范 ULID，
`UVVersionDir` 不负责判断 uv 版本是否受 Runtime 支持。

动态 segment 必须满足：

1. 非空且不含 NUL；
2. 不是 `.` 或 `..`；
3. 不含 `/`、`\` 或卷名前缀；
4. 不含 Windows 文件名非法字符 `< > : " | ? *`；
5. 不以点或空格结尾；
6. 不与 `CON`、`PRN`、`AUX`、`NUL`、`COM1`～`COM9`、
   `LPT1`～`LPT9` 等设备名冲突，比较时忽略大小写和扩展名；
7. 经校验后原样用于路径，不做 trim、大小写转换或替换字符。

任何校验失败都返回 `ErrInvalidSegment`，不得“清洗”成另一个名称。静默
替换字符会让状态文件、临时目录和日志路径失去一一对应关系。

日志 `command` 使用 CLI 预先约定的稳定短名，例如 `bootstrap`、
`workspace-sync`、`backend-supervise`。它不是用户可自由指定的文件名。

## 7. 根级保护名单

`ProtectedRootDirs()` 按固定顺序返回：

```text
config
data
history
script
debug
plugins
logs
```

前六项包含用户业务数据、外部脚本、诊断数据和插件数据；`logs` 单独列入，
保证 workspace 更新、repair 和普通 cleanup 不删除任何诊断日志。
`runtime-state` 与 `runtime` 是 Runtime 受管元数据、环境和缓存，不进入这份
绝对保护名单；它们仍只能由拥有相应职责的包按 T2.5 安全规则操作。

返回值是新建切片。调用方修改、重排或清空结果不得影响后续调用，也不得
改变 `Layout` 内部状态。实现不导出可变包级切片。

保护名单是“无条件不得递归删除或移动”的第一层边界，不是删除允许列表。
不在名单中不代表可以删除；filesystem 仍必须验证受管根、目标身份、状态、
Reparse Point 和操作允许列表。

## 8. 错误语义

实现提供可由 `errors.Is` 判断的 sentinel error：

```go
var (
    ErrEmptyPath       = errors.New("path is empty")
    ErrPathContainsNUL = errors.New("path contains nul")
    ErrBaseNotAbsolute = errors.New("base path is not absolute")
    ErrInvalidPath     = errors.New("path is invalid")
    ErrAppRootIsRoot   = errors.New("app root is a volume root")
    ErrInvalidSegment  = errors.New("path segment is invalid")
    ErrInvalidLogDate  = errors.New("log date is invalid")
)
```

| 场景 | error |
| --- | --- |
| `base` 或 `appRoot` 为空 | `ErrEmptyPath` |
| 路径含 NUL | `ErrPathContainsNUL` |
| `base` 不是绝对路径 | `ErrBaseNotAbsolute` |
| `C:relative` 等含糊卷相对形式 | `ErrInvalidPath` |
| 解析结果是盘符根或 UNC 共享根 | `ErrAppRootIsRoot` |
| 动态单段名称违反第 6 节 | `ErrInvalidSegment` |
| `RuntimeLogFile` 收到零值时间 | `ErrInvalidLogDate` |

错误字符串使用英文、小写开头、无结尾标点。实现可以增加字段名等本层上下文，
但必须 `%w` 包装对应 sentinel，且不得把含 NUL 的原始值写入错误文本。

T2.1 不直接生成协议错误。CLI 对无效 `--app-root` 的映射归 T3.1；
filesystem 对越界和物理危险路径的 `PATH_OUTSIDE_MANAGED_ROOT`、
`UNSAFE_REPARSE_POINT` 映射归 T2.5。

## 9. 并发与安全不变量

- `Layout` 构造后不可变，全部公开读取方法可并发调用；
- 不保存调用方提供的可变 slice、map、buffer 或环境引用；
- 不读取或缓存当前工作目录，进程后续 `chdir` 不影响既有布局；
- 不调用 `EvalSymlinks`、`GetLongPathName` 或任何文件系统探测；
- 所有返回路径都是绝对路径，并位于 `AppRoot()` 的词法子树中；
- 动态 segment 在 join 前校验，不能借助 `..`、分隔符或卷名逃逸；
- `IdentityKey()` 不能作为物理路径安全判据；
- `ProtectedRootDirs()` 每次返回防御性副本。

首版仅支持 Windows。实现使用 `path/filepath` 的 Windows 语义，不承诺在
非 Windows 平台产生可用于部署的目录布局。

## 10. 不负责范围

T2.1 明确不负责：

- CLI 参数注册、缺省值、help 和错误码输出；
- 从 Electron、环境变量、注册表或用户目录发现 app-root；
- 创建目录、权限设置、磁盘空间检查或可写性检查；
- 解析 Reparse Point、短路径、真实大小写或文件 ID；
- 受控删除、原子移动、审计日志和目录占用重试；
- 校验 operation ID、uv 版本或命令名的业务枚举；
- 状态 JSON schema、日志 JSONL schema 和保留策略；
- 仓库内部资源路径之外的业务规则；
- development 模式外部仓库的路径安全和清理授权。

这些职责分别属于后续 cli、filesystem、state、logging、gitrepo、uv 和
backend 任务。

## 11. 测试与验收

自动化测试必须覆盖：

1. 绝对 app-root、普通相对 app-root、尾部斜杠、`.`、`..` 和混合分隔符；
2. 相对路径只按显式绝对 `base` 解析，构造后改变当前目录不影响结果；
3. 空 `base`、空 `appRoot`、NUL、非绝对 base、卷相对路径、盘符根和
   UNC 共享根均返回精确 sentinel；
4. `~`、`%NAME%` 和 `$NAME` 不被展开；
5. `AppRoot()` 保留显示大小写，大小写或尾斜杠不同输入得到相同
   `IdentityKey()`；
6. 身份键不被任何路径 getter 用于文件 I/O 路径；
7. 第 5 节每个固定路径逐项比对，全部为绝对路径；
8. `repo.update`、`repo.previous`、uv 版本目录、uv staging、`uv.exe`、
   三类缓存和日志文件路径；
9. 动态 segment 的空值、NUL、`.`、`..`、两种分隔符、卷名、非法字符、
   结尾点/空格和设备名；
10. segment 校验失败时不返回部分路径，也不替换输入字符；
11. 四个 state 文件名及所在目录准确且互不重复；
12. `RuntimeLogFile` 使用传入时间的本地日期，零时间被拒绝；
13. 七个保护根目录顺序、绝对路径、无重复且全部位于 app-root；
14. 修改第一次 `ProtectedRootDirs()` 的返回值不影响第二次调用；
15. 并发调用全部 getter 和动态路径方法无数据竞争；
16. 构造和 getter 不创建任何文件或目录；
17. 后续包落地后执行静态扫描，确认没有重复拼接本文冻结的应用根级路径。

完成实现前，计划文档应为上述场景固定测试函数名。完成实现后执行标准验证
门，并由 code review 对“目录布局唯一来源”做一次跨包扫描。
