# 现成库替换评估

评估日期：2026-08-01。

## 结论

Go 有足够成熟的库，但本仓库现有代码并不都是“通用基础设施”。协议顺序、镜像切换、
Windows 对象身份、no-replace 发布和失败后的副作用报告属于 AUTO-MAS Runtime 的领域契约，
通用库通常只能覆盖其中一段。替换的判断标准不是“能否调用”，而是能否删除一整块自研职责，
同时保留冻结行为。

本轮建议分为三类：

1. **直接采用**：Cobra、go-git、`google/go-cmp`；
2. **标准库或既有依赖优先，先做等价性验证**：`os.Root`、`os.Process.WithHandle`、
   `golang.org/x/sys/windows`；
3. **不替换现有实现**：retryablehttp、Grab、Lumberjack、juju/mutex、renameio、数据库和 Viper。

## 当前规模与主要成本

当前仓库有 84 个生产 Go 文件、约 1.77 万行生产代码，67 个测试文件、约 3.93 万行测试。
其中 `filesystem`、`mirror`、`state`、`lock` 和 `logging` 的测试合计超过 3 万行；53 个测试文件
使用同包白盒形式。测试中存在 76 处 `reflect.DeepEqual`，说明测试比较和失败诊断已有统一工具的
实际需求。

生产代码的最大热点是：

- `internal/filesystem/state_files_windows.go`：约 2500 行；
- `internal/filesystem/path_windows.go`：约 1470 行；
- `internal/mirror/downloader.go`：约 780 行；
- `internal/mirror/rotation.go`：约 580 行。

前三个 Windows 文件的大部分复杂度来自句柄固定、Reparse Point、对象身份和失败恢复，不能仅凭
行数认定为重复造轮子。`mirror` 的长函数则更适合先拆职责，不适合把重试控制权交给通用 HTTP 库。

## 批准采用的库

### Cobra：M3 CLI

决定：**采用**。

Cobra 直接负责命令树、嵌套子命令、参数和 flag 校验、help、usage 与 PowerShell completion。
这些正是 M3 的通用 CLI 工作，不应再自研解析器。官方能力见
[Cobra](https://github.com/spf13/cobra)。

接入边界：

- Cobra 只存在于 `internal/cli`；业务逻辑仍由应用服务承担；
- 显式注入 stdin、stdout、stderr，不使用包级全局输出；
- NDJSON 模式禁止 Cobra 自动向 stdout 写 help、usage 或错误；
- 不同时引入 Viper，当前配置是冻结目录布局和显式参数，不需要动态配置框架。

### go-git：M4 工作区同步

决定：**采用当前主版本，但先执行 T4.0 spike**。

go-git 已提供 clone、fetch、reference、worktree 和 context API，可以删除自行实现 Git 协议、
packfile、ref 与 checkout 的需求。官方说明和兼容性边界见
[go-git](https://github.com/go-git/go-git)。

接入边界：

- go-git 只负责 Git 传输和仓库语义；
- 镜像选择、稳定错误码、进度事件、临时目录命名、克隆后验证和整体目录替换仍由本项目负责；
- 不把 go-git 的 progress 直接连接 stdout；
- 版本在 T4.0 验证后固定，不使用无版本的 `latest` 约束。

### google/go-cmp：测试比较

决定：**批准为仅测试依赖，在 T10.3 做单包试点**。

`cmp.Diff` 用于结构体、slice、map 和嵌套结果比较，替换重复的 `reflect.DeepEqual` 与逐字段
失败文案。它只用于测试，官方定位也是比 `reflect.DeepEqual` 更强、更安全的语义比较工具，见
[go-cmp](https://github.com/google/go-cmp)。

限制：

- 先在 `internal/mirror` 的普通行为测试试点，不做全仓机械迁移；
- error chain、调用顺序、文件副作用、句柄访问参数和协议事件顺序仍显式断言；
- 不引入 testify/gomega，不建立通用 `assert` 包；
- 只有试点能减少重复代码并改善失败输出时，才逐包迁移。

## 优先使用但必须验证等价性的能力

### `os.Root`：受根约束的普通文件操作

决定：**做有界 spike，不直接替换安全内核**。

Go 1.26 的 `os.Root` 会固定根目录，并阻止通过路径或符号链接逃逸根目录；根被移动后仍引用
原对象，适合普通的受根 open/read/write/remove。官方语义见
[`os.Root`](https://pkg.go.dev/os#Root)。

它仍会跟随指向根内的符号链接，而本项目对未知 Junction/Reparse Point 要求拒绝；它也不提供
StateFiles 所需的 volume serial、file ID、link count、no-replace、POSIX unlink 和阶段化恢复事实。
因此只评估下载临时文件、普通日志文件等低风险路径，不先迁移以下能力：

- `StateFiles` 原子写入和条件删除；
- 受控递归删除；
- 仓库整体替换；
- 任何依赖物理对象身份或审计阶段的操作。

### `os.Process.WithHandle` + `x/sys/windows`：M6 进程监督

决定：**M6 优先采用，不自行提取或猜测进程句柄**。

Go 1.26 的 `os.Process.WithHandle` 在回调期间保证 Windows 进程句柄有效；
`x/sys/windows` 已提供 Job Object 创建与进程分配 API。参考
[`os.Process.WithHandle`](https://pkg.go.dev/os#Process.WithHandle) 和
[`x/sys/windows`](https://pkg.go.dev/golang.org/x/sys/windows)。

Job Object 的生命周期、`CREATE_SUSPENDED` 接入、输出管道、优雅关闭和协议事件仍是项目编排，
但 Win32 声明、常量和句柄类型不再重复定义。既有 `x/sys` 升级必须独立验证，不顺手追最新版。

## 不采用的替换方案

| 候选 | 结论 | 原因 |
| --- | --- | --- |
| `hashicorp/go-retryablehttp` | 不替换 mirror | 它在 HTTP Client 内隐藏重试；本项目必须由 Rotator 决定同源重试、切源、完整性拉黑和 AttemptReport 顺序。 |
| `cavaliergopher/grab` | 不替换 Downloader | Grab 自己管理目标文件和断点续传，并假设本地/远端文件未被其他程序修改；无法保留 DownloadSession 的安全发布、no-replace 与清理事实。 |
| Lumberjack | 不替换 logging | 主要按文件大小轮转并自行清理；本项目按本地日历日和命令命名，删除还必须经过受管文件能力。 |
| `log/slog` | 不替换日志持久化内核 | `slog` 适合调用 API 和 Handler 组合，但当前 Logger 必须向调用方返回 file/stderr 写入事实和错误；改成自定义 Handler 仍需保留大部分现有代码。 |
| `juju/mutex` | 不替换 lock | 缺少物理 app root 身份、双锁冲突、零等待 probe、abandoned/recovered 元数据；Release 失败会 panic，许可证也不适合作为默认选择。 |
| `google/renameio` | 不可用 | 该项目明确不在 Windows 导出实现，不能覆盖当前 Windows 原子状态写入。 |
| bbolt/SQLite | 不迁移 state | 会改变已冻结的独立 JSON 状态文件、恢复与人工诊断边界，属于产品存储设计变更而非实现替换。 |
| Viper | 不采用 | `config` 只有冻结布局和显式参数，引入动态配置、环境绑定及其传递依赖没有相应收益。 |

## 对现有代码的处理顺序

1. M3 直接使用 Cobra，不写临时手工解析器；
2. T10.2 只拆 `Rotator.Run` 和 Downloader 内部职责，不引入 retryablehttp 或 Grab；
3. T10.3 用 `go-cmp` 改造 `internal/mirror` 一组普通结构比较，记录前后行数、失败输出和测试时间；
4. T10.3 单独做 `os.Root` spike，只有证明现有 Windows 对抗测试等价时才迁移低风险能力；
5. T4.0 用 go-git 当前主版本验证 GitHub/CNB 的浅克隆、取消、分支缺失和进度接入，再固定版本；
6. M6 使用 `os.Process.WithHandle` 与既有 `x/sys/windows` 完成 Job Object 接入。

不做一次性全仓依赖迁移。每次替换必须能明确删除旧职责、保留错误和副作用语义，并通过标准门、
相关包高重复测试和全仓 race detector。
