# T1.3 生命周期状态机实现计划

> **面向 AI 代理的工作者：** 必需子技能：使用
> `superpowers:subagent-driven-development` 逐任务实现本计划。步骤使用
> 复选框（`- [ ]`）跟踪进度；每个实现任务完成后先做规格审查，再做代码
> 质量审查。

**目标：** 实现协议 v1 的 stage、进度状态、生命周期状态强类型常量，
以及并发安全、可拒绝非法迁移的完整生命周期状态机。

**架构：** `values.go` 只负责稳定字符串全集和查询；`lifecycle.go` 只负责
进程内迁移约束；`capabilities.go` 用窄接口隔离一次性检查命令与生命周期
写能力。事件仍使用原有 JSON 字段，强类型底层为字符串，不改变 wire
format。

**技术栈：** Go 1.26、标准库 `encoding/json` / `sync` / `testing`，
PowerShell 7，现有 `internal/protocol` 包。

增加表驱动测试：

```go
func TestLifecycleMachineRollbackPreparation(t *testing.T) {
    for _, initial := range []StateStatus{
        StateUninitialized,
        StateEnvironmentBroken,
        StateReadyToStart,
    } {
        machine, err := NewLifecycleMachine(initial)
        if err != nil {
            t.Fatal(err)
        }
        if err := machine.Transition(StatePreparingUV); err != nil {
            t.Fatal(err)
        }
        if err := machine.RollbackPreparation(); err != nil {
            t.Fatal(err)
        }
        if got := machine.Current(); got != initial {
            t.Fatalf("Current() = %q, want %q", got, initial)
        }
    }
}
```

另覆盖：

- `syncing_repository` 可以回滚到初态；
- `preparing_python`、`syncing_environment`、稳定态和后端态拒绝回滚；
- 首次 `running -> restarting -> running` 成功且 `RestartUsed` 为 true；
- 再次 `running -> restarting` 被拒绝且状态仍为 running；
- 首次 running 直接进入 backend_failed 被拒绝；
- 已重启后的 running 进入 backend_failed 成功；
- `backend_failed` / `stopped` 后任何迁移拒绝；
- 未知状态、self-loop、`uninitialized -> ready_to_start`、
  `ready_to_start -> running`、`environment_broken -> starting_backend`
  被拒绝且状态不变。
