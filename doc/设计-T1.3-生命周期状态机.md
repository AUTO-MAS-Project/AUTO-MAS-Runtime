# T1.3 stage 与生命周期状态机设计

## 文档状态

- 日期：2026-07-28
- 状态：已批准，采用方案 A
- 任务：[T1.3 stage 常量与生命周期状态机](./任务拆分.md)
- 架构基线：[架构设计](./架构设计.md)
- 代码基线：AUTO-MAS Runtime `7bc5446`

本文冻结协议 v1 的 stage、进度状态、生命周期状态、合法迁移和只读命令
API 边界。后续实现不得自行增加状态、改名或放宽迁移；新增 stage 可以按
协议兼容规则追加，但必须同步文档和契约测试。

## 目标与范围

T1.3 交付以下内容：

1. stage、`progress.status`、`state.status` 的强类型常量全集；
2. 环境准备、修复、依赖重试和后端监督的完整合法迁移；
3. 对第二次自动重启、准备阶段回滚和终态的状态化约束；
4. 一次性检查命令无法取得生命周期写能力的 API 边界；
5. 与架构文档逐项比对的自动化测试。

本任务不实现状态文件持久化、具体命令编排、human 渲染或 stdin 控制。
状态文件由后续 `internal/state` 负责；本状态机只验证进程内的协议语义。

### StateStatus

| 常量 | 字面量 | 语义 |
| --- | --- | --- |
| `StateUninitialized` | `uninitialized` | 尚无可验证的受管工作区或环境 |
| `StatePreparingUV` | `preparing_uv` | 正在准备固定版本 uv |
| `StateSyncingRepository` | `syncing_repository` | 正在解析、克隆、校验或替换仓库 |
| `StatePreparingPython` | `preparing_python` | 正在校验或安装精确 Python |
| `StateSyncingEnvironment` | `syncing_environment` | 正在锁定同步或重建主环境 |
| `StateReadyToStart` | `ready_to_start` | 仓库、Python 和主环境已就绪 |
| `StateStartingBackend` | `starting_backend` | 后端已创建，正在等待健康检查 |
| `StateRunning` | `running` | 后端身份和连续健康检查均通过 |
| `StateRestarting` | `restarting` | 正在执行唯一一次自动重启 |
| `StateStoppingBackend` | `stopping_backend` | 正在优雅关闭或清理进程树 |
| `StateEnvironmentBroken` | `environment_broken` | Git 有效，但 Python 主环境不可用 |
| `StateBackendFailed` | `backend_failed` | 启动、健康、重启、关闭或清理失败 |
| `StateStopped` | `stopped` | 后端已退出且进程树确认清空 |

`AllStateStatuses` 和 `IsKnownStateStatus` 提供全集与生产端校验。

## 事件字段类型

协议事件改用强类型字段：

- `ProgressEvent.Stage` 使用 `Stage`；
- `ProgressEvent.Status` 使用 `ProgressStatus`；
- `StateEvent.Stage` 使用 `Stage`；
- `StateEvent.Status` 使用 `StateStatus`；
- `WarningEvent.Stage`、`ErrorEvent.Stage`、`ResultEvent.Stage` 使用 `Stage`；
- `ResultEvent.Status` 保持 `string`，因为成功检查、环境状态和后端终态会
  复用该字段，协议 v1 没有为它冻结单一枚举。

这些类型的底层仍是字符串，JSON 字面量与现有协议完全一致。

## 生命周期模型

### 稳定初态

每个顶层 Runtime 进程创建一个 `LifecycleMachine`。合法初态只有：

- `uninitialized`：没有可用受管环境；
- `environment_broken`：仓库有效但主环境不可用；
- `ready_to_start`：环境可用于启动后端。

瞬态和后端终态不能作为新的持久化初态。新的 `backend supervise` 进程从
持久化的 `ready_to_start` 开始，而不是从上一次进程内的 `stopped` 或
`backend_failed` 开始。

### 环境准备与恢复迁移

| From | To | 使用场景 |
| --- | --- | --- |
| `uninitialized` | `preparing_uv` | 首次 bootstrap |
| `environment_broken` | `preparing_uv` | 完整 repair |
| `ready_to_start` | `preparing_uv` | 幂等 bootstrap 或显式 repair |
| `environment_broken` | `syncing_environment` | dependencies sync/rebuild 重试 |
| `ready_to_start` | `syncing_environment` | 显式 dependencies sync/rebuild |
| `preparing_uv` | `syncing_repository` | bootstrap 继续同步仓库 |
| `preparing_uv` | `preparing_python` | repair 跳过 Git |
| `syncing_repository` | `preparing_python` | 仓库替换成功 |
| `syncing_repository` | `environment_broken` | 仓库已替换但后续准备无法继续 |
| `preparing_python` | `syncing_environment` | Python 已就绪 |
| `preparing_python` | `environment_broken` | Python 准备失败或取消 |
| `syncing_environment` | `ready_to_start` | 锁定依赖同步成功 |
| `syncing_environment` | `environment_broken` | 同步、重建失败或取消 |

`LifecycleMachine` 在构造时保存稳定初态。`preparing_uv` 或
`syncing_repository` 在尚未改变受管仓库和主环境前失败或取消时，只能
通过 `RollbackPreparation` 回到该稳定初态；调用方不能指定任意回滚
目标。仓库一旦替换，失败必须进入 `environment_broken`，不得回滚到
`ready_to_start`。

### 后端监督迁移

| From | To | 使用场景 |
| --- | --- | --- |
| `ready_to_start` | `starting_backend` | 开始监督 |
| `starting_backend` | `running` | 健康与身份检查通过 |
| `starting_backend` | `stopping_backend` | 就绪前收到关闭或取消 |
| `starting_backend` | `backend_failed` | spawn、健康或身份检查失败并完成清理 |
| `running` | `stopping_backend` | 主动关闭或取消 |
| `running` | `restarting` | 首次非预期退出 |
| `running` | `backend_failed` | 已使用自动重启后再次非预期退出 |
| `restarting` | `running` | 唯一一次自动重启成功 |
| `restarting` | `stopping_backend` | 重启期间收到关闭或取消 |
| `restarting` | `backend_failed` | 重启前检查或重启启动失败 |
| `stopping_backend` | `stopped` | 进程树确认清空 |
| `stopping_backend` | `backend_failed` | 无法确认进程树清空 |

进入 `restarting` 时设置进程内 `restartUsed=true`。该标记不因重新进入
`running` 而清除；第二次 `running -> restarting` 必须拒绝。
`running -> backend_failed` 仅在 `restartUsed=true` 时合法，保证首次
意外退出必须走唯一一次自动重启。主动关闭和取消不设置该标记。

`backend_failed` 与 `stopped` 是当前监督进程的终态，发送后不能继续
迁移。

### 迁移验证 API

实现提供：

```go
type LifecycleTransition struct {
    From StateStatus
    To   StateStatus
}

func AllLifecycleTransitions() []LifecycleTransition
func IsKnownLifecycleTransition(from, to StateStatus) bool

func NewLifecycleMachine(initial StateStatus) (*LifecycleMachine, error)
func (m *LifecycleMachine) Current() StateStatus
func (m *LifecycleMachine) Initial() StateStatus
func (m *LifecycleMachine) RestartUsed() bool
func (m *LifecycleMachine) Transition(next StateStatus) error
func (m *LifecycleMachine) RollbackPreparation() error
```

`AllLifecycleTransitions` 返回常规迁移表的防御性副本。
`IsKnownLifecycleTransition` 只判断静态邻接关系；`Transition` 还执行
初态、终态、回滚目标和单次重启等状态化约束。所有读取与迁移并发安全。

## 一次性检查命令边界

协议层定义两个接口：

```go
type OperationEmitter interface {
    EmitProgress(ProgressEvent) error
    EmitWarning(WarningEvent) error
    EmitError(ErrorEvent) error
    EmitResult(ResultEvent) error
}

type LifecycleEmitter interface {
    OperationEmitter
    EmitState(StateEvent) error
}
```

`version`、`doctor`、`workspace check`、`environment check` 和
`dependencies check` 的应用服务只接收 `OperationEmitter`，并且不接收
`LifecycleMachine` 或生命周期写接口。会改变环境或监督后端的服务才接收
`LifecycleEmitter` 和状态机。

协议包不导入 `internal/state`，状态机也不写文件。后续持久化层只保存
`environment_broken`、`ready_to_start` 及最近一次成功的版本和 Commit；
瞬态状态进入事件和操作日志，不作为持久化生命周期真相。

## 错误处理

以下情况返回明确错误且不改变当前状态：

- 初态不是三个稳定状态之一；
- from 或 to 是未知状态；
- 不在合法迁移表中的跳转或 self-loop；
- 从 `backend_failed` 或 `stopped` 继续迁移；
- 回滚时当前状态不是 `preparing_uv` 或 `syncing_repository`；
- 第二次进入 `restarting`；
- 尚未使用自动重启时直接从 `running` 进入 `backend_failed`。

T1.3 不新增对外错误码。这些错误表示 Runtime 内部编排违反自身契约，
由调用层映射为当前操作的主错误并写诊断日志。

## 测试与验收

自动化测试必须覆盖：

1. 24 个 stage、6 个 progress status、13 个 state status 与架构文档逐项
   比对，验证顺序、无重复和防御性副本；
2. 强类型事件 JSON round-trip 保持协议字面量；未知 stage 可解码但
   `IsKnownStage` 返回 false；
3. `AllLifecycleTransitions` 中每条常规迁移均可执行；
4. 三种稳定初态的准备路径、repair、依赖重试和幂等 bootstrap；
5. pre-mutation 回滚只回到构造时的稳定初态；
6. 首次重启成功、重启失败、第二次崩溃以及第二次重启被拒绝；
7. 启动中取消、重启中关闭、关闭成功和关闭清理失败；
8. 未知状态、self-loop、跳阶段、终态后迁移等代表性非法路径；
9. 并发读取与迁移不产生数据竞争或部分状态；
10. `OperationEmitter` 不暴露 `EmitState`，一次性检查样例不产生 state
    事件或生命周期写调用。
