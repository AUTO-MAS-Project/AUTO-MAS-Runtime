   同时观察锁和 terminal，确定性证明成功 result 的终态提交早于解锁；sticky result 回归测试

## 4. 对抗检查

- 入口别名攻击：在注入时钟中修改调用方 capability 底层数组，hello 仍保持入口快照；
- transcript 变异：缺字段、错类型、显式 `null`、未知冻结值、错误四元组错配、`OK` 误用于 warning、
  warning-only code 误用于 error 或失败 result；
- 资源边界：超长 Unicode code/stage/remediation/status/capability 的诊断保持有界且不截断半个字符；
- 文档漂移：生命周期表缺标题、缺分隔行、行格式错误、未知状态、数量变化或重复边都会失败；
- 并发锁域：renderer 回调期间 `ProcessOutput.mu.TryLock()` 必须失败；result renderer 还必须观察到
  已预约 terminal，编码失败回滚后必须允许重试；生命周期并发用例为 race detector 制造真实访问；
- 验证脚本：定向 `-run` 的零命中、退出码与 PASS/预期 RED 分别校验，`rg` 的执行错误不会冒充无匹配；
- 代码扫描：当前 `cmd/` 与 `internal/` 中无纯英文自然语言注释、无业务包 stdout 写入、
  无 `time.Sleep` 同步、无生产代码 panic/直接 Python 或 shell 子进程调用。

## 5. 验证证据

以下命令均在 PowerShell 7 中逐条检查退出码并通过：

```powershell
$gccBin = Split-Path -Parent (Get-Command gcc -ErrorAction Stop).Source
$env:PATH = "$gccBin;$env:PATH"
$env:GOCACHE = Join-Path $env:TEMP "auto-mas-runtime-t19-verify"

$unformatted = & gofmt -l .
if ($LASTEXITCODE -ne 0) { throw "gofmt failed" }
if ($unformatted) { $unformatted; throw "gofmt found unformatted files" }
& go vet ./...
if ($LASTEXITCODE -ne 0) { throw "go vet failed" }
& go build -buildvcs=false ./...
if ($LASTEXITCODE -ne 0) { throw "build failed" }
& go test ./... -count=1
if ($LASTEXITCODE -ne 0) { throw "tests failed" }
& go test ./internal/protocol ./internal/protocol/contracttest -count=100
if ($LASTEXITCODE -ne 0) { throw "repeated tests failed" }
& go test -race ./... -count=1
if ($LASTEXITCODE -ne 0) { throw "race tests failed" }
& git diff --check
if ($LASTEXITCODE -ne 0) { throw "diff check failed" }
```

2026-07-29 实现提交 `7235163` 的 100 次重复结果：`internal/protocol` 通过，
`internal/protocol/contracttest` 通过。沙箱外全量 race 结果：所有包通过，未报告数据竞争。

## 6. 剩余风险

2026-07-29 使用 Go 1.26.5、`CGO_ENABLED=1` 和 MSYS2 UCRT64 GCC 16.1.0，在 Codex 沙箱外
实际执行 `go test -race ./... -count=1` 并通过。生命周期公开 API 没有可注入的临界区 hook；
为保持生产 API 和实现简洁，没有仅为测试加入 hook。并发访问测试能让 race detector 检出漏锁，
但不能证明使用 atomics 或分离锁后仍保持 `current` / `restartUsed` 联合原子性；这项风险继续由
`LifecycleMachine.mu` 的单一锁域代码审查和确定性状态守卫测试覆盖。
