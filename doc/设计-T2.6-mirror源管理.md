# T2.6 mirror 源管理设计

## 文档状态

- 日期：2026-07-29
- 状态：已批准，采用方案 A
- 任务：[T2.6 mirror 源管理](./任务拆分.md)
- 架构基线：[架构设计](./架构设计.md)
- 代码基线：AUTO-MAS Runtime `fb06f57`

本文冻结 `internal/mirror` 的源分类、内置默认、策略值、轮换状态机、目标不变量和
尝试报告。镜像只改变数据来自哪里，不得改变要获取的产品版本、发布分支、uv 版本、
Python 版本或锁文件；Git 实际 Commit 只在某次克隆完成并通过校验后记录。

## 目标与范围

T2.6 交付：

1. Git、uv 二进制、Python standalone 分发和 Python 包索引四类独立 Source；
2. 只接受 HTTPS 生产源、默认启用 TLS 验证且没有跳过 TLS 的配置面；
3. 消费 CLI 已解析策略的 `Policy` 值对象；
4. “显式源优先、其余镜像按配置、官方末尾”的确定性尝试计划；
5. 每源默认两次尝试、完整性失败本次操作拉黑、context 取消立即停止；
6. 每次尝试携带同一个不可变 `Target`，并返回完整 `AttemptReport`；
7. `NETWORK_UNAVAILABLE` 与 `MIRROR_EXHAUSTED` 的稳定映射。

本任务不负责：

- 注册或解析 `--mirror`、`--offline`、`--mirror-only` CLI 参数，该职责属于 T3.1；
- 执行 Git clone、HTTP 下载或 uv 子进程；
- 生成产品版本、发布分支、uv/Python 版本或 lock digest；
- 解析 uv、Git 或 HTTP 自然语言文案决定是否换源；
- 为 Git 目标解析或钉扎 Commit；
- 管理 Python 插件安装；插件包索引轮换仍由 Python 后端拥有；
- 向 stdout 发 progress、warning、error 或 result。

## 方案选择

采用方案 A：**按类别建立不可变 Catalog，由 Rotator 执行显式状态机**。

备选方案 B 是维护一个通用 URL 数组，由调用方自行解释用途。它会把 Git remote、
下载 URL 和 package index 混为同一语义，并允许错误地把一个类别的源用于另一个类别，
因此不采用。

备选方案 C 是把重试分别写进 gitrepo、Downloader 和 UVRunner。它会产生不一致的
重试次数、官方兜底和完整性拉黑行为，也无法集中证明换源不改变目标，因此不采用。

## 四类 Source

### Kind

CLI 字面量与 Go 常量一一对应：

```go
type Kind string

const (
    KindGit          Kind = "git"
    KindUV           Kind = "uv"
    KindPython       Kind = "python"
    KindPackageIndex Kind = "package-index"
)

func AllKinds() []Kind
func (k Kind) String() string
func (k Kind) Valid() bool
```

同一个 key 可以在不同 Kind 下重复，例如 uv 与 Python 均可有 `gh-proxy`；同一 Kind
内 key 必须唯一。

### Source 值对象

```go
type Source struct {
    // 字段不导出，必须由构造函数创建。
}

func NewSource(
    kind Kind,
    key string,
    baseURL string,
    official bool,
) (Source, error)

func (s Source) Kind() Kind
func (s Source) Key() string
func (s Source) BaseURL() string
func (s Source) Official() bool
```

构造时固定校验：

- Kind 必须属于全集，key 必须为非空 ASCII 小写标识符；
- URL 必须是绝对 `https` URL，host 非空；
- 禁止 userinfo、fragment、RawQuery、NUL、相对 URL 和非默认 TLS 绕过参数；
- URL 规范化后保存，调用方拿不到可变的 `url.URL` 指针；
- `official` 是 Catalog 元数据，不从 host 名猜测。

生产 Source 没有 `insecure`、`skipVerify`、`allowHTTP` 或自定义 CA 跳过开关。
T2.7 的本地传输测试使用 `httptest.NewTLSServer` 与只在同包私有构造器注入的测试
Root CA/client，不通过生产 Source 构造器注册，也不放宽 HTTPS 规则。

### Catalog

```go
type Catalog struct {
    // 按 Kind 保存不可变、有序 Source。
}

func NewCatalog(sources []Source) (*Catalog, error)
func DefaultCatalog() (*Catalog, error)
func (c *Catalog) Sources(kind Kind) []Source
func (c *Catalog) Source(kind Kind, key string) (Source, bool)
```

`NewCatalog` 防御性复制输入并重新验证每个 Source 的内部不变量，拒绝零值/伪造
Source、同 Kind 重复 key、某类存在多个 official 源或某类没有 official 源。`Sources`
返回防御性副本。Catalog 构造完成后可安全供多个操作并发读取；拉黑状态绝不写入
Catalog。`DefaultCatalog` 通过同一校验路径返回错误，库代码不得因内置常量错误而 panic。

## 已解析策略

### Policy

```go
type PolicySpec struct {
    Preferred  map[Kind]string
    Offline    bool
    MirrorOnly bool
}

type Policy struct {
    // preferred、offline、mirrorOnly 均不导出。
}

func NewPolicy(spec PolicySpec) (Policy, error)
func (p Policy) Preferred(kind Kind) (string, bool)
func (p Policy) Offline() bool
func (p Policy) MirrorOnly() bool
```

PolicySpec 是 CLI 已解析数据的构造输入。NewPolicy 防御性复制 map，构造后的 Policy
不暴露可变 map，并重复验证以下不变量：

- map 中每个 Kind 已知，key 满足 Source key 的 ASCII 小写标识符语法；
- `offline` 与任何 Preferred 或 `mirrorOnly` 互斥；
- nil map 归一化为空 map。

`NewPolicy` 没有 Catalog，因而不声称验证 key 存在或判断该 key 是否 official。
`BuildPlan(catalog, policy, kind)` 在有 Catalog 的边界完成这两项验证：

- Preferred key 在对应 Kind 中不存在时返回策略错误；
- `mirrorOnly` 下显式 key 若为 official，返回策略错误。

CLI 的重复 `--mirror <kind>=<key>` 用于为多个不同 Kind 分别选择首选源。T3.1 解析为
`map[Kind]string` 时，**同一个 Kind 出现第二次即参数错误**，不采用静默
“最后一个覆盖前一个”。mirror 包只消费无重复、已校验的 map，但仍在 `NewPolicy`
防御错误的程序内调用。

`Policy` 不允许调用方提供任意 URL；CLI 只选择 Catalog 中的 key。

## 尝试顺序

### Plan

```go
type Plan struct {
    // 保存本次操作的 Kind、有序 Source 与 offline 标记，字段不导出。
}

func BuildPlan(
    catalog *Catalog,
    policy Policy,
    kind Kind,
) (Plan, error)

func (p Plan) Sources() []Source
func (p Plan) Kind() Kind
func (p Plan) Offline() bool
```

给定 Kind，顺序固定为：

1. 若有显式 Source，先加入它；
2. 加入 Catalog 配置顺序中的其余非官方镜像，去重；
3. 若非 `mirrorOnly`，最后加入尚未出现的 official Source；
4. `mirrorOnly` 完全排除 official Source；
5. `offline` 生成 `Offline()==true` 且 Sources 为空的 Plan；Rotator.Run 在零次调用
   AttemptFunc 的前提下返回 `NETWORK_UNAVAILABLE`。

非 offline 策略经过 preferred/mirrorOnly 过滤后必须至少剩一个 Source；例如
official-only Catalog 配合 mirrorOnly 时，BuildPlan 直接返回策略错误，不能构造一个随后
才由 Run 拒绝的空 Plan。

显式选择 official 且非 `mirrorOnly` 时，official 位于第一位且不会在末尾重复。未显式
选择时，所有镜像保持 Catalog 顺序，official 固定最后。

Plan 是单次操作的快照。操作进行中修改外部配置不改变它，也不会重置已拉黑 Source。

## Target 不变量

### Target 值对象

```go
type TargetSpec struct {
    ProductVersion string
    ReleaseBranch  string
    UVVersion      string
    PythonVersion  string
    LockDigest     string
}

type Target struct {
    // 五个目标字段与 fingerprint 均不导出。
}

func NewTarget(spec TargetSpec) (Target, error)
func (t Target) ProductVersion() string
func (t Target) ReleaseBranch() string
func (t Target) UVVersion() string
func (t Target) PythonVersion() string
func (t Target) LockDigest() string
func (t Target) Fingerprint() string
func (t Target) ValidateForKind(kind Kind) error
```

`TargetSpec` 只是构造输入；Rotator 与 Attempt 只接收字段私有的 Target。Target 只包含
字符串值，不包含 slice、map、指针或可变 URL。`LockDigest` 非空时必须是 64 个十六进制
字符，并在构造时归一化为小写。空 TargetSpec 被拒绝；所有非空版本字段必须满足 1～128
个 ASCII 字母、数字、点、连字符或下划线，不含 `..`、`@{`、尾点、NUL 或控制字符。
ProductVersion 还必须以 `v` 开头；ReleaseBranch 只接受
`release/<safe-product-version>`。各调用方只填当时已经确定的字段，但一旦 Rotator 开始，
五个字段必须在所有尝试中逐字节一致。

`ValidateForKind` 冻结可执行目标：

| Plan Kind | 必填字段 | 额外关系 |
| --- | --- | --- |
| `git` | ProductVersion、ReleaseBranch | `ReleaseBranch == "release/" + ProductVersion` |
| `uv` | UVVersion | 非空字段仍全部通过安全语法 |
| `python` | PythonVersion | 非空字段仍全部通过安全语法 |
| `package-index` | LockDigest | 恰为归一化的 64 hex |

Run 在任何 callback 前调用该方法；字段缺失或关系矛盾是 invalid rotation request，不得
进入网络后误报为镜像耗尽。

字段用途：

| 字段 | 典型消费方 |
| --- | --- |
| `ProductVersion` | Git 版本文件校验、最终环境状态 |
| `ReleaseBranch` | Git single-branch clone |
| `UVVersion` | uv release 资源路径 |
| `PythonVersion` | uv Python standalone 分发选择 |
| `LockDigest` | package index 重试前后的锁文件身份 |

`Fingerprint` 对带字段名的规范序列做 SHA-256，只用于断言、日志关联和报告，不参与安全
验签。

Target **没有 expected Commit 字段**。按决策 D6，Rotator 不在换源前解析、固定或比较
远端 Commit。Git 尝试在克隆并校验发布分支与版本文件后，可以把该源的实际 HEAD 写入
成功报告；后续流程持久化最终成功源的实际 Commit。

Rotator 入口会重新执行 Target 内部合法性与 fingerprint 一致性校验，拒绝 Target 零值或
任何未经过 NewTarget 的无效值；调用每个 Attempt 前再次核对 fingerprint。回调只能收到
值拷贝，不能返回一个“修订后的目标”。任何试图换版本、分支、uv/Python 版本或 lock
digest 的行为视为内部契约错误并立即停止。

## 轮换状态机

### 类型

```go
type OutcomeKind string

const (
    OutcomeSucceeded        OutcomeKind = "succeeded"
    OutcomeRetrySameSource  OutcomeKind = "retry_same_source"
    OutcomeSwitchSource     OutcomeKind = "switch_source"
    OutcomeIntegrityFailure OutcomeKind = "integrity_failure"
    OutcomeTargetFailure    OutcomeKind = "target_failure"
    OutcomeCancelled        OutcomeKind = "cancelled"
)

func (k OutcomeKind) String() string
func (k OutcomeKind) Valid() bool

type FailureKind string

func (k FailureKind) String() string
func (k FailureKind) Valid() bool

type Attempt struct {
    Source       Source
    Target       Target
    SourceTry    int
    GlobalTry    int
}

type AttemptOutcome struct {
    Kind         OutcomeKind
    FailureKind  FailureKind
    ActualCommit string
    Err          error
}

type AttemptFunc func(
    ctx context.Context,
    attempt Attempt,
) AttemptOutcome

type RotationResult struct {
    Source       Source
    ActualCommit string
    Reports      []AttemptReport
}

type Rotator struct {
    // 构造后配置只读。
}

type RotationOption func(*rotationOptions) error
type WaitFunc func(ctx context.Context, delay time.Duration) error
type reportContextFactory func(
    operationCtx context.Context,
) (context.Context, context.CancelFunc)

func NewRotator(options ...RotationOption) (*Rotator, error)
func WithRotatorClock(clock func() time.Time) RotationOption
func WithRotatorWait(wait WaitFunc) RotationOption
func WithAttemptReporter(reporter Reporter) RotationOption
func WithMaxSourceAttempts(attempts int) RotationOption
func WithRetryDelay(delay time.Duration) RotationOption

func (r *Rotator) Run(
    ctx context.Context,
    plan Plan,
    target Target,
    attempt AttemptFunc,
) (RotationResult, error)
```

构造器默认每个 Source 最多 **2 次总尝试**，即首次加一次同源重试。可为测试和未来调参
设置有限正整数，但生产默认和首版验收固定为 2；不提供无限重试。
默认 retry delay 为 250ms、clock 为 `time.Now`、wait 使用可取消 timer、
Reporter 为 nil。nil option、重复配置、nil clock/wait/reporter、attempts 不在
1～16、非正 delay 均包装 `ErrInvalidRotationOption`，构造失败不启动 goroutine。
Rotator 构造后只读，可并发 Run。

同包私有 `newRotatorWithDependencies` 可注入 report context factory。生产 factory 使用
`context.WithTimeout(context.WithoutCancel(operationCtx), 5*time.Second)` 处理每份报告；
它保留 values、忽略原取消并提供协作式 deadline，不承诺强行中断一个不响应
ctx 的 Reporter。测试 reporter 必须响应 ctx，并用 barrier 验证收口。

`Run` 在读取计划或调用 callback 前拒绝 nil ctx、nil AttemptFunc、零值/非法 Plan 和
不能通过 `Target.ValidateForKind(Plan.Kind())` 的 Target，包装
`ErrInvalidRotationRequest`。合法离线 Plan 是唯一允许 Sources
为空的计划：它的 Kind 仍有效、`Offline()==true`，且零次调用 AttemptFunc 后返回
`NETWORK_UNAVAILABLE`。非离线 Plan 必须至少有一个 Source，所有 Source 的 Kind 必须与
`Plan.Kind()` 相同且内部身份有效。请求校验失败不调用 clock、wait、reporter 或
AttemptFunc。

`OutcomeCancelled` 只用于 Rotator 自己在报告中记录 context 取消；AttemptFunc 不得主动
返回它。Rotator 验证 AttemptOutcome：未知 Outcome 或 callback 返回 cancelled 均拒绝；
`succeeded` 必须没有 Err；非成功结果
必须带 Err；非成功的 `FailureKind` 必须是非空、安全的 ASCII 小写 snake-case 标识，
成功时必须为空；Git 的 `succeeded` 必须携带 40 个小写十六进制
`ActualCommit`，其他 Kind 或任何失败结果必须为空。回调返回矛盾组合时按内部契约
错误立即停止，不把它误报为镜像耗尽。

### 状态转换

每个 Source 的处理规则：

| Outcome | 行为 |
| --- | --- |
| `succeeded` | 记录报告并立即返回成功 |
| `retry_same_source` | 未达两次时等待后重试；耗尽后切到下一 Source |
| `switch_source` | 跳过该 Source 的剩余次数，进入下一 Source |
| `integrity_failure` | 将该 Source 在本次 Run 中拉黑，跳过剩余次数，进入下一 Source |
| `target_failure` | 源无法改变该失败，保留底层业务错误并立即停止整个 Run |

完整性失败包括下载大小/SHA-256 不匹配、Git 仓库版本文件不匹配或已克隆仓库无法通过
静态完整性检查。拉黑只存在于当前 Run，不写全局文件；下一次用户重新发起顶层操作可以
在完整新计划中再次尝试该源。

连接超时、读取超时、可重试 HTTP 状态和调用方明确分类的暂时网络错误使用
`retry_same_source`。明显不适用于该 Source 的错误使用 `switch_source`。分支名非法、
本地 lock digest 在操作中改变等源无法修复的问题使用 `target_failure`。

AttemptFunc 返回合法 `succeeded` 是线性化成功点：副作用已经完成，成功优先于此时或
随后才观察到的 context 取消，Rotator 不把它改写为 cancelled。非成功返回时若 ctx 已
取消，Rotator 生成 `cancelled` 报告，不再调用 AttemptFunc，并向上返回
`context.Canceled` 或 `context.DeadlineExceeded`，由顶层映射
`OPERATION_CANCELLED`。

终止原因的固定优先级为：

1. 调用方 context 取消（已经线性化的合法 `succeeded` 除外）；
2. Outcome 契约错误、Reporter 错误或 `target_failure`；
3. 所有计划 Source 自然耗尽；只在这一层内，历史任一完整性失败优先于纯传输耗尽。

因此，先观察 integrity failure、随后遇到 target failure、Reporter failure 或取消时，
分别保留后者，不返回 `IntegrityExhaustedError`。`IntegrityExhaustedError` 只表示状态机
正常跑完全部可用 Source 且没有成功，同时历史中至少一次完整性失败。

### 重试等待

同源第二次尝试前默认等待 250ms。等待通过可注入 `WaitFunc` 实现，默认使用 timer 与
context，不调用 `time.Sleep`。测试使用 fake Wait 精确断言次数；等待被取消时不得进入
下一次网络调用。

## Attempt 报告

每一次实际调用 AttemptFunc 都产生报告：

```go
type AttemptReport struct {
    Kind          Kind
    SourceKey     string
    SourceTry     int
    GlobalTry     int
    Target        Target
    TargetHash    string
    StartedAt     time.Time
    Duration      time.Duration
    Outcome       OutcomeKind
    FailureKind   FailureKind
    Error         string
    ActualCommit  string
}
```

时钟通过 `WithRotatorClock(func() time.Time)` 注入。报告按调用顺序返回防御性副本；可选的
单方法 Reporter 在每次尝试结束后同步接收同一报告，用于操作日志：

```go
type Reporter interface {
    ReportAttempt(ctx context.Context, report AttemptReport) error
}
```

Reporter 不向 stdout 写内容。AttemptFunc 返回后，Rotator 先校验并冻结 outcome，随后
对非成功路径在报告前、报告后各检查一次 operation ctx；任一检查已取消都按取消优先。
每一份报告都使用保留 values、忽略 operation 取消、最长 5 秒
的独立 report ctx。这样取消不能在 Logger 提交点前把已经冻结的报告变成空写。deadline
是协作式边界，Reporter 必须响应 ctx，不承诺硬抢占同步 sink。

尚未成功线性化的普通报告失败会停止继续换源并返回 reporter error，因为继续网络操作却
丢失来源记录会破坏诊断性；AttemptFunc 必须在返回非成功 outcome 前按自身事务规则收口
局部副作用。取消报告失败与 context error 用 `errors.Join` 同时保留，但取消仍是主终点，
不会被改写成镜像耗尽或单纯报告失败。合法 succeeded 的报告若失败，Rotator 返回已经填充
Source/ActualCommit/Reports 的 RotationResult 与 reporter error，明确“尝试成功已发生”；
调用方不得重试或清理已发布结果。取消报告之后不再发起尝试。

`ActualCommit` 仅允许出现在成功的 Git 报告中，且必须来自已经完成分支和版本文件校验的
仓库。失败报告的 `ActualCommit` 必须为空；首版 API 不提供把失败源观察值传给下一源的
通道。

错误文本只进入本地操作日志，业务判断只使用 Outcome 与 `FailureKind`，不得解析
`Error` 字符串。

## 错误映射

Rotator 返回可经 `errors.As` 识别的 `*RotationError` 或
`*IntegrityExhaustedError`，两者都包含防御性复制的 Reports 和全部底层错误链。

```go
var (
    ErrInvalidRotationOption  = errors.New("mirror rotation option is invalid")
    ErrInvalidRotationRequest = errors.New("mirror rotation request is invalid")
)

type RotationError struct {
    // 字段不导出。
}

func (e *RotationError) Error() string
func (e *RotationError) Code() protocol.Code
func (e *RotationError) Reports() []AttemptReport
func (e *RotationError) Unwrap() []error

type IntegrityExhaustedError struct {
    // 字段不导出。
}

func (e *IntegrityExhaustedError) Error() string
func (e *IntegrityExhaustedError) Reports() []AttemptReport
func (e *IntegrityExhaustedError) Unwrap() []error
```

构造器、Catalog、Policy、Plan、Target 的错误各自使用本节或对应章节的 sentinel，
错误字符串不回显 URL query/userinfo。Reports 和 Causes 在构造错误时复制，调用方
修改返回切片不得改变 error 内部状态。

| 场景 | 协议码 |
| --- | --- |
| `offline=true` 下请求网络操作 | `NETWORK_UNAVAILABLE` |
| 允许网络、至少执行一次尝试、所有失败均为传输/源可用性且 Source 耗尽 | `MIRROR_EXHAUSTED` |
| 状态机自然耗尽，且任一 Source 报告完整性失败、最终没有成功 | 不降级为镜像码；返回 `IntegrityExhaustedError` |

已开始网络尝试后，即使全部是 DNS、连接或超时失败，最终也使用
`MIRROR_EXHAUSTED`，因为用户可执行的动作是切换或重试其他镜像。`target_failure`
保留调用方的业务错误，例如 `GIT_BRANCH_NOT_FOUND`，不改写为镜像耗尽。

在“自然耗尽”这一终点内，完整性失败具有更高优先级：只要一次 Run 观察到大小/SHA、
Git 版本或仓库静态完整性失败，后续源也全部因可换源/可重试失败而耗尽时必须返回
`IntegrityExhaustedError`，其 `Unwrap() []error`
按报告顺序保留完整性与传输错误。调用域据自己的目标类型映射
`UV_CHECKSUM_MISMATCH`、`GIT_VERSION_MISMATCH` 等稳定码；Rotator 不猜测领域码。
这避免供应链异常被最终一次连接超时掩盖成普通 `MIRROR_EXHAUSTED`。

Catalog/Policy/Target 构造错误是程序配置或 CLI 参数错误，由 T3.1 映射
`INVALID_ARGUMENT`；它们不伪装成网络错误。

mirror 包不自行构造 protocol 事件，只在错误对象中提供 `protocol.Code` 供上层使用。

## 并发与生命周期

- Catalog 可跨 goroutine 只读共享；
- Policy、Plan、Target 和 Source 均按值或防御性副本传递；
- 每个 Rotator Run 拥有独立的 source index、重试计数和拉黑集合；
- 同一个 Rotator 可并发 Run，但 Reporter 若有内部状态必须自行并发安全；
- Run 不启动后台 goroutine，AttemptFunc 返回后不保留其 context；
- 取消、Reporter 失败或 target failure 后不再发起新的尝试。

## 测试与验收

### Source 与策略

必须覆盖：

1. 四类 Kind 全集、默认 key、默认 URL 和顺序逐项比对本文；
2. 非 HTTPS、相对 URL、userinfo、fragment、RawQuery、空 host、同 Kind 重复 key
   全部拒绝；
3. 没有任何公开 TLS 跳过开关，默认 Source 全部为 HTTPS；
4. Preferred map 防御性复制且 Policy 不暴露 map，未知 Kind 与非法 key 语法由
   NewPolicy 拒绝，Catalog 中不存在的合法 key 由 BuildPlan 拒绝；
5. 同 Kind 重复 `--mirror` 的解析契约固定为参数错误，不存在 last-wins；
6. offline 与 Preferred/mirrorOnly 互斥，mirrorOnly 的 official 选择由 BuildPlan 拒绝。

### Plan 顺序

表驱动覆盖：

1. 无显式选择：镜像按 Catalog 顺序，official 最后；
2. 显式镜像：所选源第一、其余镜像随后、official 最后且不重复；
3. 显式 official：official 第一，其余镜像按配置随后且 official 不重复；
4. mirrorOnly：不出现 official；
5. 每一种 Kind 相互独立，一个 Kind 的 Preferred 不改变另一 Kind；
6. official-only Catalog + mirrorOnly 在 BuildPlan 返回策略错误，不产生空的非离线 Plan。

### 轮换状态机

使用 fake AttemptFunc、fake Wait 和 fake Clock，覆盖：

1. 首源首次成功；
2. 首源暂时失败、同源第二次成功；
3. 两次失败后切换下一源；
4. 完整性失败立即拉黑，不执行该源第二次；
5. 所有源耗尽得到 `MIRROR_EXHAUSTED`；
6. offline 零次调用并得到 `NETWORK_UNAVAILABLE`；
7. target failure 立即停止并保留底层错误；
8. context 在尝试中、重试等待中和换源前取消；
9. Reporter 失败后不再尝试；
10. 未知 Outcome、callback 主动返回 cancelled、成功带 error、失败无 error、
    Git 成功缺少/携带非法 ActualCommit、非 Git/非成功携带 ActualCommit 均被拒绝；
11. 并发 Run 的计数和拉黑集合互不污染；
12. NewRotator 默认值与每个 RotationOption 的 nil、重复、attempt/delay 边界；
13. 纯传输耗尽返回 `RotationError(MIRROR_EXHAUSTED)`，任一完整性失败混合后续
    transport/integrity 耗尽返回 `IntegrityExhaustedError` 并按顺序保留全部原因；
14. 完整性失败后其他源成功仍返回成功，但 Reports 保留先前完整性诊断；
15. integrity 后发生 target failure、Reporter failure 或 context 取消时，按固定优先级
    返回后者而不是 `IntegrityExhaustedError`；
16. Run 对 nil ctx、nil AttemptFunc、零值/非法 Plan、空的非离线 Plan 和零值 Target
    在任何 callback 前返回 `ErrInvalidRotationRequest`；合法离线 Plan 仍零次尝试返回
    `NETWORK_UNAVAILABLE`；
17. Kind、OutcomeKind、FailureKind 的 `String` / `Valid` 覆盖合法值、零值和未知值；
18. Attempt 运行中取消由 Rotator 合法生成 `OutcomeCancelled` 报告，callback 不能伪造
    该 Outcome；
19. barrier 证明合法 succeeded 返回与同时取消竞态时成功获胜；非成功路径在 Reporter
    前后任一时点取消都以 context 为主终点，每份报告使用独立 report ctx，报告错误与
    context error 同时保留，之后无新尝试；成功报告失败返回已填充 RotationResult 与
    error。

### 目标不变量与报告

必须证明：

1. 每次 Attempt 的五个 Target 字段及 fingerprint 完全一致；
2. Target 字段私有且只能由 getter 读取，fake callback 无法修改值拷贝影响后续尝试；
3. lock digest 非 64 hex 拒绝，输入大小写归一化；
4. Rotator 入口拒绝零值或无效 Target，Source 变化时版本、分支、uv/Python 版本和
   lock digest 不变；
5. Target 不包含 expected Commit；
6. Git 成功尝试可以记录实际 Commit，下一 Source 不接收该 Commit；
7. AttemptReport 顺序、source/global try、时长、失败分类和防御性副本正确；
8. 业务判断不读取错误文案。
9. `ValidateForKind` 表驱动覆盖 Git/uv/Python/package-index 的必填字段；Git branch 必须
   精确等于 `release/` + ProductVersion，所有缺失或矛盾目标在 callback 前拒绝；
10. Git 成功 ActualCommit 必须为 40 位小写 hex，不能把非法值写入结果或稳定状态。

和 UVRunner 都只消费 Rotator 提供的 Source 与原始 Target。
