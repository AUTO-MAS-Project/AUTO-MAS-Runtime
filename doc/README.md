# AUTO-MAS Runtime 文档入口

`doc/` 只保留当前仍需维护的权威文档、当前阶段工作文档和少量长期维护说明。
已经完成的阶段设计移入 `archive/`；实现计划在任务验收后删除，历史内容由 Git 保存。

## 权威文档

| 文档 | 用途 |
| --- | --- |
| [架构设计](./架构设计.md) | 系统边界、对外契约、目录安全、命令树和验收标准 |
| [协议 v1 契约补充](./契约补充-v1.md) | 后端端口、身份注入、健康检查等具体契约 |
| [任务拆分](./任务拆分.md) | 任务依赖、验收、决策和当前进度 |
| [代码审查清单](./代码审查清单.md) | 自动化门禁之外的架构边界检查 |
| [T1.3 生命周期设计](./设计-T1.3-生命周期状态机.md) | 协议测试直接读取的生命周期契约夹具 |

权威优先级仍为：`契约补充-v1.md` > `架构设计.md` > `任务拆分.md`。

## 按用途浏览

- [当前工作](./current/README.md)：只放尚未完成阶段的设计和实施计划。
- [维护与收敛](./maintenance/README.md)：文档维护规则和跨阶段可维护性工作。
- [历史归档](./archive/README.md)：已完成阶段仍有解释价值的设计与审查记录。

## 文档生命周期

1. 新任务先登记到 `任务拆分.md`。
2. 非平凡任务的设计与计划放入 `current/M<里程碑>/`。
3. 任务完成后，仍解释当前实现的设计移入 `archive/M<里程碑>/`。
4. 已执行完成的计划不作为长期真相源，验收完成后删除；需要追溯时查看 Git 历史。
5. 审查报告只在仍能解释重要决策或修复来源时归档，否则删除。
6. 不在计划中复制大段最终生产代码或测试代码；文件、红灯、绿灯和验证命令足以指导实施。
